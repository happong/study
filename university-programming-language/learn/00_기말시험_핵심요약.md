# 기말시험 핵심 요약 (1~15강 전체)

> 각 강의 상세 내용은 `01강_...md` ~ `15강_...md` 참고. 이 파일은 시험 직전 빠르게 훑어보기 위한 압축본.
> ⭐ 표시는 2017·2019학년도 실제 기말 기출(교재 전체 범위)에서 확인된 단골 출제 포인트.

## 01강 — 프로그래밍 언어 개요
- 프로그래밍 언어 = 컴퓨터가 수행 가능하고 **사람이 읽을 수 있는** 표기 체계 (기계어 자체가 아님)
- 기본 기능: **작성력 / 가독성 / 실행 가능성**. 부가 기능: 추상화, 모듈화
- 구성 요소: 데이터, 연산, 명령어, 서브프로그램(함수=반환O/프로시저=반환X), 타입, 모듈
- ⭐ **강타입/약타입/무타입** 구분은 09강과 연결됨
- 학습의 두 측면: 프로그램 형태(**구문론**) vs 수행 과정(**의미론**)

## 02강 — 언어의 발전과 구현
- ⭐ 연대-언어-개발자 매칭: Fortran(배커스,50s) / LISP(매카시,함수형 최초) / Simula(객체지향 시초) / C(데니스 리치) / Smalltalk(GUI+객체지향) / Python(귀도 반 로섬, 다중패러다임)
- 구현 방법 3가지: **인터프리터**(직접 해석) / **컴파일러**(번역 후 실행) / **하이브리드**(VM, 예: JVM)
- 평가기준 9가지와 상충관계: 효율성↔신뢰성, 가독성↔작성력, 신뢰성↔유연성

## 03강 — 프로그래밍 언어 패러다임 ⭐⭐
- 패러다임 = 프로그램 작성의 **방식/스타일**(언어 비종속). 한 언어는 여러 패러다임 동시 지원 가능
- **명령형**: 명령어 순차 나열 / **절차형**: 서브루틴(함수) 집합으로 구성 / **객체지향**: 통신하는 객체 집합 / **함수형**: 함수 적용으로 계산(대입문 없음, 고계함수 가능) / **논리형**: 논리식의 참/거짓 증명
- ⭐ 언어별 지원표: **C**=명령형+절차형만 / **Python**=명령형+절차형+함수형+객체지향 (C와 Python의 공통=명령형·절차형, Python만 있는 것=함수형 또는 객체지향)
- 계산 표현 방식: 객체지향=통신, 함수형=적용, 논리형=증명

## 04강 — 구문론과 의미론 ⭐⭐
- 구문론(형태) vs 의미론(뜻). 문맥자유문법(CFG) = 비단말기호+단말기호+생성규칙+시작기호
- **BNF**: `::=`(정의) `|`(택일) `< >`(비단말) `' '`(단말묶음) `;`(끝)
- **EBNF**: `[ ]`(생략가능=0or1) `{ }`(0번이상반복) `( | )`(묶음택일)
- **구문 도표**: 사각형=비단말기호, 원=단말기호, 화살표=흐름, `[ ]`→분기 후 합류, `{ }`→루프백 화살표
- 의미론: 정적(타입검사, 속성문법) vs 동적(기능적/표기적/공리적 의미론)

## 05강 — 구문 분석
- 어휘분석(문자→어휘, 렉심/토큰/식별자/예약어) → 구문분석(어휘→파스트리)
- 파스트리 존재 ⇔ 구문에 맞음. **파스트리가 여러 개 존재 = 모호한 문법**
- ⭐ 모호성 제거 3가지: ① 연산자 우선순위 계층화(`<exp>→<term>→<factor>`) ② 좌결합 강제(좌변 재귀를 좌측에만) ③ **짝 잃은 else 문제**(else는 가장 가까운 미결합 if와 짝 — `<문장>`/`<문장2>` 분리로 해결)

## 06강 — 언어의 구현
- 언어 구현 = 구문 검사 + 의미(실행). 인터프리터: `Int_L[[P_L]](in)=out` / 컴파일러: `Comp_L[[P_L]]=P_M`
- 전통 언어(명령형~객체지향)는 기계어 **확장**, 새 패러다임(함수형/논리형)은 **추상기계** 경유(가상기계=VM, 예 JVM)
- 구현 단계: 어휘분석→구문분석→의미분석→중간표현(**전단부**) → 중간코드최적화→코드생성→목적코드최적화(**후단부**)
- ⭐ 구조: **구문 트리**(공통) / **심볼 테이블**(컴파일러, 타입·선언위치) / **환경**(인터프리터, 값까지 포함)
- 순환 하강 구문 분석기: 문법 규칙 하나당 프로시저 하나로 그대로 옮겨 구현

## 07강 — 변수와 바인딩 ⭐
- 변수 속성 6가지: **변수명/타입/주소/값/수명/영역**
- 바인딩 = 속성이 구체적으로 결정되는 것. 바인딩 시각: 언어정의→언어구현→**컴파일**(타입)→링크→**로드**(주소)→**수행**(값)
- **정적 바인딩**(수행 중 안 바뀜, 컴파일러에 적합) vs **동적 바인딩**(수행 중 바뀜/해지 가능, 인터프리터에 적합)
- ⭐ 변수 종류: 정적변수(로드시 주소 고정) / 스택동적변수(지역변수, 자동 할당·해제) / 힙동적변수(`malloc`/`new`, 또는 Python처럼 동적 타입바인딩 언어)

## 08강 — 변수의 영역(scope) ⭐⭐
- 영역=변수를 쓸 수 있는 범위(시작=선언 지점). 블록=영역 구분 단위(언어마다 기준 다름: Pascal은 복합문 begin~end가 블록 아님 주의)
- 자유변수: 현재 블록에 선언 안 된, 참조하려는 변수
- ⭐ **정적 영역 규칙**: 문맥적 포함관계(정적 부모)로 결정, 컴파일 시점 결정, 빠름, 대부분 언어
- ⭐ **동적 영역 규칙**: 호출 관계로 결정, 수행 시점 결정, 느림, LISP 등
- 영역 구멍: 안쪽 블록에서 같은 이름 재선언 시 바깥 변수가 가려짐. 전역변수 접근은 영역 연산자 `::`

## 09강 — 타입 ⭐
- 타입 = **데이터 집합 + 연산 집합**. 타입 안전성: 모든 연산에서 타입 오류 없음
- ⭐ **강타입**(모든 타입오류 검출, Haskell/ML) / **약타입**(일부 허용, C의 공용체·캐스팅) / **무타입**(타입선언 없음, Python)
- 분류 3기준: 데이터형태 / 사용자개입(원시 vs 사용자정의) / 데이터요소형태(단순 vs 복합)
- 단순타입: 정수형(오버플로시 최댓값+1→최솟값 래핑), 실수형(부호+지수부+가수부, 범위초과시 `inf`), 문자형(ASCII 8비트/유니코드 16비트), 논리형, 열거형(`enum`, 미지정 시 직전값+1)

## 10강 — 복합타입
- **배열**: 동질형 모음, 첨자로 구분, 차원=첨자개수(Fortran77=7차원 한계)
- ⭐ 주소계산: 행우선(대부분 언어) `주소(B[i][j])=주소(B[0][0])+i×N×크기+j×크기` vs 열우선(Fortran)
- **문자열형**: C=문자배열(기본연산無) / Java=String클래스(대입·연결 가능)
- **연관배열**: 순서없는 동질형 모음, 키로 구분(Perl=hash, C++=map)
- **구조체**(레코드, 이질형 가능, 필드) vs **공용체**(저장공간 공유 — 한 필드 변경이 다른 필드에 영향, 태그로 구분)
- **포인터형**(주소 자체가 데이터, `*`=간접참조) vs **참조형**(별칭/alias, `&`)

## 11강 — 수식과 연산자
- 수식=값을 나타내는 표현(피연산자+연산자, 둘 다 필수는 아님) / 문장=처리를 나타내는 표현
- C/C++: 수식 뒤 `;` → 문장. 역은 성립 안 함(`if(a>0) printf(...)` 는 문장이지 수식 아님)
- ⭐ 타입변환: **묵시적**(자동, 보통 확대변환) vs **명시적**(캐스팅, 확대·축소 모두 가능)
- ⭐ **단락 회로 계산(short-circuit)**: `true || ...`→뒤 계산 안 함, `false && ...`→뒤 계산 안 함
- 우선순위(높은→낮은, C 기준): 후위++/-- → 전위++/--,부호 → `*/% ` → `+-` → `>><<` → 관계연산 → `==!=` → `&&` → `||`

## 12강 — 문장
- 선언문(변수/서브프로그램 선언) vs 실행문(대입문/제어문)
- 대입문: `=`,`:=`,`MOVE~TO`. **연속대입은 우결합**(`C=B=A=5` → A,B,C 모두 5)
- 복합대입연산자(`+=` 등), 단항대입(`++`,`--`)
- ⭐ 조건문(if/switch) vs 반복문: **for**/**while**(0번이상)/**do-while**(1번이상 — 핵심 차이!)
- goto 논란: 목적지 임의 지정 가능→구조 파악 어려움. goto 없는 언어: Modula-2, CLU, Java, Rust

## 13강 — 서브프로그램 개요 ⭐⭐⭐ (기출 최단골)
- 함수(반환O) / 프로시저(반환X) / 서브루틴(흐름 불명확, 초기 형태)
- **매개변수 프로파일**(인수 개수·순서·타입=시그니처) + 반환타입 = **서브프로그램 프로토콜**
- 형식인수(정의부 선언) vs 실인수(호출부 전달값). 대응: 위치 기반(일반적) / 키워드 기반
- ⭐⭐ **인수 전달 구현모델 5가지**(가장 중요):
  | 모델 | 방향 | 핵심 |
  |---|---|---|
  | 값 전달 | 입력 | 실인수 값을 복사 |
  | 결과 전달 | 출력 | 형식인수 값을 복귀 시 실인수에 복사 |
  | 값-결과 전달 | 입출력 | 호출시+복귀시 둘 다 복사(=복사에 의한 전달). 별칭문제 없음 |
  | 참조 전달 | 입출력 | 실인수 주소 자체 전달(=공유에 의한 전달). **별칭(alias) 문제** 발생 가능 |
  | 이름 전달 | - | 실인수 이름 자체 전달, 늦은 바인딩(젠슨의 기법), 비효율적 |
- 별칭 문제 발생 상황: 실인수 충돌 / 배열 원소 충돌(`i==j`) / 형식인수-전역변수 충돌
- 범용 서브프로그램: 다형(여러 타입 처리, 제너릭) / 다목적(여러 용도, 젠슨의 기법)
- 분리 컴파일(인터페이스 정보 이용, Ada) vs 독립 컴파일(정보 없음, C)

## 14강 — 서브프로그램 구현 ⭐⭐⭐ (기출 최단골)
- **활성 레코드**(틀, 정적 결정) vs **활성 레코드 인스턴스**(값, 동적 결정)
- Fortran77: 정적 할당 → **재귀호출 불가**(덮어씀) / Algol형: 스택에 동적 할당 / C: 중첩 불허→정적링크 불필요
- ⭐ 활성 레코드 필드: 지역변수, 매개변수, **동적 링크**(호출자의 프레임포인터), **정적 링크**(정적부모의 프레임포인터), 복귀주소, 반환값
- ⭐⭐ **정적 체인**(정적링크 연결=트리) vs **동적 체인**(동적링크 연결=리스트)
  - 정적 체인: 변수참조=**(체인변위, 지역변위)**. 체인변위=참조위치와 선언위치의 정적깊이 차. 구현쉬움·공간절약 / 체인변위 크면 느림
  - 동적 체인: 동적링크를 변수 찾을 때까지 거슬러 올라감(**깊은 참조**). 호출순서 따라 결과 달라짐. 변수이름 저장 필요(비효율)
- **디스플레이**: 정적체인 대체. 변수참조=**(디스플레이변위, 지역변위)**. 디스플레이변위=변수가 선언된 곳의 정적깊이와 동일. 정적깊이 p면 p+1개 항목
- 얕은 참조(변수스택/중앙테이블) — 동적체인 비효율 개선
- 과거민감 서브프로그램(정적지역변수 이용, 정보은닉 보장) / 코루틴(대등한 호출관계, resumed, Python도 지원)

## 15강 — 객체지향과 다형성 ⭐⭐
- 추상화: 제어 추상화(서브프로그램) vs 자료 추상화(ADT)
- **캡슐화**(묶기) / **정보은닉**(구현 숨기고 인터페이스만 공개) → 파급효과(ripple effect) 방지
- **ADT** = 자료집합+연산을 함께 선언, 구현은 캡슐화로 숨김. 장점: 수정용이성/재사용성/보안성
- 객체=속성(필드)+메소드, 클래스=객체의 틀(인스턴스). 동적타입언어=**오리 타입(duck typing)**
- 객체지향 구현 핵심: 메소드의 **늦은 바인딩** → **가상함수테이블(VTab)**로 구현 (C++는 `virtual`만)
- ⭐⭐ **다형성 3종류**:
  | 종류 | 정의 | 예 |
  |---|---|---|
  | 경험적(ad-hoc) | 다른 서브프로그램에 같은 이름(오버로딩) | C++ 함수/연산자 중복정의 |
  | 매개변수적(parametric) | 타입을 매개변수로 전달 | C++ template, Java generic |
  | 서브타입/순수(pure) | 상속(IS-A) 관계로 결정 | 추상클래스→구상클래스 |
- 다중상속 → **다이아몬드 상속 문제**(C++는 가상상속으로 해결)
- 인터페이스(추상메소드만, Java) vs 트레잇(일부 구현 포함, PHP/Rust/Ruby는 믹스인)
