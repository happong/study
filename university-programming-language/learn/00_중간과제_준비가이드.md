## 문제 1 (15점) — 각 10줄 이내

### (1) 프로그래밍 언어의 특징을 자연어와 비교하여 설명

**근거: `01강_프로그래밍언어_개요와학습법.md` §1의 비교표**

쓸 수 있는 대비 포인트 (전부 쓰지 말고 10줄에 맞게 2~3개를 골라 자신의 말로 풀어쓰기):
- **형식**: 자연어는 말과 글 둘 다로 존재하지만, 프로그래밍 언어는 주로 글(문자)로만 존재한다.
- **내용의 정밀도**: 자연어는 문맥에 따라 모호하고 함축적인 의미를 가질 수 있지만, 프로그래밍 언어는 컴퓨터가 기계적으로 처리해야 하므로 엄밀한 규칙에 따라 정확한 의도만을 표현해야 한다(모호함이 허용되지 않음).
- **방향성**: 자연어는 대화처럼 양방향으로 오가지만, 프로그래밍 언어는 기본적으로 사람→컴퓨터로 향하는 단방향 명령(컴퓨터가 "질문"하지 않음)이면서도, 작성 과정에서는 사람이 프로그램을 읽고 고치는 양방향적 성격도 가진다.
- (보너스) 1강의 "기계적" 특성(엄밀한 규칙 기반)과 "가변적" 특성(시대에 따라 바뀜, 예: Python)도 자연어와의 차이를 보여주는 포인트로 쓸 수 있음.
- 예시를 하나 넣으면 10줄을 자연스럽게 채우기 좋음 — 예: "자연어 문장은 생략해도 상대가 맥락으로 이해하지만, `if (a > 0)`처럼 프로그래밍 언어는 괄호 하나만 빠져도 실행되지 않는다" 같은 **본인이 직접 만든 예시**를 들 것(교재 예시 복붙 금지).

### (2) C와 Python이 공통으로 지원하는 패러다임 한 가지

**근거: `03강_프로그래밍언어패러다임.md` §3의 표**

- 표에서 C 행과 Python 행을 비교하면 공통으로 ○가 있는 패러다임은 **명령형**과 **절차형** 두 가지다. 이 중 **하나만** 골라 설명하면 된다.
- **명령형을 고를 경우**: "프로그램을 일련의 명령어 나열로 간주"하는 패러다임이라는 정의를 쓰고, C는 `a = a + 1;` 같은 대입문의 나열로, Python은 `a = a + 1`처럼 문법은 다르지만 똑같이 "상태를 바꾸는 명령을 순서대로 실행"하는 방식이라는 점을 본인 예시로 설명.
- **절차형을 고를 경우**: "프로그램을 서브루틴(절차)의 집합으로 구성"하는 패러다임이라는 정의를 쓰고, C의 `함수`(`int gcd(int a, int b){...}`)와 Python의 `def` 함수 정의가 둘 다 재사용 가능한 처리 절차를 이름 붙여 정의·호출한다는 공통점을 설명.
- 주의: "둘 다 객체지향을 지원한다"는 **틀린 답**이다 — 표에서 C는 객체지향 칸이 비어 있다(C는 구조체는 있지만 클래스·메소드 개념이 없음).

### (3) Python은 지원하나 C는 지원하지 않는 패러다임 한 가지

**근거: 같은 표. C 행에는 명령형·절차형만 ○, Python 행에는 명령형·절차형·함수형·객체지향 네 개가 모두 ○.**
→ 답으로 쓸 수 있는 것은 **함수형** 또는 **객체지향** 둘 중 하나.

- **함수형을 고를 경우**: "데이터는 값으로, 명령어는 함수로 취급하며 함수를 반복 적용해 결과를 구하는" 패러다임이라는 정의를 쓰고, Python의 `lambda`, `map()`, `filter()`, 함수를 값처럼 다른 함수의 인자로 넘기는 것(고계함수) 등을 본인 예시로 들 것. C는 함수 포인터가 있지만 "함수형 패러다임" 자체를 언어 차원에서 지원하지는 않는다는 점을 대비로 언급하면 좋음.
- **객체지향을 고를 경우**: "상태(필드)를 유지하며 메소드로 반응하는 객체들의 통신으로 계산을 표현"하는 패러다임이라는 정의를 쓰고, Python의 `class` 문법(캡슐화·상속 등)을 예로 들 것. C는 `struct`로 데이터 묶음은 만들 수 있어도 메소드·캡슐화·상속 같은 객체지향 고유 개념이 언어 차원에 없다는 점을 대비.

## 문제 2 (15점) — BNF를 EBNF/구문 도표로 합치기

**근거: `04강_구문론과의미론.md` §2 (BNF/EBNF/구문도표)**

### 주어진 BNF 3개 규칙 구조 파악하기
```
<if문> ::= if <조건> : <문장> | if <조건> : <문장> <추가조건>
<추가조건> ::= elif <조건> : <문장> <추가조건> | else: <문장> | ε
<조건> ::= T | F
```
`<추가조건>`을 풀어보면: **elif 절이 재귀적으로 0번 이상 반복**되다가, 마지막에 **else 절이 있거나(선택) 없을 수 있고**, 결국 아무것도 없을 수도 있다(ε)는 구조다. 즉:

> `<추가조건>` = `{ elif <조건> : <문장> }` (elif 0번 이상 반복) + `[ else : <문장> ]` (else는 있어도 되고 없어도 됨)

### (1) 하나의 EBNF로 합치기
4강에서 배운 **`{ }`(0번 이상 반복)**와 **`[ ]`(생략 가능)** 두 메타기호를 그대로 적용하면, 재귀적인 `<추가조건>` 비단말기호 없이도 **한 줄의 규칙**으로 합칠 수 있다.

```
<if문> ::= if <조건> : <문장> { elif <조건> : <문장> } [ else : <문장> ]
          ;
```

**"그렇게 표현한 이유"를 쓸 때 들어가면 좋은 논리** (본인 말로 재구성):
- 원래 `<추가조건>`이 자기 자신을 재귀적으로 참조하며 elif를 나열하는 구조인데, 이는 EBNF의 `{ }`가 뜻하는 "0번 이상 반복"과 정확히 같은 의미다.
- `<추가조건>`의 `else: <문장> | ε` 부분(= else가 있을 수도 없을 수도 있음)은 EBNF의 `[ ]`(생략 가능)가 뜻하는 바와 정확히 같다.
- 이렇게 합치면 ① 비단말기호(`<추가조건>`)와 재귀 규칙을 따로 둘 필요가 없어져서 **문법이 간결해지고**, ② if문의 구조(조건-elif 여러 개-else 하나)가 **한눈에 더 명확하게 드러난다**는 이유를 들 수 있다. (4강에서 본 `<unsigned integer> ::= <digit> { <digit> }` 예시와 같은 패턴임을 언급해도 좋음)

### (2) 하나의 구문 도표로 합치기
4강 구문도표 표기 규칙 복습: **사각형=비단말기호, 원=단말기호, 화살표=연결, 반복은 되돌아가는 화살표, 선택(생략가능)은 건너뛰는 분기 경로**.

**직접 그릴 때 구성 순서 (ASCII 스케치 — 실제 제출 파일에는 그림판/파워포인트/draw.io 등으로 깔끔하게 그릴 것)**

```
                 ┌───────────────────────loop-back──────────────┐
                 │                                               │
if문 ─▶(if)─▶[조건]─▶(:)─▶[문장]─▶●───▶(elif)─▶[조건]─▶(:)─▶[문장]─┘
                                   │
                                   └──▶(else)─▶(:)─▶[문장]──▶●──▶ (끝)
                                   │
                                   └───────────────(바로 끝, else도 없는 경우)────▶●
```

- 메인 경로: `(if)` → `[조건]` → `(:)` → `[문장]` 까지는 모든 if문에 공통.
- 그 뒤 분기점에서 **반복 경로**: `(elif)` → `[조건]` → `(:)` → `[문장]` 로 갔다가 다시 분기점으로 **되돌아가는 화살표**를 그려 "elif 0번 이상 반복"을 표현 (4강의 `<unsigned integer>` 구문도표의 루프백 화살표와 동일한 패턴).
- 분기점에서 또 다른 선택 경로로 `(else)` → `(:)` → `[문장]` 으로 가는 경로를 그려 "else는 있어도 되고 없어도 됨"을 표현 (4강의 if문 구문도표의 else 분기와 동일한 패턴).
- 두 경로(반복이 끝나는 지점, else 경로, 아무것도 없는 경우) 모두 최종적으로 하나의 끝점에서 합류하도록 그린다.

**"그렇게 표현한 이유"를 쓸 때 들어가면 좋은 논리** (본인 말로 재구성):
- EBNF의 `{ }`는 구문 도표에서 "되돌아가는 화살표(루프)"로, `[ ]`는 "건너뛸 수 있는 분기 경로"로 그대로 대응되므로, (1)에서 만든 EBNF 한 줄을 구문 도표 하나로 1:1 대응시켜 그릴 수 있다.
- 그림으로 그리면 "elif가 여러 번 반복될 수 있고 else는 선택적으로 온다"는 구조가 텍스트 규칙보다 **시각적으로 직관적으로** 드러난다는 점을 이유로 들 수 있다.

> 참고: 구문 도표는 그림 파일이어야 하므로, 위 ASCII 스케치를 참고해 파워포인트 도형이나 그림판으로 **본인이 직접** 그려서 캡처해 넣어야 합니다. 원하시면 제가 참고용 이미지(시각 자료)를 하나 만들어 드릴 수도 있어요 — 필요하면 말씀해주세요.
