# 04강 — 구문론과 의미론 ⭐ (중간과제 2번 핵심)

## 1. 언어의 형식적 정의

언어를 엄밀하게 정의하려면 **구문론 + 의미론**이 필요하다.

- **구문론(syntax)**: 문장의 **올바른 형태**를 정의 (프로그램 작성 시 어떤 형태로 써야 하는지)
- **의미론(semantics)**: 올바른 형태의 문장이 나타내는 **의미**를 정의 (프로그램 실행 시 어떤 일이 일어나는지)

예) `printf("GCD is %d", a);` → 구문: `printf("출력할 내용", 변수);` / 의미: `%d` 자리에 변수 값을 넣어 출력하라.

**형식적 정의가 필요한 이유**: 컴퓨터 입장에서는 해석의 모호함을 없애고, 작성자 입장에서는 프로그램의 동작을 예측 가능하게 하기 위함.

**프로그램의 구조**: 문자(알파벳·숫자·기호) → **어휘(토큰)**(최소 의미 단위) → **구문**(토큰을 모아 프로그램을 구성하는 규칙)

## 2. 구문의 표현 — 문맥자유문법(CFG)

- **문맥자유문법(Context-Free Grammar)**: 구성 = (비단말기호 집합 N, 단말기호 집합 T, 생성규칙 집합 P, 시작 비단말기호)
  - **비단말기호**: 정의될 대상 / **단말기호**: 언어에서 직접 쓰이는 표현
  - **생성규칙**: 하나의 비단말기호를 단말/비단말기호 조합으로 바꿔 쓰는 규칙
- 프로그래밍 언어의 구문은 보통 CFG로 표현하며, 그 표현 방법에는 **BNF, EBNF, 구문 도표** 세 가지가 있고 **서로 변환 가능**하다.

### BNF (Backus-Naur Form)
Algol의 구문 정의를 위해 고안됨.

| 기호 | 의미 |
|---|---|
| `::=` | 정의 |
| `\|` | 택일 |
| `< >` | 비단말기호 |
| `' '` | 단말기호를 묶음 |
| `;` | 한 규칙의 끝 |

```
<if문> ::= if <논리식> then <문장> else <문장>
         | if <논리식> then <문장>
         ;
```

### EBNF (Extended BNF)
BNF에 메타기호를 추가해 **더 간결하게** 표현한 것.

| 기호 | 의미 | BNF로 풀면 |
|---|---|---|
| `[ ]` | 생략 가능(선택) | `A ::= x [y]` ↔ `A ::= x y \| x` |
| `{ }` | 0번 이상 반복 | `A ::= x {y}` ↔ `A ::= x \| A y` (재귀) |
| `( )` | 묶음(`\|`와 함께 한정된 택일) | `A ::= x (p\|q) y` ↔ `A ::= x p y \| x q y` |
| `' '` | 메타기호 자체를 단말기호로 사용 | |

예) `<if문> ::= if <논리식> then <문장> [ else <문장> ];`
예) `<unsigned integer> ::= <digit> { <digit> };`
예) `<수식> ::= <수식> ( + \| - \| * \| / ) <수식>;`

### 구문 도표(syntax diagram)
초기 Pascal 사용자 설명서에서 쓰인 **그림(순서도 유사)** 표현법.

- **사각형** = 비단말기호
- **원** = 단말기호
- **화살표** = 기호들을 연결하는 흐름(= 하나의 생성규칙)
- `[ ]` 선택 → 화살표가 **분기했다가 다시 합류**하는 경로(건너뛰는 경로 하나 추가)
- `{ }` 반복 → 지나간 뒤 **되돌아가는(루프백) 화살표**

예) `<unsigned integer> ::= <digit> { <digit> }` 는
`unsigned integer → [digit] →` 로 가다가, digit 뒤에서 **다시 digit로 되돌아가는 루프 화살표**를 그려 반복을 표현한다.

## 3. 의미의 표현

- **의미론**: 프로그램의 **내용적 효과**(실행 시 일어나는 일)를 정의. 자연어로 표현하는 경우가 많지만 명확성이 부족해 **형식 의미론** 기법들이 개발됨.

### 정적 의미론 — 프로그램 수행 **전** 의미가 맞는지 확인 (주로 타입 검사)
- **속성 문법**: 각 비단말기호에 "속성"(예: 타입)이 있다고 가정하고, 구문 규칙마다 속성을 계산하는 규칙을 함께 정의.
  예) `<T> ::= int` 일 때 `T.t = 정수`

### 동적 의미론 — 프로그램 수행 시 나타나는 의미를 표현
- **기능적 의미론**: "추상기계의 상태"(수행할 명령어, 메모리 상태)가 바뀌는 것으로 수행 의미를 표현. `<명령어들, 메모리상태> ⇒ <남은 명령어들, 바뀐 메모리상태>`
- **표기적 의미론**: 각 구문 요소를 수학적 표기(의미함수)에 대응시킴. 예) `Bin[[B 0]] = 2 * Bin[[B]]`
- **공리적 의미론**: 프로그램의 "효과"로 의미를 표현. `{P} S {Q}` = 프로그램 S를 실행하면 사전조건 P가 사후조건 Q로 변함. 대입문 효과 공리: `{Q[x→E]} x = E; {Q}`

**효과**: 속성문법 → 컴파일러/인터프리터의 트리 생성·타입검사·코드생성에 유용 / 수학적 표기 → 언어 특성을 명확히 정의할 때 / 공리적 의미론 → 프로그램이 특정 조건을 만족하는지 검증할 때.
**한계**: 언어 전체에 대한 의미 표현은 매우 복잡하다.
