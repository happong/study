# 02강 — 프로그래밍 언어의 발전 및 동작 원리

## 1. 프로그래밍 언어의 발전

### 컴퓨터/운영체제 발전 배경
- 아이디어 시대(튜링기계) → 전자식 컴퓨터(에니악, 콜로서스) → 프로그램 저장 방식 컴퓨터(에드박)
- 일괄처리 OS → 시분할 OS → DOS(개인용 PC) → GUI/Linux

## 2. 프로그램 동작 원리

- **컴퓨터 구조**: CPU ↔ BUS ↔ 메모리(RAM)/저장장치(HDD)/외부저장장치
- **부팅**: 전원 ON → ROM의 BIOS가 하드웨어 점검 후 부트로더 실행 → 부트로더가 OS를 메모리에 적재
- **프로그램 수행**: CPU가 **인출(fetch)-해석(decode)-실행(execute)** 주기를 반복
- **언어 구현이 필요한 이유**: 기계어(이진수, 사람이 이해하기 매우 어려움), 어셈블리어(기계어와 거의 1:1 대응, CPU 종속적이라 이식성 없음) → 사람에 가까운 **고급 프로그래밍 언어**가 필요. 소스 프로그램과 목적(기계어) 프로그램의 간극을 메꿔야 함.

### 구현 방법 3가지
1. **인터프리터**: 고수준 명령을 해석하며 바로 수행. CPU의 인출-해석-실행 주기를 흉내냄.
2. **컴파일러**: 소스 프로그램 → 기계어 코드로 미리 번역 후 CPU가 실행. 해석 과정을 미리 다 해두므로 효율적. 상용 프로그램은 보통 컴파일 방식으로 판매.
3. **하이브리드(가상기계 방식)**: 소스 → (작은 컴파일러) → 중간 코드 → 가상기계(VM) 안의 인터프리터가 해석. (예: Java의 JVM)

## 3. 프로그래밍 언어의 평가 기준

### 요구사항 3가지
- **표현 풍부성**: 아이디어를 표현할 수 있는가
- **유지보수성**: 변화에 쉽게 대처할 수 있는가
- **실행 가능성**: 컴퓨터에서 실행 가능한가

### 설계 원칙
- **규칙성(regularity)** → 일반성·직교성·일관성
- **추상화 지원** → 데이터/제어 추상화, 추상 데이터 타입 정의
- **복잡도 제어** → 캡슐화·모듈화

### 평가 기준 9가지 (요구사항과의 매핑이 시험 포인트)
작성력, 가독성, 신뢰성, 직교성, 일관성, 확장성, 효율성, 유연성, 이식성
→ 표현풍부성과 관련: 작성력/직교성/일관성/확장성/유연성
→ 유지보수성과 모두 관련 / 실행가능성과 관련: 신뢰성/효율성/이식성

### 상충(trade-off) 관계 — 자주 출제
| 사용자 측면 | ↔ | 개발자 측면 |
|---|---|---|
| 효율성(검사비용↓) | ↔ | 신뢰성(더 많이 검사) |
| 가독성(간단해야 이해 쉬움) | ↔ | 작성력(복잡해도 많은 기능) |
| 신뢰성(제약 많아야 안전) | ↔ | 유연성(제약 적어야 편함) |

→ 평가 기준은 서로 상충될 수 있어 **적절한 지점에서 절충**해야 함.

### 언어 선택 기준
커뮤니티가 활발/호의적인 언어, 특정 응용 분야가 있는 언어, 접해보지 못한 패러다임을 배울 수 있는 언어.
