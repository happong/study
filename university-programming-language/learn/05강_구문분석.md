# 05강 — 구문 분석

## 1. 어휘 분석

- 프로그램 분석 = **어휘 분석**(문자 → 어휘) → **구문 분석**(어휘 → 구문 트리)
- **어휘 분석**: 프로그램에서 쓰인 단어를 구별해내는 과정.
  - **렉심(lexeme)**: 프로그램에 실제로 사용된 단어(예: `x12`, `if`, `+`)
  - **토큰(token)**: 렉심이 속하는 분류(= 렉심의 집합). 예: 연산자, 구분자, **식별자**, **예약어**, 리터럴
- **식별자**: 변수·함수 등의 이름. 전통적으로 문자+숫자 조합, 첫 글자는 문자.
  `<identifier> ::= <letter> | <identifier> <letter> | <identifier> <digit>`
- **예약어**: 언어 자체에 정의되어 포함된 토큰(if, for, int 등). 식별자와 구문 구조는 같지만 **사용자가 재정의할 수 없음**. C의 어휘분석기는 예약어를 먼저 검사한 뒤 토큰으로 반환.

## 2. 파스 트리(parse tree)

- **유도(derivation)**: 구문 규칙을 이용해 주어진 프로그램을 만들어내는 과정. 유도가 가능하면 **문법적 오류가 없는 유효한 프로그램**이다.
- **파스 트리**: 유도 과정을 트리 형태로 나타낸 것.
  - **루트 노드** = 시작 비단말기호
  - **단말 노드** = 단말기호
  - 단말 노드를 **왼쪽부터 오른쪽으로** 나열하면 원래의 프로그램이 됨
- 주어진 표현에 대해 **파스 트리가 존재 → 구문에 부합**, **존재하지 않음 → 오류 있는 표현**.

## 3. 모호성(ambiguity)

- 하나의 표현에 대해 **파스 트리가 여러 개** 존재할 수 있음.
  - 구문론 관점: 파스 트리가 존재하므로 구문에는 맞음
  - 의미론 관점: 서로 다른 의미로 해석될 수 있음 → **모호한 문법(ambiguous grammar)**
- 문제점: 하나의 프로그램이 서로 다른 결과를 낼 수 있어, 프로그래머의 의도와 다르게 해석되어 **잘못된 결과**를 낳을 위험이 있다.
  예) `1+5*2`를 `(1+5)*2=12`로 해석할 수도, `1+(5*2)=11`로 해석할 수도 있는 모호한 문법.

### 모호성 제거 방법 3가지 (대표 패턴 — 시험에 자주 나옴)

**① 연산자 우선순위 계층화**: `<exp>` 하나로 모든 연산을 표현하던 것을, `<exp>(+,-) → <term>(*,/) → <factor>(괄호,숫자)` 처럼 **우선순위별로 비단말기호를 계층화**해서 모호성을 없앤다.

```
<exp>    ::= <exp> + <term> | <exp> - <term> | <term>
<term>   ::= <term> * <factor> | <exp> / <factor> | <factor>
<factor> ::= ( <exp> ) | <digit>
```

**② 좌결합 연산자(결합 방향 강제)**: 같은 우선순위의 연산자가 연속되면 **왼쪽부터** 묶이도록, 규칙의 좌변 비단말기호를 우변 "앞쪽"에만 재귀적으로 두고 뒤쪽은 한 단계 낮은 비단말기호로 고정한다. (`<exp> ::= <exp> + <term>` 처럼)

**③ 짝 잃은 else 문제(dangling else problem)**: 중첩된 if문에서 else의 개수가 if의 개수보다 적으면, 그 else가 어느 if와 짝인지 모호해짐. 해결: **else는 항상 "다른 else와 아직 짝지어지지 않은, 가장 가까운 if"와 짝**이 되도록 규칙을 분리한다 — 비단말기호를 `<문장>`(= 뒤에 else가 없을 수도 있는 if 포함)과 `<문장2>`(= if-else가 반드시 완결된 문장)로 나눠서, `then` 뒤에는 반드시 `<문장2>`만 오도록 강제한다.

```
<if문>  ::= if <논리식> then <문장2> else <문장> | if <논리식> then <문장>
<if문2> ::= if <논리식> then <문장2> else <문장2>
<문장>  ::= <if문> | <문장2> | ...
<문장2> ::= <if문2> | <대입문> | ...
```
