# 03강 — 프로그래밍 언어 패러다임 ⭐ (중간과제 1번 핵심)

## 1. 패러다임이란?

- 한 시대의 견해·사고를 규정하는 양식·규범·체계. 토머스 쿤의 "패러다임 전환"(예: 천동설→지동설) 개념에서 유래.
- **프로그래밍 패러다임**: 프로그램을 작성하는 전형적인 **방식/스타일**. 특정 언어에 종속되지 않음.
- **프로그래밍 언어 패러다임**: 해당 언어가 **지원하는** 프로그래밍 패러다임. 보통 한 언어는 **여러 패러다임을 동시에 지원**한다.

## 2. 패러다임의 변화 흐름 (왜 등장했는가)

| 패러다임 | 등장 배경 |
|---|---|
| **명령형(imperative)** | 데이터에 어떤 연산을 어떤 순서로 할지가 중요 |
| **절차형(procedural)** | 복잡한 데이터 처리 방식 자체를 잘 정리하는 것이 중요 (서브루틴화) |
| **함수형(functional)** | 데이터가 저장된 메모리 관리가 어려운 문제로 대두 |
| **논리형(logic, 선언적의 한 종류)** | 계산 절차를 "문제의 조건을 명시하는 규칙"으로 생각 |
| **객체지향(OOP)** | 같은 데이터에 대해 다른 처리 절차를 여러 개 명시해야 하는 경우가 흔함 |

변화 배경: 응용 도메인의 변화(계산 분야→다양한 응용 분야), 프로그램 구성 방식의 변화(명령어 나열→존재하는 모듈의 조합), 계산 모델의 변화(튜링기계 모델→새로운 계산 모델). 새 패러다임이 등장해도 기존 패러다임이 사라지지 않고 **서로 양립·보완**한다.

## 4. 각 패러다임의 특징과 예시 (GCD 구하기 예제로 비교)

### 명령형 프로그래밍
- 프로그램을 **일련의 명령어 나열**로 간주. 장점: 쉽게 이해 가능. 단점: 복잡한 프로그램을 효과적으로 다루기 어려움.
- 예(BASIC): `LET C = A - INT(A/B)*B` 처럼 변수에 값을 대입하는 명령을 순서대로 나열.

### 절차형 프로그래밍
- 프로그램을 **서브루틴(절차)의 집합**으로 구성. 재귀 호출로 프로시저를 간단히 정의 가능.
- **구조화 프로그래밍**: goto 없이 블록과 서브루틴, 구조화된 제어문만으로 작성하는 방법. 현재 대부분의 언어가 블록 구조 언어임.
- 예(C): `do { c = a % b; a = b; b = c; } while (b > 0);` 처럼 함수 안에 반복/조건 제어 구조로 처리를 구성.

### 객체지향 프로그래밍
- 프로그램 = 서로 통신하는 **객체(object)의 집합**. 소프트웨어 재사용으로 빠른 개발 지원.
- 객체 = 상태(**필드/멤버변수**)를 유지하며 외부 요청에 반응(**메소드/멤버함수**)하는 데이터. 상태는 숨기고 메소드는 공개(캡슐화).
- 예(Smalltalk): 블록으로 묶인 코드가 메시지(value:)를 받아 자신의 상태를 갱신.

### 함수형 프로그래밍
- 프로그램 수행 = 원하는 값을 구하는 것. 초깃값에 **함수를 반복 적용**해 값을 구함.
- 데이터는 값으로, 명령어는 함수로 취급 → **명령어가 데이터를 바꿀 수 없음**(대입문·반복문 없음).
- 함수 자체도 값으로 취급 가능 → 함수를 다루는 함수 = **고계함수**.
- 예(Haskell): `igcd a 0 = abs a; igcd a b = igcd (abs b) (a `mod` (abs b))` 처럼 재귀적 함수 정의로 계산.

### 선언적/논리 프로그래밍
- 프로그램은 **논리식(명제/술어)의 집합**으로 구성. 논리식을 나열함으로써 "무엇을 구할지"를 선언.
- 예(Prolog): `gcd(U, 0, U). gcd(U, V, X) :- V > 0, W is U mod V, gcd(V, W, X).` 로 규칙을 선언하고 질의(`?-`)로 값을 구함.

## 5. 패러다임별 "계산을 표현하는 방식" 요약 (정리 포인트)
- **객체지향**: 객체 사이의 **통신**을 통해 계산을 표현
- **함수형**: 함수의 **적용**을 통해 계산을 표현
- **논리**: 논리식의 **진위를 증명**하는 과정을 통해 계산을 표현
