## Lv.10 딕셔너리 (2026-08-10~, 진급 보류 중 — 계속 섞어서 출제할 것)

1. **키 존재 확인 방법 오류**: `dict.keys() == "keyname"`처럼 시도 (항상 `False`, 잘못된 방법)
   → 올바른 방법: `"keyname" in dict`
2. **매개변수 미사용**: 함수에서 매개변수로 받은 키 이름을 실제로 사용하지 않고, 따옴표로 감싼 고정 문자열을 키처럼 사용
   → 예: `dict["quest_name"]`(틀림, 문자열 리터럴) 대신 `dict[quest_name]`(맞음, 매개변수 변수)이어야 함
3. **괄호 혼동**: 딕셔너리 접근에 `()` 소괄호를 잘못 사용
   → `dict("key")`(틀림, 함수 호출처럼 씀) → `dict["key"]`(맞음, 대괄호로 접근)
4. **반복문 변수를 반복문 밖에서 재사용** (2026-08-28): `for key, value in dict.items():`에서 쓰던 `key`라는 이름을, 반복문이 없는 다른 함수에서도 마치 존재하는 변수처럼 그대로 사용 → `NameError: name 'key' is not defined`
   → 매개변수로 받은 이름(예: `item_name`)을 직접 키로 사용해야 함
5. **괄호+비교 혼용으로 키 존재 확인 시도** (2026-08-28): `play_dict(player_name) == True`처럼 딕셔너리를 함수처럼 호출(`()`)하면서 동시에 `== True`로 키 존재를 확인하려 함 → `SyntaxError`
   → 존재 확인은 `player_name in play_dict`, 값 접근/수정은 `play_dict[player_name]`
6. **`.items()`를 `.item()`으로 오타** (2026-08-28, 2회 반복): 메서드 이름 철자 오류 → `AttributeError: 'dict' object has no attribute 'item'`
   → 항상 `.items()`(끝에 s) 확인
7. **`return`을 `if` 블록 안에 너무 깊이 배치 (조기 종료)** (2026-08-28): `for` 반복문 안 `if` 블록 내부에 `return`을 넣으면, 조건을 처음 만족하는 순간 함수가 즉시 끝나버려 나머지 항목을 순회하지 못함
   → 반복이 다 끝난 뒤 `for` 블록 밖에서 결과를 `return`해야 함
8. **키 순회 시 값 대신 키를 비교** (2026-08-28): `for key in dict:`는 키만 순회함. 값을 조건에 써야 하는데 키(문자열)를 숫자와 비교 → `TypeError`
   → `.items()`로 키-값을 함께 받아 값을 비교해야 함
9. **`for`문이 반복 변수를 자동으로 만들어준다는 것을 모름** (2026-08-28): `for level, count in dict.items():`처럼 쓰면 반복이 시작되는 순간 `level`, `count`가 자동으로 생성/할당됨. 미리 선언하지 않아도 에러가 아닌데, "정의 안 해서 에러"라고 잘못 판단
10. **키 이름 오타가 우연히 같은 출력으로 이어져 못 알아챔** (2026-09-01): `"boss_cleared"`를 써야 하는데 `"boss_cleard"`로 오타. 데이터에 애초에 둘 다 없는 키라 출력 결과가 우연히 일치했지만, 실제로는 잘못된 키를 확인하는 숨은 버그였음
    → 출력이 맞아도 문제에 나온 키 이름 철자를 코드와 정확히 대조하는 습관 필요

## Lv.11 튜플 (도입: 2026-09-07)

11. **인덱스와 값을 혼동** (2026-09-09): 리스트/튜플에서 "몇 번째 자리인지"(인덱스, 0부터 시작)와 "그 자리에 든 실제 값"을 헷갈림. `(90, 85, 100)`의 첫 번째 값 90을 바꾸려다 `scoreLi[90] = 95`처럼 값 90을 인덱스 자리에 넣어 `IndexError`
    → "첫 번째"는 항상 인덱스 `0`
12. **리스트/딕셔너리를 함수처럼 호출** (2026-09-09): 매개변수로 받은 리스트 `logs`를 `logs()`처럼 호출 → `TypeError: 'list' object is not callable`. Lv.10의 `dict("key")` 실수와 같은 계열 (자료구조 접근에 `()`를 쓰면 안 됨, 함수 호출과 값 접근을 구분)
13. **`return`이 `if` 밖으로는 나왔지만 여전히 `for` 안에 있어 조기 종료** (2026-09-09): Lv.10에서 배웠던 "조기 return" 실수가 Lv.11에서도 재발. `return`은 `for`와 같은 들여쓰기(반복문 완전히 바깥)에 있어야 전체를 다 순회함
14. **`min()`/`max()` 내장 함수를 몰라서 직접 구현하려다 막힘** (2026-09-09): 리스트의 최솟값/최댓값을 구하는 표준 내장 함수가 있다는 걸 몰라서 중첩 반복문으로 시도하다 막힘 → `min(리스트)`, `max(리스트)` 안내 후 해결

## 복습(Lv.1~11 종합) 세트에서 새로 발견 (2026-09-14)

15. **딕셔너리 키(문자열)를 따옴표 없이 변수처럼 씀**: `config[theme]`처럼 문자열이어야 할 키를 따옴표 없이 써서 변수로 착각됨 → `NameError`. 10번 패턴("매개변수 대신 리터럴 사용")의 반대 케이스 — 리터럴이어야 하는데 변수처럼 씀
16. **문자열 조합 시 구분자 공백/접미사 누락**: 로직은 맞지만 `" - "`의 공백, `"원"` 같은 접미사를 빠뜨려 정확한 문자열 매칭에서 계속 실패 (2026-09-09, 2026-09-14 반복) → 목표 문자열을 한 글자씩 비교하는 습관 필요
17. **비슷한 이름의 변수를 착각해서 엉뚱한 변수를 참조 (에러 없이 조용히 틀림)**: `salesList.append(sales)`라고 써야 하는데 `salesList.append(salesList)`처럼 자기 자신을 참조 → 에러 없이 자기참조 리스트가 되어 이상한 출력. **에러 메시지가 없는 버그가 더 위험할 수 있음**을 보여주는 사례

## 복습(Lv.1~11 종합) 세트에서 새로 발견 (2026-09-15)

18. **"이상"(`>=`)과 "초과"(`>`) 혼동, 테스트 데이터에 경계값이 없어 우연히 통과**: 문제는 "5000 이상"인데 `num > 5000`을 씀. 데이터에 정확히 5000이 없어 결과가 우연히 일치 — 16번(Q4)과 같은 "우연히 맞는 출력" 계열
19. **최댓값 찾기에서 비교 기준값을 갱신하지 않음**: `if 값 >= 최댓값:` 안에서 이름(정답)만 갱신하고, 비교에 쓰이는 `최댓값` 변수 자체는 갱신하지 않아 조건이 사실상 항상 참이 되어 마지막 항목이 남아버림 → 최댓값 찾기는 "비교값"과 "정답"을 항상 함께 갱신해야 함
20. **`else`를 `for` 안에 둬서 첫 항목만 보고 조기 종료 (조기 return의 변형)**: `if 일치: return 값 / else: return 기본값`을 반복문 **안**에 두면, 첫 번째 항목이 불일치하는 순간 나머지를 검사하지 않고 바로 기본값을 반환함. 주어진 테스트만으로는 못 잡아낼 수 있는 숨은 버그 — 다른 키로 추가 테스트해봐야 드러남

## 복습 세트에서 새로 발견 (2026-09-16)

21. **`range()`에 리스트를 그대로 넣음**: `range()`는 정수를 받아 "0부터 그 수 전까지"의 숫자를 만드는 함수인데, 리스트를 그대로 `range(리스트)`에 넣어 순회하려 함 → `TypeError: 'list' object cannot be interpreted as an integer`
    → 리스트를 그냥 순회할 땐 `range()` 없이 `for x in 리스트:`로 충분함

## Lv.12 파일 입출력 (도입: 2026-09-17)

22. **"w" 모드로 쓰고 같은 블록에서 바로 읽으려 함**: `"w"`(쓰기 전용) 모드로 연 파일에서 바로 `read()`를 호출하면 에러. 쓰고 나서 읽으려면 별도로 다시 `open("파일명", "r")`로 열어야 함
23. **`write()`에 여러 인자를 콤마로 전달**: `print()`와 달리 `write()`는 문자열 **하나만** 받음(`write(a, b, c)` → `TypeError`). 여러 값을 쓰려면 미리 `+`로 합친 문자열 하나를 만들어야 함
24. **딕셔너리를 `.items()` 없이 두 변수로 순회 (에러 없이 조용히 틀림, 위험도 높음)**: `for name, score in 딕셔너리:`처럼 쓰면 키(문자열)만 순회되는데, 키가 2글자면 언패킹 에러 없이 **글자 단위로 쪼개져서** 들어감(`"하은"` → `name='하', score='은'`). `.items()`를 반드시 써야 함
25. **`readline()`(단수)과 `readlines()`(복수) 혼동**: `readline()`은 첫 줄 하나만 문자열로 가져오는데, 거기에 `len()`을 쓰면 "줄 수"가 아니라 "그 줄의 글자 수"가 나옴. 특정 테스트 데이터(첫 항목 글자 수 == 전체 개수)에서만 우연히 맞고, 개수나 항목이 조금만 바뀌면 확실히 틀림 — "우연히 맞는 정답" 패턴 중 가장 설득력 있게 반박이 필요했던 사례(여러 반례로 직접 증명함)

## 복습 세트에서 새로 발견 (2026-09-21)

26. **`read()`로 받은 문자열에 `.readlines()` 호출**: `read()`는 문자열을 반환하는데, 그 문자열 변수에 파일 전용 메서드인 `.readlines()`를 부르려 함 → `AttributeError: 'str' object has no attribute 'readlines'`. `read()`와 `readlines()`는 파일 객체에서 하나만 선택해서 써야 함
27. **문제의 핵심 동작(파일 쓰기/읽기)을 건너뛰고 계산 결과만 반환**: 요구된 로직(최댓값 찾기 등)은 정확했지만, 그 결과를 실제로 파일에 쓰고 다시 읽어오는 과정 없이 바로 return함. 출력값은 우연히 일치했지만 파일 자체가 생성되지 않아 그 문제가 연습시키려던 "쓰기/읽기" 동작을 전혀 연습하지 못한 사례
