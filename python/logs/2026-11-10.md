### 개념 질문 / 디버깅 과정 (매우 길었음, 상세 기록)

사용자가 Q10을 두고 튜플 언패킹과 딕셔너리 키:값 구조를 깊이 파고들며 여러 차례 질문함. 주요 흐름:
1. "왜 `totals[level]`로 값을 불러오느냐" → 딕셔너리는 `dict[key]`로 값을 읽는다는 것(Lv.10 복습)과, 누적합을 위해 기존 값을 먼저 읽어와야 한다는 것 설명
2. "`a,b,c` 중 `b`로 `c`를 부르는 거냐" → 혼동 소지가 있는 변수명(`level`)과 딕셔너리 키 조회를 분리해서 재설명
3. "`totals[level]`이 '일반'이라는 글자를 주는 거 아니냐" → 키(이름표)와 값(내용물)의 차이를 사물함 비유로 설명, 실제 실행으로 `totals[level]`이 숫자를 반환함을 확인시킴
4. "튜플 안에 키:값 매칭이 어떻게 되냐, `reportList[item]`하면 '일반'이 나오는 거 아니냐" → **핵심 오해 발견**: 사용자는 원본 튜플 `(item, level, count)`의 위치 관계가 `reportList` 딕셔너리 안에도 그대로 이어진다고 생각하고 있었음. 튜플 자체에는 키:값 관계가 전혀 없고(그냥 순서대로 값 3개), `reportList`의 키:값 관계는 코드에서 새로 만든 것(`reportList[level] = ...`)이라고 설명. 실제로 `reportList["골드박스"]`를 실행해서 `KeyError`가 나는 것을 보여줌으로써 "item은 reportList의 키로 쓰인 적이 없다"는 것을 증명
5. "그럼 reportList[level]이 처음엔 없었으니까 else에서 count 값이 그대로 들어가는 거냐" → 정확히 이해함, 확인해줌
6. "튜플/리스트/딕셔너리 항상 헷갈린다"는 소회 → 비교표(순서 vs 이름표, 가변 vs 불변)로 정리해줌

**신규 학습(설계 보완)**: Q9를 계기로 문자열에 대한 `in` 연산자(부분 문자열 포함 확인)와 `for line in file:`로 파일을 한 줄씩 순회하는 패턴을 간단히 가르침. `concepts/learned.md`에 추가.

### 새로 발견된 실수 패턴

- **파일을 반복문 안에서 매번 `open(..., "w")` 또는 `open(..., "a")`로 열어버림**: 반복마다 쓰기/추가가 일어나 결과가 덮어써지거나(마지막 것만 남음) 비정상적으로 누적됨. 여러 줄을 저장할 때는 `open`을 반복문 **밖에서 한 번만** 열고, 그 안에서 반복하며 계속 써야 함
- **`for` 문의 타깃 자리에 찾고 싶은 값 자체를 직접 씀**: `for "FAIL" in file:`처럼 쓰면 `SyntaxError: cannot assign to literal`. "문자열 안에 특정 단어가 있는지" 확인은 `for line in file: if "단어" in line:`처럼 **먼저 꺼내고, 그 다음에 포함 여부를 확인**하는 2단계로 나눠야 함
- **튜플의 "순서(위치) 관계"와 딕셔너리의 "키:값 관계"를 혼동**: 튜플 `(a, b, c)`를 언패킹한 뒤, 새로 만드는 딕셔너리에 그 변수들 중 하나(`item`)를 키로 써도 자동으로 나머지 값과 매칭될 거라고 착각하기 쉬움. 딕셔너리의 키:값 관계는 반드시 코드에서 명시적으로 지정(`dict[키] = 값`)해야 생긴다는 것을 강조할 것
