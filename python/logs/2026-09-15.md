def busiest_server(server_loads):
    maxCPU = 0

    for serverName, cpupercent in server_loads:

def user_range(daily_users):
    userNumver = []
    for daily, userN in daily_users:

### 새로 발견된 실수 패턴

- **Q7**: "이상"(`>=`)과 "초과"(`>`)를 혼동. 마침 테스트 데이터에 경계값(5000)이 없어서 결과가 우연히 일치 — Q4(9/1)의 "우연히 맞는 출력" 패턴과 동일 계열
- **Q8**: 최댓값 추적 시 비교 기준(`maxCPU`)을 반복 중 갱신하지 않아, 조건이 사실상 항상 참이 되어 마지막 항목이 남아버림 — "최댓값 찾기" 패턴에서 비교값과 갱신값을 함께 업데이트해야 함을 재확인
- **Q9**: `else`를 `for` **안**에 둬서, 첫 항목이 불일치하면 나머지를 검사하지 않고 바로 기본값을 반환 — "조기 return"의 변형(else를 통한 조기 종료). given 테스트만으로는 못 잡아내는 숨은 버그였고, 추가 테스트 케이스로 반례를 직접 보여준 뒤 사용자가 스스로 원인 파악하고 수정함

### 참고 (교육적 팁, 새 문법 아님)
사용자가 "Q8을 더 간단히 할 수 없냐"고 질문 → `max(server_loads, key=lambda pair: pair[1])[0]` 방식을 참고용으로 소개함. `lambda`/`key=`는 아직 커리큘럼에 도입되지 않은 문법이라 지금 단계에서 사용 강제하지 않음.
