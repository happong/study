# 05강 — 연결 리스트

## 핵심 요약

- **리스트(list)**는 원소들 사이에 "논리적인 순서"가 유지되는 자료구조이다. 이 순서는 메모리에 실제로 저장된 물리적 위치와는 상관없다.
- 리스트를 컴퓨터 안에 구현하는 방법은 크게 두 가지: **배열을 이용한 구현**과 **포인터를 이용한 구현(연결 리스트)**이 있다.
- 배열로 리스트를 만들면 원소의 논리적 순서 = 메모리에 저장된 물리적 순서가 되어, 중간에 원소를 삽입/삭제할 때 뒤의 원소들을 전부 밀거나 당겨야 해서 비효율적이다.
- **연결 리스트(linked list)**는 원소값(data)과 "다음 원소의 주소"(link, 포인터)를 한 묶음(노드, node)으로 저장해서, 물리적으로 떨어진 곳에 있어도 화살표(링크)로 논리적 순서를 표현한다.
- 연결 리스트는 **head(헤드) 포인터**가 첫 번째 노드를 가리키고, 각 노드가 사슬처럼 다음 노드를 가리키며, 마지막 노드의 링크는 **NULL**이다.
- 포인터(pointer)는 변수의 값이 아니라 "그 값이 저장된 메모리 주소"를 저장하는 특수한 변수이다. `*`(역참조)와 `&`(주소연산자)로 다룬다.
- 연결 리스트에 노드를 **삽입**하거나 **삭제**할 때는 배열처럼 전체를 밀 필요 없이, 앞뒤 노드의 링크(화살표)만 바꿔주면 된다 — 이것이 연결 리스트의 가장 큰 장점이다.
- 연결 리스트의 삽입/삭제는 반드시 **순서를 지켜서** 링크를 연결해야 한다. 순서를 틀리면 리스트의 나머지 부분을 영영 잃어버릴 수 있다(연결이 끊김).

## 상세 내용

### 1. 리스트의 개념

**비유**: 리스트는 "맛집 웨이팅 명단"과 같다. 1번, 2번, 3번... 손님이 적힌 순서가 있다. 이 순서는 종이 위의 "의미"일 뿐, 그 손님들이 실제로 가게 안 어디에 앉아 있는지(물리적 위치)와는 상관없다.

- **리스트의 의미**: '일정한 순서'의 나열. 어떤 정의에 의해서 결정된 '논리적인 순서'의 나열.
  - 예: (3·1운동, 8·15광복, 6·25전쟁, 서울올림픽) — "일어난 시간 순서"라는 논리적 순서로 나열된 리스트.
- **배열(array)의 정의**: 원소의 메모리 공간(주기억장치)에서의 물리적인 위치를 '순서'대로 결정하는 자료구조. 배열의 순서는 메모리 공간에 저장되는 '원소값의 물리적 순서' 그 자체이다.
  - 예: 주소값 00ffff00에 100, 00ffff04에 200... 처럼 인덱스 1,2,3,4,5가 메모리 주소 순서와 딱 맞게 저장된다.
- **핵심 차이점**: 배열은 "인덱스로 표현되는 추상적 순서"가 "메모리 공간에서의 물리적 위치"와 일치한다. 하지만 리스트의 '순서' 개념은 사람 머릿속의 '논리적인 순서'이며, 원소들의 물리적인 저장 순서나 위치와는 무관하게 원소들 간의 논리적 순서만 유지하면 된다.
- **리스트의 구현 방법 두 가지**:
  1. 배열을 이용한 구현: 논리적 순서 = 물리적(메모리) 저장 순서
  2. 포인터를 이용한 구현: 원소값을 저장하는 공간 + "다음 원소를 가리키는 위치 정보(포인터)"를 저장하는 공간을 함께 구현

예시 그림: 개발자가 (3·1운동, 8·15광복, 6·25전쟁, 서울올림픽) 순서로 리스트를 만들고 싶어도, 컴퓨터는 메모리에 "서울올림픽, 8·15광복, (빈칸), 3·1운동, 6·25전쟁" 처럼 아무 순서로나 저장할 수 있다 — 그래도 포인터로 연결하면 원하는 논리적 순서를 표현할 수 있다는 것이 핵심이다.

### 2. 배열을 이용한 리스트의 구현

**비유**: 배열은 "번호가 붙은 사물함이 일렬로 쭉 붙어 있는 복도"다. 중간에 사물함 하나를 새로 끼워 넣으려면, 그 뒤의 사물함 주인들을 전부 한 칸씩 뒤로 옮겨야 한다.

- 리스트 (1919, 1945, 1950, 1988)을 배열 L로 구현: `L[0]=1919, L[1]=1945, L[2]=1950, L[3]=1988`
- **원소 삽입 예시**: 1936년 '애국가 작곡'을 리스트 중간(1919와 1945 사이)에 삽입하려면
  1. 1945, 1950, 1988을 모두 한 칸씩 뒤(오른쪽)로 이동시킨다.
  2. 비워진 L[1] 자리에 1936을 채워 넣는다.
  - 결과: L[0]=1919, L[1]=1936, L[2]=1945, L[3]=1950, L[4]=1988
  - 배열을 미리 충분히 크게 선언해두면 확장은 피할 수 있지만 → **메모리 낭비**가 생기고, 중간 삽입 시 원소들을 밀어야 하므로 → **연산 시간이 증가**한다.
- **원소 삭제 예시**: 리스트 (1919, 1936, 1945, 1950, 1988)에서 1936을 삭제하면, 뒤의 원소들(1945, 1950, 1988)을 모두 한 칸씩 앞으로 당긴다.
- **정리**: 배열로 구현한 리스트는 원소의 순서가 "연속된 물리적 주소"에 그대로 저장되므로, 삽입/삭제 시 해당 위치 뒤(또는 앞)의 모든 원소를 이동시켜야 한다. 원소 수가 많을수록 이동 시간이 늘어나고, 실행 중 메모리를 추가로 할당해야 하는 경우도 생긴다. 그래서 **실제 IT 서비스 환경에서는 배열 기반 리스트가 자주 쓰이지 않는다** — 삽입/삭제가 빈번한 상황에서는 비효율적인 컴퓨팅 성능을 유발하기 때문이다.
- (교재 외 생각해볼 질문) 스택과 큐는 왜 배열을 이용해 구현할까? 리스트는 왜 배열을 이용해 구현하지 않을까? — 스택/큐는 데이터가 한쪽 끝(또는 양 끝)에서만 추가·제거되어 "중간 삽입/삭제"가 필요 없기 때문에 배열이 적합하지만, 리스트는 중간 삽입/삭제가 잦아 배열이 불리하다는 점을 생각해보는 것이 포인트.

### 3. 포인터를 이용한 리스트의 구현 (연결 리스트)

**비유**: 연결 리스트는 "보물찾기 쪽지"와 같다. 첫 번째 쪽지에는 "다음 보물은 냉장고 셋째 칸에 있다"라고 적혀있고, 그 보물(원소값)과 함께 "다음 장소(주소)"가 같이 적혀 있다. 보물들이 집안 여기저기(메모리 여기저기) 흩어져 있어도, 쪽지를 따라가면 순서대로 찾아갈 수 있다.

- **노드(node)**: 리스트의 원소값(데이터) + 다음 원소를 가리키는 정보(포인터)로 구성된 자료 단위. 노드는 데이터 요소(원소값)와, 리스트의 다음 노드를 지시하는 포인터(주소, 링크(link))로 구성된다.
- 슬라이드 예시(식사 일정): "7월31일 식사" → "냉장고 셋째 칸" → "아침식사 / 거실TV 앞" → "점심식사 / 냉장고 냉동실" → "저녁식사 / 끝!!" 처럼, 각 쪽지가 "내용 + 다음 장소"를 담고 있다.
- **노드의 구조 및 연결**: 각 노드가 메모리 주소값 1919, 1945, 1950, 1988을 담고, Head가 첫 노드를 가리키며 각 노드가 사슬처럼 다음 노드의 메모리 주소를 담아 연결된다.
  - 표(연결 예시):

  | 메모리 주소 | 자료 | 링크 |
  |---|---|---|
  | 1000 | 1919 | 1004 |
  | 1004 | 1945 | 1100 |
  | 1100 | 1950 | 1110 |
  | 1110 | 1988 | Null |

  - 그림으로 표현하면: `head → [1919|●]→[1945|●]→[1950|●]→[1988|null]`
- 또 다른 예(요일): head가 '월'을 가리키고, 월→화→수→...→일까지 연결되며 마지막 '일'의 링크는 빈 칸(null)이다. 이 예시는 "논리적 순서(월,화,수,...)"와 "실제 메모리상의 저장 위치(17, 33, 50, 62, 75, 80, 124 등 뒤죽박죽)"가 다를 수 있음을 보여준다.
- **배열과 연결리스트의 차이**: 배열은 컴퓨터가 정해준 연속된 메모리 주소(00ffff00, 04, 08, 0c, 10)에 개발자가 인덱스(AAA[1]~AAA[5])로 접근하지만, 연결리스트는 원소들이 메모리 여기저기(순서 없이) 저장되고 화살표(링크)로만 연결되어 논리적 순서가 유지된다.

### 4. 포인터 변수

**비유**: 포인터는 "집 주소가 적힌 쪽지"다. 쪽지 자체는 작은 메모지일 뿐이지만, 그 안에는 "진짜 보물이 있는 집 주소"가 적혀 있다. 쪽지(포인터)를 따라가면 진짜 값(보물)을 찾을 수 있다.

- 연결 리스트 노드를 C 언어 구조체로 정의하는 법:
```c
struct linked_list_node {
    int data;                      // 원소값(데이터)
    struct linked_list_node *link; // 다음 노드를 가리키는 포인터
};
```
- 생성 직후 노드는 `data`에 값이 없고 `link`는 `NULL`(아무것도 안 가리킴)로 시작한다.
- **포인터의 할당과 반환 예시**:
```c
int a, *p_a;
float b, *p_b;
p_a = (int *)malloc(sizeof(int));       // 정수 1개 크기만큼 메모리 할당
p_b = (float *)malloc(sizeof(float));   // 실수 1개 크기만큼 메모리 할당
*p_a = 10;      // p_a가 가리키는 곳에 10을 저장
*p_b = 3.14;    // p_b가 가리키는 곳에 3.14를 저장
printf("a is %d,  b is %f\n", *p_a, *p_b);
free(p_a);      // 메모리 반환(사용 끝)
free(p_b);
```
  - `malloc()`은 필요한 만큼 메모리 공간을 "새로 빌리는" 함수, `free()`는 다 쓴 메모리를 "돌려주는" 함수이다.
  - `*p_a = 10;` 처럼 `*`를 변수 앞에 붙이면 "포인터가 가리키는 곳의 값"이라는 뜻(역참조)이 된다.
- **포인터와 메모리의 관계 예시** (`char myVar; char *myPtr;`):
  - `myVar = 100;` → myVar가 저장된 메모리 주소(예: 1002)에 실제값 100이 저장됨.
  - `myPtr = &myVar;` → `&myVar`는 "myVar의 주소를 찾아주는" 연산. myPtr(예: 주소 2002에 저장된 변수)에는 myVar의 주소값(1002)이 저장된다.
  - 즉 `myPtr`은 "1002"라는 숫자(주소값)를 담고 있고, `*myPtr`은 그 주소에 가서 꺼내온 값(100)을 의미한다.
  - 실행 결과 예시: `myVar : 0x64, 100` / `&myVar : 0x2FF8C7, 3143879` / `myPtr : 0x2FF8C7, 3143879` / `*myPtr : 0x64, 100`

### 5. 연결 리스트의 삽입과 삭제

**비유**: 기차 칸을 서로 연결하는 고리(커플러)라고 생각하면 쉽다. 기차 중간 칸 하나를 빼거나(삭제) 새로 끼우려면(삽입), 그 칸을 통째로 들어 옮길 필요 없이 앞뒤 칸의 "연결 고리"만 바꿔 걸면 된다.

**노드 삭제**
- 초기 리스트: `head(5000) → [data:100, link:5500] → [data:200, link:6000] → [data:300, link:NULL]`
- 가운데 노드(X, 가리키는 데이터값 200)를 삭제하려면:
  1. 삭제할 노드(X)의 **선행 노드**(i)의 링크 필드를, 삭제할 노드의 **후행 노드**(j)를 가리키도록 바꾼다. (즉, i의 link를 6000 → 6000으로, 원래 가리키던 5500을 건너뛰고 j를 바로 가리키게 함)
  2. 삭제할 노드를 메모리에서 반환(free)한다.
- 삭제 후 결과: `head(5000) → [data:100, link:6000] → [data:300, link:NULL]` (가운데 노드가 사라지고 앞 노드가 바로 뒤 노드를 가리킴)

**노드 삽입**
- 초기 리스트: `head(5000) → [data:100, link:5500] → [data:300, link:NULL]`
- 1936(애국가 작곡)에 해당하는 새 노드 X(주소 6000, data:200)를 삽입하려면:
  1. X 노드의 링크부분이 **후행 노드가 될 j 노드**를 가리키게 한다. (`X.link = 5500`, 즉 j를 가리킴)
  2. 삽입될 X 노드의 **선행 노드가 될 i 노드**의 링크 필드가 X 노드를 가리키게 한다. (`i.link = 6000`, 즉 X를 가리킴)
- **순서가 중요하다!** 반드시 ①(X가 j를 가리키게) 먼저 하고, ②(i가 X를 가리키게) 나중에 해야 한다. 순서를 바꾸면(i가 먼저 X를 가리키게 하면) i→j로 가는 원래 연결이 끊어져서 뒤쪽 리스트 전체를 잃어버린다(연결 리스트 실무에서 자주 하는 실수).

## 상세 내용 (코드로 보는 연결 리스트의 여러 가지 연산)

슬라이드 6장에서 다룬 연결 리스트 연산 프로그램 코드를 순서대로 정리한다.

### (1) 연결 리스트의 노드/헤드 구조 정의 및 생성

```c
typedef struct ListNode {      // 단순 연결 리스트의 노드 구조 정의
    int data;
    struct ListNode* link;
} listNode;

typedef struct {               // 리스트의 헤드(first) 노드 구조 정의
    listNode* head;
} linkedList_h;

linkedList_h* createLinkedList_h(void) {  // 연결리스트 생성
    linkedList_h* H;
    H = (linkedList_h*)malloc(sizeof(linkedList_h));
    H -> head = NULL;
    return H;
}
```
→ 리스트가 막 생성되었을 때는 `head`가 `NULL`, 즉 "아직 아무 노드도 없는 빈 리스트" 상태이다.

### (2) 리스트 맨 뒤에 노드 삽입

```c
void addNode(linkedList_h* H, int x) {
    // 리스트 마지막 노드에 삽입 연산하며, x값은 1000이라고 가정함
    listNode* NewNode;
    listNode* LastNode;
    NewNode = (listNode*)malloc(sizeof(listNode));
    NewNode -> data = x;
    NewNode -> link = NULL;

    if (H -> head == NULL) {      // 현재 리스트가 공백인 경우
        H -> head = NewNode;
        return;
    }
    LastNode = H -> head;
    while(LastNode -> link != NULL) LastNode = LastNode -> link;  // 마지막 노드까지 이동
    LastNode -> link = NewNode;   // 마지막 노드가 새 노드를 가리키게 함
}
```
→ 비유: 줄 맨 끝까지 걸어가서(while문으로 link가 NULL일 때까지 이동), 맨 끝 사람이 새로 온 사람의 손을 잡게(link 연결) 하는 것과 같다. 단, 줄이 아예 비어있으면(head가 NULL) 새 사람이 바로 첫 번째 사람이 된다.

### (3) 특정 노드 뒤에 새 노드 삽입 (중간 삽입)

```c
void additNode(linkedList_h* H, listNode* prevNode, int itdata) {
    // 리스트 중간에 노드를 삽입하는 연산하며, itdata값은 1500이라고 가정함
    listNode* NewNode;
    NewNode = (listNode*)malloc(sizeof(listNode));
    NewNode -> data = itdata;
    NewNode -> link = NULL;

    NewNode -> link = prevNode -> link;  // ① 새 노드가 먼저 후행 노드를 가리키게
    prevNode -> link = NewNode;          // ② 그 다음 선행 노드가 새 노드를 가리키게
    return;
}
```
→ 순서가 바뀌면(②를 먼저 하면) `prevNode -> link`가 NewNode로 덮어써져서 원래 뒤에 있던 노드들의 주소를 잃어버린다(연결 끊김, "실패" 사례로 슬라이드에 나옴). 반드시 ① → ② 순서를 지켜야 한다.

### (4) 리스트의 마지막 노드 삭제

```c
void deleteNode(linkedList_h* H) {  // 리스트 마지막 노드 삭제
    listNode* prevNode;
    listNode* delNode;
    if(H -> head == NULL) return;              // 공백 리스트인 경우, 삭제 연산 중단

    if(H -> head -> link == NULL) {            // 리스트에 노드가 한 개인 경우
        free(H -> head);                        // 첫 번째 노드의 메모리를 해제
        H -> head = NULL;
        return;
    }
    else {                                      // 리스트에 노드가 여러 개 있는 경우
        prevNode = H -> head;
        delNode = H -> head -> link;
        while(delNode -> link != NULL) {        // 마지막 노드까지 따라감
            prevNode = delNode;
            delNode = delNode -> link;
        }
        free(delNode);                           // 마지막 노드 메모리 해제
        prevNode -> link = NULL;                 // 새로운 마지막 노드의 링크를 NULL로
    }
}
```

### (5) 특정 값을 가진 노드를 찾아서 삭제

```c
void findandDeleteNode(linkedList_h* H, int itdata) {
    // 연결 리스트에서 특정 노드를 검색하여 삭제하고자 하는 연산, itdata=200
    listNode* prevNode;
    listNode* delNode;
    if(H -> head == NULL) return;   // 공백 리스트
    prevNode = H;
    delNode = H -> head;

    while(delNode != NULL) {
        if(delNode -> data == itdata) {
            deleteitNode(H, prevNode, delNode);
            return;
        }
        else {
            prevNode = delNode;
            delNode = delNode -> link;
        }
    }
}

void deleteitNode(linkedList_h* H, listNode* prevNode, listNode* delNode) {
    // 연결 리스트에서 데이터의 값이 200인 노드(delNode)를 삭제하는 연산
    prevNode -> link = delNode -> link;   // 선행 노드가 삭제할 노드의 다음 노드를 바로 가리키게
    free(delNode);                        // 삭제할 노드 메모리 해제
    return;
}
```
→ 비유: 사슬에서 중간 고리 하나를 빼낼 때, 양옆 고리를 먼저 서로 걸어준 다음에 가운데 고리를 빼는 것과 같다.

## 기억해야 할 키워드

- **리스트(list)**: 원소들 간의 논리적 순서가 지켜지며 유지되는 자료구조
- **논리적 순서**: 데이터가 저장되는 물리적 위치와 상관없이, 사람 머릿속에 인식되거나 리스트상에서 의미적으로 유지되는 순서
- **배열(array)**: 인덱스로 표현되는 추상적 순서가 메모리상의 물리적 위치와 일치하는 자료구조
- **노드(node)**: 원소값(데이터)과 다음 원소를 가리키는 위치(주소값)로 구성된 자료 단위
- **포인터(pointer)**: 메모리에 저장되는 값(데이터)의 저장 위치에 대한 주소를 가리키는 데이터형
- **head**: 연결 리스트의 첫 번째 노드를 가리키는 포인터
- **link(링크)**: 노드 안에서 다음 노드의 주소를 저장하는 필드(포인터 필드)
- **NULL**: 더 이상 가리킬 노드가 없음(리스트의 끝)을 의미하는 값
- **malloc() / free()**: 메모리를 할당받는 함수 / 할당받은 메모리를 반환(해제)하는 함수
- **구조체(struct)**: 다양한 데이터형의 변수를 하나의 상자 안에 넣어서 선언하거나 사용하는 C 프로그래밍 문법
- **단항 연산자**: 피연산자를 하나만 갖는 연산자 (예: `*`, `&`)
- **prevNode / delNode / NewNode / LastNode**: 삽입·삭제 연산에서 선행 노드, 삭제할 노드, 새로 만든 노드, 마지막 노드를 가리키기 위해 쓰이는 포인터 변수들
- **삽입/삭제 순서의 중요성**: 연결 리스트에서 노드를 삽입·삭제할 때는 링크를 바꾸는 순서를 지켜야 하며, 순서를 틀리면 리스트의 나머지 부분과의 연결이 끊어진다
