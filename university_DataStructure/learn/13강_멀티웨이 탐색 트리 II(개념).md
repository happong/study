# 13강 — 멀티웨이 탐색 트리 II

## 핵심 요약

- 트리는 크게 **이진 트리**와 **멀티웨이 트리**(자식이 3개 이상일 수 있는 트리)로 나뉘고, 멀티웨이 트리 중 B-트리 계열에는 B⁺트리·B*트리·**2-3 트리**·**2-3-4 트리**·**레드 블랙 트리**가 있다.
- **2-3 트리**는 내부 노드가 **2-노드(자식 2개, 키 1개)** 또는 **3-노드(자식 3개, 키 2개)**만 존재하는 탐색 트리이며, "모든 잎 노드가 같은 레벨에 있어야 한다"는 제약만 있다.
- 2-3 트리에 키를 삽입하다 노드가 4-노드(키 3개)가 되어버리면(오버플로), 가운데 키를 부모로 올려보내는 **분리(split)** 로 다시 2-노드/3-노드로 되돌린다.
- 2-3 트리에서 키를 삭제할 때, 잎 노드가 아닌 곳의 키는 **후계자(왼쪽 서브트리의 최댓값 또는 오른쪽 서브트리의 최솟값)로 대체**한 뒤 지우며, 잎이 비면 **회전**(형제가 3-노드일 때 키를 하나 빌려옴) 또는 **결합**(형제와 합쳐 부모 키를 내림)으로 재구성한다.
- **2-3-4 트리**는 2-3 트리를 확장해 **4-노드(자식 4개, 키 3개)**까지 허용한 트리로, 2-노드·3-노드가 될 확률이 낮아져 2-3 트리보다 삽입/삭제 시 트리 재구성이 덜 일어나 더 효율적이다.
- 2-3-4 트리의 삽입에서는 4-노드가 생기면 **그 위치(루트/부모가 2-노드/부모가 3-노드)에 따라 분리**하며, 실무 구현에서는 삽입 경로를 따라 내려가면서 만나는 4-노드를 **미리(사전에) 분리**해 두는 방식(사전 분리, top-down split)을 많이 쓴다.
- **레드 블랙 트리**는 2-3-4 트리를 메모리 효율이 좋은 **이진 트리 모양**으로 바꾼 자료구조로, 같은 2-3-4 노드 안의 관계는 **빨간(레드) 간선**, 서로 다른 2-3-4 노드 사이의 부모-자식 관계는 **검정(블랙) 간선**으로 표시한다.
- 레드 블랙 트리의 **탐색은 일반 이진 탐색 트리와 똑같이** 동작하며, 삽입 시 4-노드에 대응하는 모양이 생기면 2-3-4 트리의 분리 규칙을 그대로 이진 트리 모양으로 적용해 재구성한다.

## 상세 내용

### 0. (복습) m원 탐색 트리 — 12강 내용

**비유**: 이진 탐색 트리가 "갈림길이 2개(왼쪽/오른쪽)뿐인 길"이라면, m원 탐색 트리는 "갈림길이 최대 m개까지 있는 길"이다.

이번 강의 도입부에서 12강의 m원(m-way) 탐색 트리 정의를 다시 확인한다.

- 노드 구조 : `P₀ k₀ P₁ k₁ P₂ … Pₙ₋₁ kₙ₋₁ Pₙ` (Pᵢ는 서브트리를 가리키는 포인터, kᵢ는 키 값), 이때 **n ≤ m - 1**
- 조건
  ① i = 0,…,n-2 인 i에 대해 kᵢ < kᵢ₊₁ (키 값은 오름차순으로 정렬)
  ② i = 0,…,n-1 인 i에 대해, Pᵢ가 가리키는 서브트리의 모든 키 값은 kᵢ 보다 작다
  ③ Pₙ이 가리키는 서브트리의 모든 키 값은 kₙ₋₁ 보다 크다
  ④ i = 0,…,n 인 i에 대해, Pᵢ가 가리키는 서브트리는 역시 m원 탐색 트리이다(재귀적 정의)
- 3원 탐색 트리의 노드 구조 예시: `P₀ k₀ P₁ k₁ P₂` (자식 포인터 3개, 키 2개)
- 슬라이드에는 10, 20, 30, 40, 42, 43, 50, 53, 60, 61, 62, 63, 70, 80, 82, 87, 88, 89, 90, 91, 92, 93, 0, 11, 12, 13, 22, 32 등의 키를 가진 **3원 탐색 트리** 그림 예시가 제시되어, 노드마다 최대 2개의 키와 3개의 자식 포인터를 가지는 모습을 보여준다.

### 1. 2-3 트리 (2-3 tree)

**비유**: 사물함 한 칸에 물건을 1개나 2개만 넣을 수 있다고 정해놓은 보관함이라고 생각하면 된다. 1개 넣은 칸(2-노드)은 문이 2개(왼쪽/오른쪽), 2개 넣은 칸(3-노드)은 문이 3개(왼쪽/가운데/오른쪽)로 통하는 식이다.

**정의**: 차수(자식 수)가 2 또는 3인 내부 노드만을 갖는 탐색 트리. 즉 **2-노드**(자식 2개, 차수 2)와 **3-노드**(자식 3개, 차수 3)만으로 구성되는 특수한 형태의 **B-트리**이다.

- 2-노드 혹은 3-노드라는 제약은 **내부 노드에만** 해당한다.
- ⇒ **모든 잎 노드는 같은 레벨에 있어야 한다**는 제약만 존재함 (이것이 2-3 트리가 "균형"을 유지하는 핵심 성질이다).

**노드 구조**

```
2-노드                3-노드
┌───┬──────┐     ┌───┬──────┬──────┐
│   │ lkey │     │   │ lkey │ rkey │
└───┴──────┘     └───┴──────┴──────┘
```

- 2-노드: 키 값 `lkey` 1개, 자식 `lchild`(왼쪽), `mchild`(중간) 2개
- 3-노드: 키 값 `lkey, rkey` 2개, 자식 `lchild`(왼쪽), `mchild`(중간), `rchild`(오른쪽) 3개

**2-3 트리의 조건**

① 각각의 내부 노드는 2-노드이거나 3-노드이다. 2-노드는 1개의 키 값을, 3-노드는 2개의 키 값을 갖는다.

② (2-노드) lchild, mchild를 각각 2-노드의 왼쪽 자식 및 중간 자식이라 하고, lkey가 이 노드의 키 값이라 하면:
- 루트가 lchild인 모든 2-3 서브 트리 키 값은 lkey보다 작고,
- 루트가 mchild인 모든 2-3 서브 트리 키 값은 lkey보다 크다.

③ (3-노드) lchild, mchild, rchild를 각각 3-노드의 왼쪽, 중간, 오른쪽 자식이라 하고 lkey, rkey를 이 노드의 두 키 값이라 하면:
- a. lkey < rkey
- b. 루트가 lchild인 모든 2-3 서브 트리 키 값은 lkey보다 작다.
- c. 루트가 mchild인 모든 2-3 서브 트리 키 값은 rkey보다 작고 lkey보다 크다.
- d. 루트가 rchild인 모든 2-3 서브 트리 데이터는 rkey보다 크다.

④ 모든 잎 노드는 같은 레벨에 있다.

**예시 트리** (1(2-노드)를 루트로, 2(3-노드), 3(2-노드) 자식)

```
            [ 4 ]            ← 1 (2-노드)
           /     \
    [ 1 | 2 ]    [ 8 ]       ← 2(3-노드), 3(2-노드)
```

**노드 구조 코드**

```c
typedef struct two_three *two_three_ptr;
struct two_three {
    int lkey, rkey;
    two_three_ptr lchild, mchild, rchild;
};
```

**2-3 트리의 탐색**

```c
two_three_ptr search23(two_three_ptr t, int x) {
    while(t)
        switch(compare(x, t)) {           // 검색키 x와 노드 t에 있는 키 값을 비교
            case 1 : t = t -> lchild;      // x가 노드 t의 왼쪽 키값(lkey)보다 작은 경우
                break;
            case 2 : t = t -> mchild;      // x가 lkey보다 크고 rkey보다 작은 경우
                break;
            case 3 : t = t -> rchild;      // x가 노드 t의 오른쪽 키값(rkey)보다 큰 경우
                break;
            case 4 : return (t);          // x가 노드 t의 키값들 중 어느 하나와 같은 경우
        }
    return(NULL);
}
```

**2-3 트리의 삽입**

예시: 위 트리(루트 [4], 왼쪽 [1|2], 오른쪽 [8])에 **키 값 7을 삽입**하는 과정
1. 탐색을 통해 7이 들어갈 잎 노드(오른쪽 [8] 노드)를 찾는다.
2. 그 노드에 7을 끼워 넣으면 `[7|8]`이 되어 **3-노드로 바뀔 뿐**, 아직 4-노드가 아니므로 추가 재구성이 필요 없다.

이어서 같은 트리에 **키 값 3을 삽입**하는 과정 (분리/split 예시)
1. 3이 들어갈 자리는 왼쪽 `[1|2]` 노드인데, 이미 3-노드이므로 3을 넣으면 `[1|2|3]`이라는 **4-노드(오버플로)** 가 되어버린다.
2. 이때 **가운데 키(2)를 부모로 올려보내고**, 나머지 두 키(1과 3)를 각각 2-노드로 쪼갠다(분리, split).
3. 결과: 부모 노드가 `[2|4]`(3-노드)가 되고, 그 자식으로 `[1]`, `[3]`, `[7|8]`의 세 개 2/3-노드가 생긴다.

**삽입 알고리즘 (의사코드)**

```c
void insert23(two_three_ptr t, int y) {
    two_three_ptr q, p;
    if (!(*t))
        new_root(t, y, NULL);
    else {
        p = find_node(*t, y);
        if (!p) {
            fprintf(stderr, "The key is currently in the tree\n");
            exit(1);
        }
        q = NULL;
        for ( ; ; )
            if (p -> rkey == INT_MAX) {     // 빈 자리가 있으면 그냥 끼워 넣음
                put_in(&p, y, q);
                break;
            }
            else {                          // 이미 꽉 찬(3-노드) 경우 분리
                split(p, &y, &q);
                if (p == *t) { new_root(t, y, q); break; }
                else p = delete();
            }
    }
}
```

**2-3 트리의 삭제**

- 삭제하려는 키가 **잎 노드가 아닌 노드**에 있으면, 그 자리를 바로 비우지 않고 **대체 키**로 바꾼 뒤 삭제한다.
  - 일반적으로 삭제한 키의 **왼쪽 서브트리에서 가장 큰 키 값**(또는 **오른쪽 서브트리에서 가장 작은 키 값**)을 선택해 대체한다.
- 대체 후 결국 **잎 노드에서 키 하나를 지우는 문제**로 귀결되는데, 이때 그 잎 노드가 비어버리면(2-노드였던 자리가 텅 비면) 두 가지 재구성 방법을 쓴다.

**① 회전(rotation)** : 형제가 **3-노드**인 경우 — 그 형제 노드의 키 값 중 하나를 부모로 올리고, 대신 부모로부터 키 값 하나를 가져다 빈 노드를 채운다.

예시: 키 값 7을 삭제 → 왼쪽 형제 `[1|2]`가 3-노드이므로, 형제의 키 1을 부모 자리(기존 부모 키 5)와 교환하듯 회전시켜 부모는 `[2|8]`이 되고, 비었던 자리는 부모의 옛 키 5를 받아 `[5]`가 된다. (왼쪽 형제 `[1]`, 가운데 `[5]`, 오른쪽 `[10]`으로 재구성)

**② 결합(combine)** : 형제가 **2-노드**인 경우 — 하나의 노드를 삭제하고 형제와 합쳐서, 부모의 키 하나를 끌어내려 합쳐진 노드에 채운다.

예시: 키 값 10을 삭제 → 형제 `[5]`가 2-노드이므로 결합. 부모 `[2|8]`에서 8을 끌어내려 형제와 합쳐 `[5|8]`로 만들고, 부모는 `[2]`(2-노드)만 남는다. (결합으로 부모의 키가 줄어들면, 그 상위에서 다시 회전/결합이 필요할 수도 있다.)

### 2. 2-3-4 트리 (2-3-4 tree)

**비유**: 2-3 트리의 사물함을 조금 더 키워서, 한 칸에 물건을 최대 3개(문 4개)까지 넣을 수 있게 만든 보관함이다.

**정의**: 2-3 트리를 확장하여 **4개의 자식을 가진 4-노드**(키 3개)까지 허용하는 탐색 트리.

- 2-3-4 트리는 2-3 트리보다 **삽입과 삭제가 용이**하다.
- 2-3-4 트리에서는 2-노드와 3-노드에 대한 **트리 재구성 확률이 2-3 트리에서보다 작기 때문에** 삽입 및 삭제 연산을 수행하는 데 더 효율적이다. (노드 한 칸에 더 많은 키를 담을 수 있어 분리가 덜 자주 일어난다는 뜻)

**노드 구조**

```
2-노드               3-노드                      4-노드
┌──────┐        ┌──────┬──────┐          ┌──────┬──────┬──────┐
│ lkey │        │ lkey │ rkey │          │ lkey │ mkey │ rkey │
└──────┘        └──────┴──────┘          └──────┴──────┴──────┘
```

**2-3-4 트리의 조건**

① 각각의 내부 노드는 2-노드, 3-노드 및 4-노드이다. 2-노드는 1개, 3-노드는 2개, 4-노드는 3개의 키 값을 갖는다.

② (2-노드) lchild, lmchild를 각각 2-노드의 왼쪽 자식 노드 및 좌중간 자식 노드라 하고 lkey를 키값이라 하면, 루트가 lchild인 모든 서브 트리 키 값은 lkey보다 작고, 루트가 lmchild인 모든 서브 트리 키 값은 lkey보다 크다.

③ (3-노드) lchild, lmchild, rmchild를 각각 3-노드의 왼쪽, 좌중간, 우중간 자식 노드라 하고 lkey, rkey가 키 값이면:
- a. lkey < rkey
- b. lchild 서브트리의 키 값은 lkey보다 작다.
- c. lmchild 서브트리의 키 값은 lkey보다 크고 rkey보다 작다.
- d. rmchild(=rchild) 서브트리의 키 값은 rkey보다 크다.

④ (4-노드) lchild, lmchild, rmchild, rchild를 각각 4-노드의 왼쪽, 좌중간, 우중간, 오른쪽 자식이라 하고 lkey, mkey, rkey가 키 값이면:
- a. lkey < mkey < rkey
- b. lchild 서브트리 키값은 lkey보다 작다.
- c. lmchild 서브트리 키값은 lkey보다 크고 mkey보다 작다.
- d. rmchild 서브트리 키값은 mkey보다 크고 rkey보다 작다.
- e. rchild 서브트리 키값은 rkey보다 크다.

⑤ 모든 잎 노드들은 같은 레벨에 있다.

**조건을 만족하는 2-3-4 트리의 예**

```
                         [10]
                /                    \
           [5]                     [13|17]
         /      \              /      |      \
   [1|2|3]    [8|9]        [11]     [15]    [19|20|21]
```

**2-3-4 트리의 삽입 연산 — 4-노드가 생겼을 때의 분리(split)**

삽입 연산 시 문제가 되는 **4-노드**는 그 위치에 따라 세 가지 경우로 구분하여 분리한다.

① **4-노드가 루트인 경우**: `[1|2|3]` → 가운데 키 2가 새 루트가 되고, 1과 3이 각각 자식 노드로 분리된다.

```
[1|2|3]        →        [2]
                       /     \
                    [1]       [3]
```

② **4-노드의 부모가 2-노드인 경우**
- (i) 4-노드가 부모의 왼쪽 자식일 때: 부모 `[4]` + 왼쪽 자식 `[1|2|3]` → 가운데 키 2를 부모로 올려 부모가 `[2|4]`(3-노드)가 되고, 1과 3이 각각 독립된 자식이 된다.
- (ii) 4-노드가 부모의 오른쪽 자식일 때: 부모 `[1]` + 오른쪽 자식 `[2|3|4]` → 가운데 키 3을 부모로 올려 부모가 `[1|3]`이 되고, 2와 4가 독립된 자식이 된다.

③ **4-노드의 부모가 3-노드인 경우**
- (i) 4-노드가 맨 왼쪽 자식일 때: 부모 `[4|5]` + 왼쪽 자식 `[1|2|3]` → 가운데 키 2를 올려 부모가 `[2|4|5]`(4-노드)가 되고, 1과 3이 독립된 자식이 된다.
- (ii) 4-노드가 가운데(혹은 다른) 자식일 때: 부모 `[1|5]` + 자식 `[2|3|4]` → 가운데 키 3을 올려 부모가 `[1|3|5]`가 되고, 2와 4가 독립된 자식이 된다.

> **참고**: 위처럼 "삽입하다 보니 4-노드가 생겨서 그 자리에서 분리"하는 방식 외에, 실제 구현에서는 **삽입에 대비한 4-노드 사전 분리(top-down split)** 방식을 많이 쓴다. 즉 삽입할 키를 찾아 루트에서부터 내려가는 길(경로) 위에서 **4-노드를 만날 때마다 미리** 위 ①~③과 똑같은 규칙으로 쪼개 놓아, 정작 삽입할 때는 절대 4-노드가 만들어지지 않게(뒤로 되돌아갈 필요 없게) 만드는 기법이다. 슬라이드의 "삽입에 대비한 4-노드 사전 분리 (i)(ii)(iii)" 예시들은 위 ①~③과 **구조적으로 동일한 세 가지 경우**를 "미리 쪼갠다"는 관점에서 다시 보여준 것이다.

**2-3-4 트리의 삭제 연산**

- 잎 노드에 있는 키 값은 **단순히 삭제하면 됨**.
- 3-노드, 및 4-노드인 잎 노드는 각각 2-노드 및 3-노드가 되므로 **트리의 재구성이 불필요**하다. (2-노드였던 잎이 삭제로 비는 경우에만 2-3 트리처럼 회전/결합 등의 재구성이 필요해진다.)

### 3. 레드 블랙 트리 (red-black tree)

**비유**: 2-3-4 트리는 한 칸(노드)에 키가 여러 개 들어갈 수 있어 편리하지만, 노드 하나의 크기가 들쭉날쭉(1~3개 키)해서 메모리 관리가 번거롭다. 레드 블랙 트리는 이 2-3-4 트리를 "한 칸에 키 1개씩만 들어가는 보통의 이진 트리" 모양으로 눌러 편 것이다. 다만 원래 같은 칸(노드) 안에 있었던 키들끼리는 특별히 **빨간 선(레드 간선)** 으로 표시해서, "사실 이건 한 묶음이었다"는 흔적을 남겨둔다.

**정의**: 효율적인 기억 장소 사용을 위하여 **2-3-4 트리를 이진 트리로 나타낸** 탐색 트리이다.

- **레드 간선**과 **블랙 간선**의 서브 트리 포인터를 가짐
- **레드 간선**은 2-3-4 트리의 **한 노드 내에 있던 노드들 사이의 관계**이고, **블랙 간선**은 2-3-4 트리의 **부모-자식 관계**이다.
- 레드 블랙 트리의 **탐색 방법은 보통의 이진 탐색 트리의 탐색 알고리즘과 동일**하다. (빨강/검정 구분은 삽입·삭제 시 트리 모양을 관리하기 위한 표시일 뿐, 탐색 자체는 그냥 "작으면 왼쪽, 크면 오른쪽"으로 내려가면 된다.)

**3-노드에 대응하는 레드 블랙 트리** (구분을 위해 레드 간선은 점선, 블랙 간선은 실선으로 표시)

3-노드 `[1|2]`는 다음 **두 가지 모양** 중 하나로 이진 트리화될 수 있다(어느 키를 부모로 삼느냐에 따라 다름). 두 모양 모두 빨간 간선 1개를 가진다.

```
모양 A: 2가 부모            모양 B: 1이 부모
     [2]                       [1]
    /                              \
 [1](빨간 간선)                  [2](빨간 간선)
```

**4-노드에 대응하는 레드 블랙 트리**

4-노드 `[1|2|3]`은 가운데 키 2가 부모가 되고, 1과 3이 각각 **빨간 간선**으로 연결된 자식이 된다.

```
          [2]
      (빨강)/  \(빨강)
         [1]    [3]
```

**2-3-4 트리 전체를 레드 블랙 트리로 변환한 예**

앞서 본 2-3-4 트리 예시(루트 10, 자식 5·[13|17], …)를 레드 블랙 트리로 바꾸면 다음과 같은 모양이 된다. (점선 = 레드 간선, 실선 = 블랙 간선)

```
                         10
                /                 \
             5                     13
           /   \                /      \
         2       9            11         17 (점선, 레드 간선)
       /  \    /(점선)                  /    \
     1    3   8                      15       20
   (점선)(점선)(점선)                        /    \
                                          19      21
                                        (점선)   (점선)
```

- 10-5-13 사이, 5-2-9 사이, 13-11-17 사이, 17-15-20 사이는 **블랙 간선**(서로 다른 2-3-4 노드 사이 관계)
- 2-1, 2-3, 9-8, 13-17, 20-19, 20-21 사이는 **레드 간선**(원래 같은 2-3-4 노드였던 키들 사이 관계)

**레드 블랙 트리에서 삽입 연산을 위한 노드 분리**

2-3-4 트리에서 4-노드가 루트인 경우의 분리(`[1|2|3]` → 부모 2, 자식 1·3)를 레드 블랙 트리 모양으로 표현하면: 분리되기 전에는 2-1, 2-3 간선이 모두 **점선(레드)** 이었다가, 분리 후에는 2가 새 루트가 되면서 2-1, 2-3 간선이 모두 **실선(블랙)** 으로 바뀐다. 즉 레드 블랙 트리의 재구성도 2-3-4 트리의 분리 규칙을 그대로 따르되, "간선의 색(레드↔블랙)을 바꾸는 것"으로 표현된다는 점이 핵심이다.

### 4. 트리 전체 분류 정리

이 강의에서 다룬 트리들은 아래 분류도에서 멀티웨이 트리 계열(B-트리 계열)의 맨 아래쪽에 해당한다.

```
                        트리
            /                        \
        이진 트리                  멀티웨이 트리
       /          \                      |
    Heap      이진 탐색 트리        m원 멀티웨이 트리
             /    |      \                |
          AVL   BB    Splay           B-트리
          트리  트리   트리          /   |   \
                                 B⁺  B*  2-3 트리
                                트리 트리     |
                                        2-3-4 트리
                                             |
                                        레드 블랙 트리
```

## 기억해야 할 키워드

- **2-노드(2-node)**: 자식(차수)이 2개, 키 값이 1개인 내부 노드
- **3-노드(3-node)**: 자식(차수)이 3개, 키 값이 2개인 내부 노드
- **4-노드(4-node)**: 자식(차수)이 4개, 키 값이 3개인 내부 노드
- **2-3 트리**: 2-노드와 3-노드만으로 구성된 탐색 트리(모든 잎이 같은 레벨), B-트리 계열과 거의 같은 성능을 유지하면서 삽입·삭제가 상대적으로 쉬움
- **2-3-4 트리**: 2-노드, 3-노드, 4-노드만으로 구성한 트리로 2-3 트리와 같은 특성을 가지며, 재구성 빈도가 더 낮아 효율적임
- **분리(split)**: 삽입으로 4-노드(오버플로)가 생겼을 때 가운데 키를 부모로 올려보내고 나머지를 둘로 쪼개는 연산
- **사전 분리(top-down split)**: 삽입 경로를 따라 내려가며 만나는 4-노드를 미리 쪼개 두어, 되돌아가는 재구성을 없애는 삽입 기법
- **회전(rotation)**: 2-3 트리 삭제 시, 형제가 3-노드이면 형제의 키를 부모로 올리고 부모 키를 내려받아 빈 노드를 채우는 재구성
- **결합(combine)**: 2-3 트리 삭제 시, 형제가 2-노드이면 부모 키를 내려 형제와 합쳐 하나의 노드로 만드는 재구성
- **레드 블랙 트리(red-black tree)**: 2-3-4 트리를 이진 트리 모양으로 나타낸 트리로 기억장소를 효율적으로 사용함
- **레드 간선**: 2-3-4 트리의 한 노드(2/3/4-노드) 안에 있던 키들 사이의 관계를 나타내는 간선
- **블랙 간선**: 2-3-4 트리에서 서로 다른 노드 사이의 부모-자식 관계를 나타내는 간선
- **레드 블랙 트리의 탐색**: 일반 이진 탐색 트리의 탐색 알고리즘과 동일
