# 01강 — 자료구조란 무엇인가

(컴퓨터과학과 정광식 교수 / 한국방송통신대학교)

## 핵심 요약

- **자료(Data)** 는 관찰·측정으로 얻은 "날것" 값이고, **정보(Information)** 는 그 자료를 가공(처리)해서 의사결정에 쓸 수 있게 만든 결과물이다. 공식으로 `I = P(D)` (정보 = 처리(자료)).
- 자료는 **정리(정렬·분류)** 가 되어 있어야 빠르게 의미를 파악할 수 있고, 효율적으로 정보로 바뀐다. 정리되지 않은 자료는 혼란만 준다.
- **추상화(Abstraction)** 란 공통적인 개념만 뽑아서 같은 종류의 다양한 대상을 하나로 정의하는 것이다. 핵심 특징만 남기고 불필요한 세부사항은 버린다.
- **자료의 추상화**는 컴퓨터 내부에서 자료가 실제로 어떻게 저장되는지(이진수, 주소 등)는 신경 쓰지 않고, 개발자 머릿속에서 그림처럼 자료를 개념화하는 것이다.
- **추상 자료형(ADT, Abstract Data Type)** 은 "자료값의 집합 + 그 자료에 대한 연산의 집합"으로 자료의 성격을 정의하는 형식이며, 자료구조를 표현하는 가장 대표적인 방법이다.
- **자료구조(Data Structure)** 는 추상화를 통해 알고리즘에서 사용할 자료들 사이의 논리적 관계를 구조로 만든 것이다.
- **알고리즘(Algorithm)** 은 컴퓨터에게 일을 시키기 위한, 추상화된 명령어의 유한한 연속 덩어리이며, 출력·유효성·입력·명확성·유한성의 5가지 조건을 반드시 만족해야 한다.
- 알고리즘의 성능은 **시간 복잡도**(실행 횟수 O(n)으로 예측)와 **공간 복잡도**(고정+가변 메모리, Sp = Sc + Se)로 분석하거나, 실제 실행 시간을 시계로 측정해서 평가한다.

## 상세 내용

### 1. 자료와 정보

**쉬운 비유**: 연필꽂이에 연필이 아무렇게나 꽂혀 있으면("나쁜 자료구조") 원하는 색 연필을 찾기 어렵다. 하지만 색깔별로 정리되어 라벨까지 붙어 있으면("좋은 자료구조") 한눈에 파악하고 바로 쓸 수 있다. 이것이 "자료"와 "정보"의 차이를 보여주는 그림이다.

- **자료의 가공 결과가 정보다.**
  ```
  자료 ──(컴퓨터의 처리)──▶ 정보
  I = P(D)   (I: Information, P: Process, D: Data)
  ```
- **자료(Data)의 정의**
  - 현실 세계에서 관찰이나 측정을 통해서 수집된 값(value)이나 사실(fact)
  - 우리 생활에서 실제로 만지거나 볼 수 있는 것(길이, 무게, 부피 등 측정 가능한 대상)을 물리적인 단위로 표현하여 얻어낸 내용
  - 정리되지 않은 자료는 무작위로 흩어져 있어 아무 의미도 전달하지 못하고 혼란만 유발한다.
  - 정리된 자료는 빠른 이해와 효율적인 판단을 가능하게 하며, 정보로의 전환이 효율적이다.
- **정보(Information)의 정의**
  - 어떤 상황에 대해 적절한 의사결정을 할 수 있게 하는 지식으로서, 자료의 유효한 해설이나 자료 상호 간의 관계를 표현한 내용
  - 어떠한 상황에 적절한 결정이나 판단에 쓸 수 있는 형태로 가공되거나 분류되기 위해 "처리 과정"을 거쳐서 정리되고 정돈된, 자료의 2차 처리 결과물

**예시(표)** — 문구점의 재고 자료를 처리해서 "구매예상 시기"라는 정보를 뽑아내는 예:

| | 재고 | 사용량 | 구매예상 시기 |
|---|---|---|---|
| 파란펜 | 120 | 80 | 2019-09-01 |
| 빨간펜 | 110 | 90 | 2019-09-01 |
| 파란연필 | 190 | 10 | 2019-08-01 |
| 빨간연필 | 90 | 110 | 2019-10-01 |
| **총합** | **510** | **290** | |

→ "재고"와 "사용량"은 단순한 자료(숫자)지만, 이를 계산·처리해서 나온 "구매예상 시기"는 의사결정에 바로 쓸 수 있는 정보다.

### 2. 추상화의 개념

**쉬운 비유**: 서울 지하철 노선도를 생각해보자. 실제 지하철역 사이의 정확한 거리나 방향은 지도와 다르지만, "환승 가능 여부"와 "역의 순서"라는 핵심 정보만 남겨서 누구나 쉽게 이해하도록 단순화한 것이 노선도다. 버스의 겉모습(창문, 문, 바퀴 위치 등 공통 특징)만 그려서 "버스"라는 개념을 표현하는 그림도 같은 원리다. 이렇게 **복잡한 실제 모습에서 핵심만 뽑아 단순하게 표현**하는 것이 추상화다.

- **추상화(Abstraction)**: 공통적인 개념을 이용하여 같은 종류의 다양한 객체를 정의하는 것. 추상화를 통해 간결하게 말하는 사람의 의사를 전달할 수 있게 된다.
- **자료의 추상화**: 물리적이며 전기적인 동작과는 무관하게, 자료를 생각하고 바라보는 사람의 상상
  - 예: "정수가 컴퓨터 내부에서 '0101'의 이진코드로 어떻게 저장될까"라는 의문 없이, 정수 그 자체를 머릿속의 그림처럼 떠올리는 것
  - 다양한 대상을 컴퓨터에서 저장하고 처리하기 위해 그 대상들의 의미와 구조에 대해서 공통의 특징만을 뽑아 정의한 것
  - 즉, 컴퓨터 내부의 이진수 표현 방법, 저장 위치 등은 포함되지 않고, 단순하게 개발자의 머릿속에 그림을 그리는 것처럼 개념화하여 개발자들 사이의 의사를 쉽게 전달하기 위해 사용되는 방법
- **자료의 추상화가 주는 효과**
  - 하드웨어 독립성: 불필요한 세부 요소를 제거함으로써 시스템의 복잡도를 줄이고, 개발자에게 본질적인 정보만 제공
  - 개발자의 접근성: 추상화된 개념을 통해 개발자는 실제 내부 구현에 상관없이 동일한 인터페이스로 소통함
  - 의사소통: 복잡한 데이터를 단순화함으로써 개발자의 가독성 및 소통 편의성 향상
  - 개발 효율성: 자료구조와 알고리즘 설계 시 복잡한 현실을 추상화하여 효율적인 구현이 가능하도록 도움

### 3. 자료구조와 알고리즘

**쉬운 비유**: "개발자"는 그림(추상화된 개념)으로 자료를 생각하지만, "컴퓨터"는 그 그림을 숫자(이진수)로 저장된 실제 메모리 주소로 다룬다. 즉 사람의 머릿속 그림(연결된 요일 이름들: 월→화→수…)과 컴퓨터 메모리 속 실제 주소/값(17번지엔 "목"이 적혀있고 124번지를 가리킴 …)은 서로 다른 표현이지만, "자료구조"가 이 둘을 이어주는 다리 역할을 한다.

```
개발자 ──(추상화)──▶ 자료구조 ◀──(구체화)── 컴퓨터
```

- **자료구조의 두 가지 측면**
  - 개발자: 자료의 의미, 구조, 처리 목적을 고려하여 프로그램 개발
  - 컴퓨터: 입력된 데이터를 이진수로 해석하고, 처리와 저장에 대한 자료의 단순 처리 수행
  - 추상화된 자료구조: 개발자와 컴퓨터 사이의 사고방식을 연결하며 효율적인 구현을 돕는 방법
- **자료구조의 정의**: 추상화를 통해 알고리즘에서 사용할 자료의 논리적 관계를 구조화한 것
  - 자료의 추상화와 구조화가 적절히 이루어지지 못하면 소프트웨어는 비효율적으로 수행되거나 소프트웨어의 확장성에 문제가 생길 수 있다.
- **알고리즘의 정의**: 컴퓨터에게 일을 시키기 위한 (추상화된) 명령어의 연속된 덩어리
  - 사람(개발자)이 컴퓨터에게 일을 시키기 위한 사람의 의도와 명령을 전달해 줄 수 있는 방법(언어/글)
  - 컴퓨터가 수행할 명령어의 유한 집합이 사람의 머릿속에 추상화되어 존재하는 것
  - 컴퓨터에게 시킬 일(프로그램)을 머릿속에서 추상화시켜서 대략적으로 상상해 놓은 것
- **자료구조와 알고리즘의 관계**: 자료구조는 입력 자료에 대한 추상화된 상태이고, 알고리즘은 컴퓨터가 수행해야 할 명령의 추상화다.

  (순서도 예시, 슬라이드 그림 재현)
  ```
  시작
   │
  학교 갈 준비 ──(판단 다이아몬드)
   │
  학교
   │
  컴퓨터 학원
   │
  피아노 학원
   │
  끝
  ```
  → 이런 순서도처럼 "할 일의 순서"를 추상화해서 정의한 것이 알고리즘이다.

- **자료구조/알고리즘의 추상화 ↔ 구체화 관계**
  - 입력값을 머릿속에서 추상화된 형태(자료구조)로 구조화하고, 수행되어야 할 명령어를 머릿속에서 추상화된 형태(알고리즘)로 체계화함
  - → **프로그래밍 언어**는 자료구조와 알고리즘을 구체화(실제 코드로 구현)하는 방법이다.
  ```
  자료구조 ──▶ 입력값 ──▶ 컴퓨터 ──▶ 출력
                            ▲
                          프로그램
                            ▲
                          알고리즘
  ```

- **추상 자료형(ADT)**: 자료구조와 알고리즘의 중간쯤에 있는, 자료의 복잡한 논리적 성격을 정의하는 형식. 자료값의 집합과 연산 집합에 대한 정의로 구성되며, 자료구조를 표현하는 가장 대표적인 방법이다.

  슬라이드의 의사코드(ADT 명세) 예시, 그대로 재현:
  ```
  ADT Array
    • 배열 객체: <i∈Index, e∈Element> 쌍들의 집합이며, Index는 순서를
      나타내는 정수값이고 Element는 같은 자료형의 원소값
    • 연산: a∈Array; i∈Index; x, item∈Element; n∈Integer인 모든
      a, item, n에 대하여 다음과 같은 연산이 정의된다
      (a는 0개 이상의 원소를 갖는 배열, item은 배열에 저장되는 원소,
       n은 배열의 최대 크기를 정의하는 정수값).
      ① Array create(n) ::= 배열의 크기가 n인 빈 배열을 생성하고
             공백 배열을 반환한다;
      ② Element retrieve(a, i) ::= if (i∈Index)
             then { 배열의 i 번째에 해당하는 원소값 'e'를 반환한다; }
             else { 에러 메시지를 반환한다; }
      ③ Array store(a, i, e) ::= if (i∈Index)
             then { 배열 a의 i 번째 위치에 원소값 'e'를 저장하고
                    배열 a를 반환한다; }
             else { 인덱스 i가 배열 a의 크기를 벗어나면
                    에러 메시지를 반환한다; }
  End Array
  ```

- **추상화와 추상 자료형의 차이**
  - 추상화: 그림이나 수식과 같이 의미를 표현하고 전달하는 방법 (일반적인 개념)
  - 추상 자료형: 전산학에서 사용되는, 자료구조를 표현하는(공통의 의미를 추출하여 전달하는) 방법 (ADT라는 구체적 형식)

- **전체 흐름 정리**: 추상화 → 자료의 추상화 → 추상 자료형 → 자료구조 → 알고리즘
  - 추상화: 공통적인 개념을 이용하여 같은 종류의 다양한 객체를 정의하는 것
  - 자료의 추상화: 컴퓨터에서 저장·처리하기 위한 대상들의 의미와 구조에 대해서 공통의 특징만을 뽑아 정의한 것
  - 추상 자료형: 자료의 복잡한 논리적 성격을 정의하는 형식
  - 자료구조: 추상화를 통해 알고리즘에서 사용할 자료의 논리적 관계를 구조화한 것
  - 알고리즘: 컴퓨터에게 일을 시키기 위한 (추상화된) 명령어의 연속된 덩어리

- **자료구조의 분류(그림)**
  ```
                         자료구조
                      /            \
             미리 정의된 자료구조      개발자 정의 자료구조
              /          \                    |
        기본 자료구조   파생된 자료구조    (리스트, 스택, 큐,
        정수/실수/문자   배열/구조체/포인터   트리, 그래프)
  ```
  - 미리 정의된 자료구조: 언어가 기본적으로 제공 (정수, 실수, 문자 / 배열, 구조체, 포인터)
  - 개발자 정의 자료구조: 개발자가 필요에 따라 직접 설계 (리스트, 스택, 큐, 트리, 그래프)

### 4. 알고리즘의 개념과 조건

**쉬운 비유**: 알고리즘은 "요리 레시피"와 같다. 레시피에는 재료(입력), 조리 순서(명확한 명령), 그리고 반드시 완성되는 요리(출력)가 있어야 하고, 각 단계는 애매하지 않고(명확성), 끝이 있어야(유한성) 한다.

- **알고리즘**: 컴퓨터에게 일을 시키기 위한 (추상화된) 명령어의 연속된 덩어리
- **알고리즘의 5가지 조건**
  - **출력(Output)**: 알고리즘을 수행하고 나면 적어도 한 가지 이상의 결과(변화)를 생성해야 함
  - **유효성(Effectiveness)**: 반드시 실행 가능해야 함
  - **입력(Input)**: 외부/내부 입력값은 유한해야 하며, 반드시 입력 형태가 정의될 수 있어야 함
  - **명확성(Definiteness)**: 각 명령들은 명확하고 애매모호하지 않아야 함
  - **유한성(Finiteness)**: 반드시 종료가 명확하게 정의되어 있어야 함

### 5. 알고리즘의 성능

**쉬운 비유**: 같은 목적지를 가는 두 가지 길이 있을 때, "시간이 얼마나 걸리는지(시간 복잡도)"와 "짐을 얼마나 들고 가야 하는지(공간 복잡도)"를 비교해서 더 나은 길을 고르는 것과 비슷하다.

- **시간 복잡도(Time Complexity)**: 알고리즘을 실행하는 데 필요한 예측 실행시간을 추정하여 알고리즘의 성능을 분석함
  - 실행 시간의 예측: 알고리즘의 실행 횟수를 O(n)이라고 표현
  - 같은 O(n)을 가진다고 해서 같은 실행 시간을 갖는 것이 아니라, 실행 시간의 유사한 증가 경향에 대한 표현 방법일 뿐이다.
- **공간 복잡도(Space Complexity)**: 알고리즘을 실행하는 데 필요한 공간(메모리)을 추정하여 알고리즘의 성능을 분석함
  - 공간 복잡도는 프로그램을 실행시켜서 완료하는 데 필요한 총 메모리 공간
  - **고정 메모리 공간(Sc)**: 프로그램의 크기나 입출력의 횟수에 관계없이 컴파일 시에 결정되어, 프로그램의 실행이 끝날 때까지 고정적으로 필요한 메모리 공간
  - **가변 메모리 공간(Se)**: 프로그램의 실행 과정에서 동적으로 할당되어야 하는 자료 구조와 변수들을 위해 필요한 메모리 공간
  - 공식: `Sp = Sc + Se` (공간복잡도 = 고정 메모리 공간 + 가변 메모리 공간)
- **알고리즘의 성능 측정(실측)**: 컴퓨터가 실제로 프로그램을 실행하는 데 걸리는 시간을 측정하여 알고리즘의 성능을 측정함
  - 실행 시간의 측정은 실제로 실행 시간을 시계로 잰다는 의미
  - 실제로 실행될 수 있는 프로그램(실행 파일)이 있어야 함
  - 시스템 시계를 이용함

### 정리하기 (강의 마지막 요약 슬라이드)

- **자료**: 현실 세계에서 관찰이나 측정을 통해서 수집된 값(value)이나 사실(fact)
- **정보**: 어떤 상황에 대해서 적절한 의사결정을 할 수 있게 하는 지식이며, 자료의 유효한 해석이나 자료 상호 간의 관계 (정보는 자료를 처리해서 얻어진 결과)
- **알고리즘**: 컴퓨터가 특정한 일을 수행하는 명령어들의 유한집합
- **자료형**: 자료가 기억될 기억장소의 유형, 즉 정수형, 실수형 등
- **추상 자료형**: 자료의 복잡한 논리적 성격을 정의하는 형식으로, 자료값의 집합과 연산 집합에 대한 명세의 집합

## 기억해야 할 키워드

- **자료(Data)**: 현실 세계에서 관찰·측정으로 수집된 값이나 사실. 아직 가공되지 않은 날것의 값.
- **정보(Information)**: 자료를 처리(가공)해서 얻은, 의사결정에 쓸 수 있는 결과물. `I = P(D)`.
- **추상화(Abstraction)**: 공통 개념만 뽑아서 같은 종류의 다양한 대상을 하나로 정의하는 것.
- **자료의 추상화**: 내부 저장 방식(이진수 등)은 신경 쓰지 않고 자료를 머릿속 그림처럼 개념화하는 것.
- **추상 자료형(ADT, Abstract Data Type)**: 자료값의 집합 + 연산 집합으로 자료의 논리적 성격을 정의하는 명세(형식).
- **자료구조(Data Structure)**: 추상화를 통해 알고리즘에서 쓸 자료들의 논리적 관계를 구조화한 것.
- **알고리즘(Algorithm)**: 컴퓨터에게 일을 시키기 위한, 추상화된 명령어의 유한한 연속 덩어리.
- **알고리즘의 5가지 조건**: 출력, 유효성, 입력, 명확성, 유한성.
- **시간 복잡도(Time Complexity)**: 알고리즘 실행에 필요한 예측 실행시간, O(n)으로 표현 (증가 경향의 표현).
- **공간 복잡도(Space Complexity)**: 알고리즘 실행에 필요한 총 메모리 공간. `Sp = Sc + Se`.
- **고정 메모리 공간(Sc)**: 컴파일 시 결정되어 실행 내내 고정적으로 필요한 메모리.
- **가변 메모리 공간(Se)**: 실행 중 동적으로 할당되는, 자료구조·변수를 위한 메모리.
- **미리 정의된 자료구조 / 개발자 정의 자료구조**: 언어가 기본 제공하는 자료구조(정수·배열 등) vs 개발자가 직접 설계하는 자료구조(리스트·스택·큐·트리·그래프 등).
