# 07강 — 트리

## 핵심 요약

- **트리(tree)**는 데이터들이 "부모-자식" 관계로 위아래 계층을 이루며 연결된 자료구조이다. 가계도나 회사 조직도를 떠올리면 된다.
- 트리를 이루는 하나하나의 항목을 **노드(node)**, 맨 꼭대기에서 부모가 없는 노드를 **루트(root)**, 맨 아래에서 자식이 없는 노드를 **잎 노드(leaf)**라고 부른다.
- 노드는 **진입 차수(들어오는 선의 개수)**와 **진출 차수(나가는 선의 개수)**로 구분하며, 루트는 진입 차수 0, 잎 노드는 진출 차수 0이다.
- 노드의 **레벨**은 루트부터 그 노드까지 이어진 경로의 길이이고, 트리의 **깊이**는 레벨 중 가장 큰 값 + 1이다.
- 모든 노드가 자식을 **2개 이하**만 갖도록 제한한 트리가 **이진 트리(binary tree)**이며, 수학적으로 다루기 쉽고 컴퓨터로 구현하기도 효율적이라 가장 널리 쓰인다.
- 이진 트리는 **배열**(인덱스 계산으로 부모/자식 위치 찾기) 또는 **포인터(연결 리스트 방식)**로 구현할 수 있다.
- 이진 트리를 빠짐없이 한 번씩 방문하는 방법을 **순회(traverse)**라고 하며, 방문 순서에 따라 **전위(PLR)·중위(LPR)·후위(LRP)** 세 가지로 나뉜다.
- 자식이 여러 개인 **일반 트리**도 "첫째 자식-다음 형제" 방식으로 규칙을 적용하면 항상 이진 트리로 바꿀 수 있다.

## 상세 내용

### 1. 트리의 개념

**비유**: "모차르트, 바흐, 베토벤, 세잔, 피카소, 아인슈타인, 뉴턴"이라는 사람들을 생각해보자. 이들은 모두 "직업"이라는 큰 분류 아래, "예술가"와 "학자"로 나뉘고, 예술가는 다시 "음악가"와 "화가"로, 학자는 "과학자"로 나뉜다. 이렇게 큰 분류에서 점점 작은 분류로 뻗어나가는 모양이 바로 트리다.

```
"직업"
 ├─ "예술가"
 │   ├─ "음악가" ─ 모차르트, 바흐, 베토벤
 │   └─ "화가"   ─ 세잔, 피카소
 └─ "학자"
     └─ "과학자" ─ 아인슈타인, 뉴턴
```

트리의 특징(슬라이드에 제시된 순서):
- **검색의 편리함**: 분류를 따라가면 원하는 데이터를 빠르게 찾을 수 있다.
- **논리적 계층**: 위아래 관계가 명확하다.
- **계급적 특성**: 상위 항목이 하위 항목을 포함(관리)하는 구조다.

(참고, 교재 외 내용) 스택과 큐는 데이터가 일렬로만 늘어서기 때문에 배열로 구현하는 경우가 많고, 리스트는 중간 삽입/삭제가 잦아 포인터(연결 리스트)로 구현하는 경우가 많다. 트리는 이 둘의 중간적 성격을 가지므로, 상황에 따라 배열과 포인터 중 어느 쪽으로 구현할지 선택하게 된다 (4절에서 두 방식 모두 다룸).

### 2. 트리의 표현 방법

**트리의 구성 요소**
- **노드(node)**: 트리의 항목, 즉 데이터의 묶음. 위 예시에서 "음악가", "모차르트" 같은 각 네모 칸 하나하나.
- **부모 노드-자식 노드 관계**: 직접 연결된 두 노드 중 위쪽을 부모, 아래쪽을 자식이라 한다. 상하 계층 관계(구조)를 가진다.
- **루트 노드(root)**: 트리의 최상위 노드. 부모가 없는 노드. (예: "직업")
- **서브트리(subtree)**: 부모 노드를 삭제하면 생기는 트리들. 즉 하나의 노드를 루트로 보면 그 아래가 통째로 하나의 작은 트리가 된다.
- **잎 노드(leaf)**: 트리의 맨 끝(바닥)에 있으면서 자신의 서브트리(자식)를 갖지 않는 노드.

예시 트리 (J를 루트로 하는 트리, 아래 내용 전체에서 계속 재사용됨):

```
            J
         /     \
        A       Sh
       / \        \
      M   P        Sc
     /|   |\       / \
   aM V   C Pi    E   N
```

**진입/진출 차수**
- 루트 노드 : 진입 차수 = 0 (들어오는 화살표가 없음)
- 루트를 제외한 모든 노드 : 진입 차수 = 1 (부모로부터 선 하나만 들어옴)
- 잎 노드 : 진출 차수 = 0 (더 이상 나가는 선이 없음)

**내부 노드와 형제**
- **내부 노드(internal node)**: 루트도 아니고 잎(잎 노드)도 아닌 노드. 위 트리에서 A, Sh, M, P, Sc.
- **형제(sibling)**: 같은 부모를 갖는 노드들. 예: A와 Sh는 형제, M과 P는 형제.

**트리의 레벨과 깊이**
- 노드의 **레벨**: 루트로부터 그 노드까지 이어진 선(경로)의 길이.
  - 레벨 0 : J
  - 레벨 1 : A, Sh
  - 레벨 2 : M, P, Sc
  - 레벨 3 : aM, V, C, Pi, E, N
- **트리의 깊이**: 트리의 레벨 중 가장 큰 값에 1을 더한 것. 위 예시는 최대 레벨이 3이므로 깊이는 4.

**트리의 다른 표현 방식**
같은 트리라도 여러 가지 모습으로 그릴 수 있다. 슬라이드에서는 가지를 자유롭게 구부려 그려도(J-A-Sh-M-P-Sc-E-N 관계만 같다면) 같은 트리임을 보여준다. 또한 트리는 다음과 같이도 표현 가능하다:
- **중첩된 집합(벤 다이어그램)**: 큰 원 안에 작은 원들이 포함되는 식으로 계층을 표현.
- **들여쓰기 표현**: 파일 탐색기의 폴더 구조처럼, 들여쓰기 정도로 계층을 표현.

```
J ----------------
  A -----------
    M ---------
      aM ---
      B  ----   (※ 슬라이드 예시 그림의 라벨, 본문 트리의 V에 해당)
      V  ----
    P ---------
      C  ----
      Pi ----
  Sh ----------
    Sc -------
      E  ----
      N  ----
```

### 3. 추상 자료형 (ADT)

**추상 자료형(ADT)**이란: 자료구조를 "어떤 데이터를 담고 있는가"와 "어떤 연산을 할 수 있는가"만으로 정의하고, 내부적으로 어떻게 구현되는지는 숨기는 설계 방식이다. 마치 자동차를 운전할 때 엔진 내부 구조를 몰라도 핸들, 페달 사용법만 알면 운전할 수 있는 것과 비슷하다.

- **트리 객체**: 루트 노드를 갖는 유한 리스트로 정의.
- **큐 객체**: 0개 이상의 원소를 갖는 유한 순서 리스트.
- **스택 객체**: 0개 이상의 원소를 갖는 유한 순서 리스트.

**트리의 추상 자료형 연산 목록** (슬라이드 그대로):

| 번호 | 연산 | 설명 |
|---|---|---|
| ① | `Tree Create()` | 트리를 생성하고 루트 노드를 가리키는 포인터를 반환 |
| ② | `Destroy(Tree)` | 더 이상 사용하지 않는 트리의 기억 장소를 시스템에 반환 |
| ③ | `Tree Copy_Tree(Tree)` | 트리를 복사하고 새로 생성한 트리의 루트 노드 포인터를 반환 |
| ④ | `Insert(n)` | 트리에 노드 n을 삽입 |
| ⑤ | `Delete()` | 트리에서 노드를 삭제 (보통 재구성 단계 포함) |
| ⑥ | `Search()` | 특정 키값을 갖는 노드를 찾음 (찾으면 true, 못 찾으면 false) |
| ⑦ | `Traverse()` | 트리를 순회하고 방문 순서대로 값을 반환 |
| ⑧ | `Root()` | 루트 노드 값을 반환 |
| ⑨ | `Parent(n)` | 노드 n의 부모(값 또는 포인터)를 반환, n이 루트이면 오류 |
| ⑩ | `Children(n)` | 노드 n의 자식(값 또는 포인터)를 반환, n이 잎이면 오류 |
| ⑪ | `IsRoot(n)` | 노드 n이 루트이면 true, 아니면 false |
| ⑫ | `IsInternal(n)` | 노드 n이 내부 노드이면 true, 아니면 false |
| ⑬ | `IsLeaf(n)` | 노드 n이 잎이면 true, 아니면 false |
| ⑭ | `IsEmpty()` | 트리가 비었으면 true, 아니면 false |
| ⑮ | `Replace(n, m)` | 노드 n을 노드 m으로 바꿈 |

### 4. 이진 트리

**이진 트리의 정의**: 모든 노드의 차수(자식 수)가 2 이하인 트리. 수학적으로 이진 트리의 구성에 관한 이론을 정리하기 쉽고, 컴퓨터 내부에서 구현하기도 효율적이다. 모든 노드가 2개 이하의 자식 노드를 가지므로 일반성을 잃지 않고 '왼쪽', '오른쪽'이라는 방향 개념을 부여할 수 있으며, 오른쪽 노드와 왼쪽 노드 사이에 개념적(의미적) 관계를 둘 수도 있다.

예시: 앞서 본 J 트리에서 M의 자식이 aM, V, B 세 개(3개)였다면 이진 트리 조건을 어기므로, aM과 B를 한 그룹으로 묶는 등 자식이 2개를 넘지 않도록 조정한다.

**가득 찬(포화) 이진 트리**: 이진 트리의 각 레벨에서 허용되는 최대 개수의 노드를 가지는 트리. 레벨 k에는 최대 2^k개의 노드가 올 수 있다 (레벨 0엔 1개, 레벨 1엔 2개, 레벨 2엔 4개...).

**완전 이진 트리**: 높이가 k인 이진 트리가 '0 레벨'부터 'k-2 레벨'까지 다 채우고, 마지막 'k-1 레벨'에서 왼쪽부터 오른쪽으로 노드들이 차례로 채워진 이진 트리. (포화 이진 트리는 완전 이진 트리의 특수한 경우다.)

**배열을 이용한 이진 트리 구현**

완전 이진 트리나 포화 이진 트리라면 배열 인덱스 계산만으로 부모/자식 위치를 알 수 있어 낭비되는 공간이 없이 효율적이다.

```
인덱스(1부터 시작 기준):   1   2   4        8
배열 칸:                 [1] [2][3] [4][5][6][7]
트리:  A(1), B(2), C(3), D(4), E(5), F(6), G(7), H(8), I(9), J(10), K(11)
```

예시로 J 트리를 배열에 넣으면:

| 인덱스 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---|---|---|---|---|---|---|---|
| 값 | J | A | Sh | M | P | - | Sc | - |

하지만 트리가 한쪽으로 치우쳐(편향되어) 깊어질수록 기억장소 낭비가 **2의 거듭제곱**에 비례해 심해진다. 예를 들어 J-A-M-aM처럼 한 줄로 늘어선 트리를 배열에 넣으면 대부분의 칸이 빈 채로 낭비된다.

**포인터(연결 리스트)를 이용한 이진 트리 구현**

각 노드를 왼쪽 자식 포인터(`*left`), 데이터(`data`), 오른쪽 자식 포인터(`*right`) 세 부분으로 구성한다.

```c
typedef struct node {
    struct node *left;
    char data;
    struct node *right;
} node;
```

노드 구조를 그림으로 보면:

```
| *left | data | *right |
| 주소값 | 원소값 | 주소값 |
```

이 방식은 빈 칸 낭비 없이, 실제로 존재하는 노드 개수만큼만 메모리를 사용한다(필요할 때마다 malloc으로 생성).

### 5. 이진 트리 연산

**이진 트리의 순회(traverse)**: 이진 트리의 각 노드를 빠짐없이, 그리고 중복 없이 한 번씩 방문하는 것. 순회는 세 가지 "할 일"의 순서를 어떻게 정하느냐로 나뉜다.

- 루트 방문(P, Parent/Root)
- 왼쪽 서브트리 순회(L)
- 오른쪽 서브트리 순회(R)

**세 가지 순회 방식**

| 이름 | 순서 | 설명 |
|---|---|---|
| 전위 순회 (PLR, Preorder) | P → S_L → S_R | 루트를 먼저 방문하고, 왼쪽 서브트리를 전위 순회, 오른쪽 서브트리를 전위 순회 |
| 중위 순회 (LPR, Inorder) | S_L → P → S_R | 왼쪽 서브트리를 먼저 중위 순회하고, 루트를 방문, 오른쪽 서브트리를 중위 순회 |
| 후위 순회 (LRP, Postorder) | S_L → S_R → P | 왼쪽 서브트리를 먼저 후위 순회하고, 오른쪽 서브트리를 후위 순회, 마지막에 루트 방문 |

비유: "할 일 목록을 처리하는 순서"라고 생각하면 쉽다. 전위 순회는 "내가 먼저 하고, 왼쪽 팀에게 맡기고, 오른쪽 팀에게 맡긴다"이고, 후위 순회는 "왼쪽 팀이 다 끝내고, 오른쪽 팀이 다 끝낸 다음에야 내가 마지막으로 처리한다"는 식이다.

**순회 알고리즘 (의사코드/C 코드)**

전위 순회(PLR):
```c
void preorder(node* root) {
  if (root != NULL) {
    printf("%c", root -> data);
    preorder(root -> left);
    preorder(root -> right);
  }
}
```

중위 순회(LPR):
```c
void inorder(node* root) {
  if (root != NULL) {
    inorder(root -> left);
    printf("%c", root -> data);
    inorder(root -> right);
  }
}
```

후위 순회(LRP):
```c
void postorder(node* root) {
  if (root != NULL) {
    postorder(root -> left);
    postorder(root -> right);
    printf("%c", root -> data);
  }
}
```

**이진 트리의 삽입**

새로운 노드(X)를 삽입하면 기존 노드들의 연결이 끊어지지 않도록, 빈 자리(NULL인 자리)를 찾아 그 자리에 새 노드를 연결한다. 이미 노드가 있던 자리에 새 노드(Z)를 끼워 넣으면, 기존에 있던 자식(X, Y 등)은 새 노드의 자식으로 다시 연결된다 (슬라이드의 X→Y→Z 삽입 예시 참고).

일반적으로 이진 트리를 생성하는 것은 **연결 리스트 연산**을 사용한다. 첫 노드를 생성하면 루트 노드가 되고, 새로운 노드를 추가하려면 연결 리스트의 삽입 연산을 사용한다.

```c
// 리스트의 노드/헤드 구조 (참고용)
typedef struct ListNode {
    int data;
    struct ListNode* link;
} listNode;

typedef struct {
    listNode* head;
} linkdedList_h;

// 새 노드 생성 예
NewNode = (listNode*)malloc(sizeof(listNode));
```

이진 트리의 노드 삽입 코드:
```c
node *insert(node *here, node *it) {
  if (here == NULL) {
     here = it;
     return NULL;
  }
  else {
    node* victim;
    victim = here;
    *here = *it;
    return victim;
  }
}
```

**이진 트리의 삭제**

- 삭제하려는 노드가 **잎 노드**인 경우: 그 노드를 가리키는 포인터를 NULL로 지정하면 끝.
- 삭제하려는 노드가 **잎 노드가 아닌 경우**: 그 노드의 자식 노드들도 함께 처리(재배치)해주어야 한다.

이진 트리의 노드 삭제 코드:
```c
node *delete(node *root, node *it, char direction) {
  node *parent = searchParent(root, it);
  if (parent == NULL) {
    printf("삭제 불가!\n");
    return NULL;
  }
  else {
    if (direction == 'l') {
      free(parent -> left);
      parent -> left = NULL;
      return it;
    }
    else if (direction == 'r') {
      free(parent -> right);
      parent -> right = NULL;
      return it;
    }
    else return NULL;
  }
}
```

**노드 개수 세는 연산** (재귀로 왼쪽/오른쪽 서브트리 개수를 더한 뒤 자기 자신 1을 더함):
```c
int get_nodeNum(node *root) {
  int num = 0;
  if (root == NULL) {
    return 0;
  }
  else {
    num = 1;
    num += (get_nodeNum(root -> left) + get_nodeNum(root -> right));
    return num;
  }
}
```

**잎 노드 개수 세는 연산** (자식이 둘 다 없으면 잎이므로 1을 세고, 그 외엔 재귀로 더해감):
```c
int get_leafNum(node *root) {
  int result = 0;
  if (root == NULL) {
    return 0;
  }
  else if (root -> left == NULL && root -> right == NULL) {
    return 1;
  }
  result += (get_leafNum(root -> left) + get_leafNum(root -> right));
  return result;
}
```

### 6. 일반 트리를 이진 트리로 변환

자식이 3개 이상일 수 있는 **일반 트리**도 다음 규칙으로 항상 이진 트리로 바꿀 수 있다:

1. 일반 트리에 대하여 각 노드의 **형제들을 (가로선으로) 연결**한다.
2. 각 노드에 대하여 **가장 왼쪽 링크(첫째 자식으로 가는 선)만 남기고 나머지(부모→둘째 자식 이후, 형제가 아닌 세로선)는 모두 제거**한다.
3. 루트 노드는 반드시 **왼쪽 자식 노드 하나만** 갖도록 전체 그림을 시계 방향으로 45도 정도 회전시켜 정리한다.

예시 (숫자는 원래 트리에서의 형제 순서):

```
원래 트리:        형제 연결 후:        정리(45도 회전) 후:
   1                  1                    1
 / | \              / x x \                \
2  3  4            2-3-4                    2
                                              \
                                               3
                                                \
                                                 4
```

더 복잡한 예시(1의 자식 2,3,4 / 3의 자식 5 / 5의 자식 6,7 / 7의 자식 8):

```
원래 트리 → 형제 연결(가로선 추가, 세로선 중 가장 왼쪽만 남기고 X 표시로 제거) → 최종 이진 트리
```

변환 규칙은 결국 "**첫째 자식은 왼쪽 자식으로, 바로 다음 형제는 오른쪽 자식으로**" 라는 한 문장으로 요약된다. 이 방법 덕분에, 자식이 몇 개든 상관없이 모든 일반 트리를 이진 트리 하나로 표현할 수 있고, 이것이 **왜 이진 트리를 가장 많이 사용하는지**에 대한 답이 된다 (이진 트리로 표현하면 포인터 구조가 `*left`, `*right` 단 두 개로 통일되어 구현이 단순해지고 효율적이기 때문).

## 기억해야 할 키워드

- **트리(tree)**: 논리적 계층이 있는 구조이며, 트리를 구성하는 항목을 노드(node) 혹은 정점(vertex)이라고 함
- **노드(node)**: 트리에 저장되는 데이터의 묶음
- **루트(root)**: 트리에서 부모를 갖지 않는 최상위 노드
- **서브트리(subtree)**: 부모 노드를 삭제하면 생기는 트리들
- **잎 노드(leaf)**: 자신의 서브트리를 갖지 않는 맨 끝 노드
- **내부 노드(internal node)**: 루트도 잎도 아닌 노드
- **형제(sibling)**: 같은 부모를 갖는 노드들
- **진입 차수**: 어떤 노드로 들어오는 선의 개수 (루트는 항상 0)
- **진출 차수**: 어떤 노드에서 나가는 선의 개수 (잎 노드는 항상 0)
- **레벨(level)**: 루트로부터 그 노드까지 이어진 경로의 길이
- **깊이(depth)**: 트리의 레벨 중 가장 큰 값 + 1
- **이진 트리(binary tree)**: 모든 노드의 차수가 2 이하인 트리
- **가득 찬(포화) 이진 트리**: 각 레벨에서 허용하는 최대 개수의 노드를 가진 이진 트리
- **완전 이진 트리**: 마지막 레벨을 제외하고 모두 채워지고, 마지막 레벨은 왼쪽부터 채워진 이진 트리
- **순회(traverse)**: 트리의 각 노드를 빠짐없이 한 번씩만 방문하는 것
- **전위 순회(PLR/Preorder)**: 루트 → 왼쪽 → 오른쪽
- **중위 순회(LPR/Inorder)**: 왼쪽 → 루트 → 오른쪽
- **후위 순회(LRP/Postorder)**: 왼쪽 → 오른쪽 → 루트
- **추상 자료형(ADT)**: 데이터와 연산만 정의하고 내부 구현은 감추는 설계 방식
- **일반 트리 → 이진 트리 변환**: 첫째 자식은 왼쪽 자식으로, 다음 형제는 오른쪽 자식으로 연결하는 규칙
