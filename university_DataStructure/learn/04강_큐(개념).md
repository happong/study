# 04강 — 큐

## 핵심 요약

- 큐(Queue)는 한쪽(뒤, rear)에서만 넣고 다른 한쪽(앞, front)에서만 꺼낼 수 있는, **양쪽이 모두 터진 관** 같은 자료구조다.
- 큐는 **선입선출(FIFO, First-In-First-Out)** 또는 **선착순 서비스(FCFS, First-Come-First-Serve)** 원칙을 따른다. 먼저 들어온 것이 먼저 나간다.
- 삽입 연산은 rear 쪽에서, 삭제 연산은 front 쪽에서 일어난다. 삽입은 "서비스를 받기 위한 기다림", 삭제는 "서비스를 받는 중"에 비유된다.
- 큐의 추상 자료형(ADT)은 Add_q(삽입), Delete_q(삭제), IsEmpty_q(비었는지 검사), IsFull_q(가득 찼는지 검사) 연산으로 정의된다.
- 배열로 큐를 구현하면 front와 rear가 계속 오른쪽으로만 이동하기 때문에, 원소 개수가 배열 크기보다 적어도 배열 공간이 꽉 찬 것처럼 보이는 문제(거짓 포화 상태)가 생긴다.
- 이 문제를 해결하기 위해 배열의 끝과 처음을 연결한 **원형 큐(circular queue)**가 사용되며, 인덱스 계산에 나머지 연산자(%)를 활용한다.
- 큐는 CPU 작업 스케줄링(FCFS, Round Robin)이나 너비 우선 탐색(BFS) 같은 실무/알고리즘 분야에서 널리 쓰인다.

## 상세 내용

### 1. 큐의 개념

**비유로 이해하기**
- 생수 디스펜서의 종이컵 뭉치: 아래에서 하나씩 채워 넣고(삽입), 맨 아래 컵을 뽑아 쓴다(삭제) — 이건 사실 스택과 비교하기 위한 그림이고, 큐는 "버스 정류장에 줄 선 사람들"처럼 한쪽 끝에서 들어와서 반대쪽 끝에서 나가는 구조다.
- 스택(책 쌓기, 양쪽 모두가 아니라 한쪽에서만 넣고 빼는 구조)과 대비되는 개념으로 먼저 소개된다: 스택은 "나중에 넣은 것이 먼저 나가는(LIFO)" 구조이고, 큐는 그 반대다.

**큐의 의미(First-In-First-Service)** — 슬라이드 예시:
- 택시를 타기 위해 서 있는 행렬
- 병원의 접수대
- 은행의 예금 인출기
- 백화점의 계산대 위에 놓인 상품들
- 작업 큐에 들어간 작업이 가장 처음에 처리되는 작업 스케줄

**정확한 정의**
- 큐: 한쪽에서는 **삽입 연산만** 발생 가능하고, 다른 한쪽에서는 **삭제 연산만** 발생 가능한, **양쪽이 모두 터진 관**과 같은 자료구조
- 삽입 연산: 서비스를 받기 위한 기다림
- 삭제 연산: 서비스를 받는 중
- 선입선출(FIFO) 또는 선착순 서비스(FCFS) 알고리즘과 함께 사용됨

**큐의 정의 (배열로 표현한 그림)**

```
0    1    2    3    4
    [A]  [B]  [C]
     ↑              ↑
   front           rear

삽입(add) 후:
0    1    2    3    4
    [A]  [B]  [C]  [D] ← 삽입(add)
     ↑              ↑
   front           rear

삭제(delete) 후:
0    1    2    3    4
    [A]  [B]  [C]  [D]
     ↑              ↑
   front           rear
→ 삭제(delete)
0    1    2    3    4
    [B]  [C]  [D]
          ↑         ↑
        front     rear
```
- 삽입은 rear 쪽(오른쪽 끝)에서, 삭제는 front 쪽(왼쪽, front가 가리키는 그 다음 칸)에서 일어난다는 것을 보여주는 그림이다.

### 2. 큐의 추상 자료형(ADT)

**쉬운 설명**: 추상 자료형이란 "이 자료구조가 무슨 기능(연산)을 제공하는지"만 약속으로 정해놓은 것. 실제 구현 방법(배열이든 연결리스트든)은 나중에 정해도 된다.

**큐의 객체 정의**
> 큐 객체: 0개 이상의 원소를 갖는 유한 순서 리스트
(스택의 객체 정의도 "0개 이상의 원소를 갖는 유한 순서 리스트"로 동일하게 표현됨 — 차이는 연산에서 난다.)

**큐의 연산 정의**
```
연산 : queue∈Queue, item∈element,
       maxQueueSize∈positive integer인 모든 queue, item,
       maxQueueSize에 대하여 다음과 같은 연산이 정의된다.
       (queue는 0개 이상의 원소를 갖는 큐,
        item은 큐에 삽입되는 원소,
        maxQueueSize는 큐의 최대 크기를 정의하는 정수).
```

**삽입(Add_q) 연산** — 의사코드
```
Queue Add_q(queue, item) ::=
  if (IsFull_q(queue))
     then { 'queueFull'을 출력한다; }
     else { 큐의 rear에서 item을 삽입하고,
            큐를 반환한다; }
```

**삭제(Delete_q) 연산** — 의사코드
```
Element Delete_q(queue) ::=
  if (IsEmpty_q(queue))
     then { 'queueEmpty'를 출력한다; }
     else { 큐의 front에 있는
            원소를 삭제하고 반환한다; }
```

**빈 큐 검사(IsEmpty_q) 연산**
```
Boolean IsEmpty_q(queue) ::=
  if (rear == front)
     then { 'TRUE' 값을 반환한다; }
     else { 'FALSE' 값을 반환한다; }
```

**만원 검사(IsFull_q) 연산**
```
Boolean IsFull_q(queue, maxQueueSize) ::=
  if ( (queue의 elements의 개수) == maxQueueSize )
     then { 'TRUE' 값을 반환한다; }
     else { 'FALSE' 값을 반환한다; }
```

**삽입/삭제 연산의 실행 예시** — 아래 순서를 차례로 수행하며 queue, front, rear가 어떻게 바뀌는지 보여준다.
```
① Create_q(4);
② Add_q(queue, 'A');
③ Add_q(queue, 'B');
④ Add_q(queue, 'C');
⑤ Delete_q(queue);
⑥ Delete_q(queue);
⑦ Delete_q(queue);
⑧ Add_q(queue, 'D');
```

| 단계 | 상태 | front | rear | queue 내용 |
|---|---|---|---|---|
| ① 초기 상태 | 빈 큐 | 가리키는 칸 없음(start) | 가리키는 칸 없음(start) | [ ][ ][ ][ ][ ] |
| ② Add_q A | 삽입 | front↓[0] | rear↓[0] | A | | | | |
| ③ Add_q B | 삽입 | [0] | rear↓[1] | A|B| | | |
| ④ Add_q C | 삽입 | [0] | rear↓[2] | A|B|C| | |
| ⑤ Delete_q | 삭제(A 제거) | front↓[1] | [2] | _|B|C| | |
| ⑥ Delete_q | 삭제(B 제거) | front↓[2] | [2] (front==rear) | _|_|C| | |
| ⑦ Delete_q | 삭제(C 제거) → **Queue empty** | front,rear 모두 [2]+1 지점 | 같음 | 모두 빈 칸 |
| ⑧ Add_q D | 삽입 | front | rear↓[3] | _|_|_|D| |

- 이 예시에서 중요한 점: 삭제가 계속 일어나면 front가 오른쪽으로 계속 밀려가고, 그 뒤에 삽입을 더 해도 rear만 오른쪽으로 이동한다. 즉 **front와 rear는 한 번 지나간 왼쪽 칸으로는 다시 돌아가지 않는다.** 이것이 다음 장(원형 큐)에서 나오는 문제의 원인이 된다.

### 3. 큐의 응용

**CPU의 관리 방법(운영체제에서 큐가 쓰이는 예)**

① **FCFS(First-Come First-Served) 스케줄링** (FIFO 스케줄링이라고도 함)
- 작업(프로그램)이 **준비 큐(Ready Queue)에 도착한 순서대로** CPU를 할당받고, 작업이 완료될 때까지 CPU를 사용하는 기법
```
준비 큐(Ready Queue)
[C] [B] [A]  ──────▶  [CPU]  ──완료──▶
```

② **RR(Round Robin) 스케줄링**
- 대화형 시스템에 적합하며, **일정 시간(time slice)만** CPU를 사용하는 스케줄링 방식
- 작업(프로그램)이 도착한 순서대로 CPU가 할당되지만, CPU의 **시간 할당량 또는 시간 간격**에 의해 제한을 받으며, 일정한 크기의 시간 할당량을 모든 작업에 주고 그 시간 동안 작업이 완료되지 못하면 **준비 큐의 맨 뒤에 다시 배치되는** 기법
```
준비 큐(Ready Queue)
[A] [C] [B] [A]  ──────▶  [CPU]  ──완료──▶
 ↑                           │
 └────────── 선점(되돌아옴) ──┘
```

③ **너비 우선 탐색(BFS) 알고리즘** (교재 외 내용으로 표시됨)
- 하나의 정점에서 방문하지 않은 인접한 정점들을 하나씩 선택하여 먼저 방문하는 방법
- 예시 그림: 정점 1을 중심으로 2, 3이 연결되고, 2에는 4·5, 3에는 5·6이 연결되고, 5와 6 밑에 7이 연결된 트리 형태의 그래프가 제시됨 (BFS는 이런 그래프를 가까운 정점부터 순서대로 방문할 때 큐를 이용한다는 취지의 예시).

### 4. 배열을 이용한 큐의 구현

**큐의 생성**
- 변수 rear의 초기값은 큐의 공백 상태를 나타내는 **'-1'**로 시작함
```c
#define QUEUE_SIZE 5
typedef int element;
element queue[QUEUE_SIZE];
    int front = -1;
    int rear = -1;
```

**큐의 초기 상태 예시** — 이미 100, 200, 300이 들어있는 상태
```
front        rear
 ↓            ↓
[0]  [1]  [2]  [3]  [4]
100  200  300
```
(이 그림에서 rear가 [2]를 가리키고 있다는 것은, 이미 3개(인덱스 0~2)가 채워져 있고 다음 삽입 위치가 [3]이라는 뜻)

**큐의 삽입 연산**
- 삽입 연산이 발생하면 **rear 변수만** 오른쪽으로 이동하고, 삭제 연산이 발생하면 **front 변수만** 오른쪽으로 이동함
```c
void Add_q(element item) {
    if (rear == QUEUE_SIZE-1)   {
        printf("Queue is full !!");
        return; }
    queue[++rear] = item;
    return;
}
```
- 실행 결과: 400을 삽입하면 rear가 [2]→[3]으로 이동하고 queue[3]에 400이 저장됨.

**큐의 삭제 연산**
- 삭제 연산의 수행 결과로 삭제된 원소를 Delete_q 연산자의 호출 프로그램에게 반환해 줌
```c
element Delete_q( ) {
    if (front == rear)  {
        printf("Queue is empty");
        return;   }
    return(queue[++front]);
}
```
- 실행 결과: Delete_q를 호출하면 front가 [0]→[1]로 이동하고, queue[1]의 값(200)이 반환됨. (100은 이미 그 전에 삭제된 상태로 가정한 그림)

### 5. 원형 큐

**배열 큐의 문제점**
- 배열로 구현한 큐의 경우, 큐에 들어있는 원소의 개수가 (배열 크기 - 1)이 아니더라도 큐가 가득 찬(full) 것처럼 보일 수 있음. front와 rear가 계속 오른쪽으로만 이동하다가 배열의 끝(마지막 인덱스)에 다다르면, 앞쪽에 빈 칸이 남아있어도 더 이상 삽입할 수 없게 되기 때문.

**해결책: 원형 큐**
- 배열의 문제점을 해결하기 위해 **원형 큐**가 제안됨
- 원형 큐는 **파이프의 입구와 출구 부분을 연결시킨 형태** — 즉, 배열의 마지막 인덱스 다음에 다시 처음(인덱스 0)으로 돌아가도록 **나머지 연산자(%)**를 이용해 순환 구조로 만든 것.
- 실생활 비유 그림: 일주일 요일이 적힌 둥근 약통(월~일이 원형으로 배치), 회전문(revolving door) — 양쪽 다 "끝까지 가면 다시 처음으로 돌아온다"는 원형 구조의 비유.

**원형 큐의 구조**

```
       0    1
        \  /
   4 ─ (원형 공간) ─ 2
        /  \
       3
```
(배열의 [0]~[4]를 둥글게 이어 붙인 모양. front, rear가 이 원을 따라 시계방향으로 이동함)

**원형 큐의 초기 상태(빈 상태)**
```
front, rear 모두 같은 위치(겹침)
[0] [1] [2] [3] [4]
```

**원형 큐의 삽입 연산 결과 (나머지 연산자 활용)**
- 배열이 꽉 찬 것처럼 보여도(rear가 배열 끝 [4]) 나머지 연산(rear+1) % QUEUE_SIZE로 다시 [0]으로 돌아가 계속 삽입할 수 있다.
```
예) front=[1], rear=[4]에 300,400,500이 들어있는 상태에서 600을 삽입
→ rear가 (4+1)%5 = 0 으로 이동 → queue[0] = 600
```

**원형 큐의 만원 상태**
- 원형 큐에서는 "모든 칸이 실제로 다 찬 것"과 "front==rear인 빈 상태"를 구분하기 위해, 보통 **배열 한 칸을 항상 비워두는 방식**(원소 개수가 QUEUE_SIZE-1이 되면 가득 찬 것으로 간주)을 사용한다. 슬라이드는 "교재 외 내용"으로 표시하며 이 부분이 애매할 수 있음을 "(?)" 물음표로 강조하고, front==rear가 되는 경우가 "완전히 가득 찬 경우"와 "완전히 빈 경우" 모두에서 똑같이 나타날 수 있다는 점(즉 둘을 구분하기 어려운 문제)을 여러 그림으로 보여준다.
- 원형 큐에서의 삭제 연산도 마찬가지로 나머지 연산을 이용해 front를 순환시킨다.

## 기억해야 할 키워드

- **큐(Queue)**: 한쪽(rear)에서만 삽입, 다른 한쪽(front)에서만 삭제가 일어나는 선형 자료구조
- **FIFO(First-In-First-Out)**: 먼저 들어온 원소가 먼저 나가는 원칙
- **FCFS(First-Come-First-Serve)**: 먼저 도착한 순서대로 서비스받는 원칙 (FIFO와 같은 맥락으로 설명됨)
- **front**: 큐에서 삭제가 일어나는 쪽(앞)
- **rear**: 큐에서 삽입이 일어나는 쪽(뒤)
- **Add_q**: 큐에 원소를 삽입하는 연산
- **Delete_q**: 큐에서 원소를 삭제하고 반환하는 연산
- **IsEmpty_q**: 큐가 비어있는지 검사(front==rear일 때 TRUE)
- **IsFull_q**: 큐가 가득 찼는지 검사
- **queueFull / queueEmpty**: 삽입/삭제가 불가능할 때 출력되는 메시지
- **원형 큐(circular queue)**: 배열의 끝과 처음을 논리적으로 연결하여, 배열 공간을 순환적으로 재사용하는 큐 구현 방식
- **나머지 연산자(%)**: 원형 큐에서 인덱스가 배열 끝에 도달했을 때 다시 처음(0)으로 돌아가게 계산하는 연산
- **FCFS 스케줄링**: 준비 큐에 도착한 순서대로 CPU를 할당하는 CPU 스케줄링 기법
- **RR(Round Robin) 스케줄링**: 일정 시간(time slice)만 CPU를 사용하고, 끝나지 않으면 준비 큐의 맨 뒤로 다시 보내는 CPU 스케줄링 기법
- **준비 큐(Ready Queue)**: CPU를 기다리는 작업들이 줄 서 있는 큐
- **BFS(너비 우선 탐색)**: 한 정점에서 인접한 정점들을 순서대로 하나씩 방문하는 탐색 방법 (큐를 활용)
