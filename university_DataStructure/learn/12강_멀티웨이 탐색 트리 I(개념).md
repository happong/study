# 12강 — 멀티웨이 탐색 트리 Ⅰ

## 핵심 요약

- **m원 탐색 트리(m-way search tree)**는 노드 하나가 자식을 최대 m개까지 가질 수 있도록 이진 탐색 트리를 확장한 트리다. 자식이 많아질수록 같은 개수의 데이터를 더 낮은 높이로 담을 수 있다.
- m원 탐색 트리는 노드 안에 **키 여러 개와 포인터 여러 개가 번갈아** 들어있는 구조(P₀ k₀ P₁ k₁ ... Pₙ)이며, 키 값은 항상 왼쪽에서 오른쪽으로 오름차순이고, 포인터가 가리키는 서브트리의 모든 값은 그 좌우 키 사이에 들어간다.
- m원 탐색 트리는 **서브트리 사이의 균형을 보장하지 않는다**는 약점이 있다. 이를 개선해서 항상 균형을 유지하도록 만든 것이 **B 트리**다.
- **B 트리(B-tree)**는 ①루트·잎을 제외한 모든 노드가 최소 ⌈m/2⌉개의 서브트리를 갖고, ②루트는 최소 2개의 서브트리를 가지며, ③모든 잎 노드가 같은 레벨에 있는, 매우 균형 잡힌 탐색 트리다. 인덱스(색인) 구조를 구현하는 데 가장 널리 쓰인다.
- B 트리에 키를 **삽입**할 때 노드에 빈자리가 있으면 그냥 넣고 끝나지만, 노드가 꽉 차 있으면 **노드를 둘로 쪼개고(분리)** 중간값을 부모로 올려보낸다. 이 과정이 루트까지 연쇄적으로 이어질 수 있다.
- B 트리에서 키를 **삭제**할 때, 잎 노드면 바로 지우면 되지만 내부 노드면 왼쪽 서브트리의 최댓값(또는 오른쪽 서브트리의 최솟값)으로 대체한 뒤 그 값을 지운 자리에서 삭제한다. 삭제 후 키 개수가 모자라면 형제와 **재배열(회전)**하거나 **결합**한다.
- **B\* 트리**는 B 트리를 더 꽉 채운 버전(노드의 약 2/3 이상 채움)으로, 노드가 꽉 차도 바로 분리하지 않고 먼저 **형제 노드로 키를 옮겨서** 분리 횟수를 줄인다.
- **B+ 트리**는 모든 실제 데이터 주소를 **잎 노드에만** 두고, 잎 노드들끼리 포인터로 한 줄로 연결해 둔 트리다. 그래서 "이 값 하나를 찾는" 직접 탐색과 "처음부터 끝까지 순서대로 훑는" 순차 처리를 모두 잘 할 수 있다.

## 상세 내용

### 1. m원 탐색 트리 (m-way Search Tree)

**비유**: 이진 탐색 트리(BS 트리)는 "왼쪽이냐 오른쪽이냐" 딱 두 갈래 길만 있는 미로다. 그런데 노드 하나에서 선택할 수 있는 길을 2개가 아니라 더 많이(예: 5개, 10개) 만들어주면, 같은 수의 방(데이터)을 훨씬 낮은 층수(트리의 높이)로 배치할 수 있다. 이것이 m원 탐색 트리다.

**이진 탐색 트리(BS 트리, binary search tree)**
- 트리에서 특정 데이터를 검색하고, 노드의 삽입/삭제가 자주 일어나는 문제에 효과적인 이진 트리.
- '왼쪽'과 '오른쪽'이라는 방향성이 있어 다루기 편리함.
- 부모 노드 기준으로 [부모보다 작은 데이터 : 왼쪽 서브트리], [부모보다 큰 데이터 : 오른쪽 서브트리]로 구분됨.
- 노드 개수가 많아지면 트리의 높이가 커짐 → 노드 개수는 같아도 높이를 낮게 유지하는 자료구조가 필요 (예: 노드 9개를 균형있게 배치하면 높이가 작지만, 한쪽으로 치우치면 높이가 노드 개수만큼 길어짐).
- BS 트리는 **2원(2-way) 탐색 트리**다 (자식을 최대 2개만 가짐).

**m원 탐색 트리의 정의**
- 트리의 노드가 m개 이하의 가지(자식)를 가질 수 있는 탐색 트리.
- 같은 수의 노드를 갖는 이진 트리보다 낮은 높이의 m원 트리를 만들 수 있음.
- 이진 탐색 트리의 확장된 형태이며, 이진 탐색 트리의 제한(왼쪽은 작은 값, 오른쪽은 큰 값)을 그대로 따르면서 두 개 이상(m개 이하)의 자식 노드를 가질 수 있음.

**m원 탐색 트리(=n원 탐색 트리)의 노드 조건** — 노드 구조는 다음과 같다. 여기서 P₀, P₁, ..., Pₙ은 서브트리에 대한 포인터이고, k₀, ..., k_{n-1}은 키 값이다. 또한 n ≤ m - 1 이 성립한다.

```
| P₀ | k₀ | P₁ | k₁ | P₂ | ... | Pₙ₋₁ | kₙ₋₁ | Pₙ |
```

① 위 노드 구조를 가진다 (n ≤ m-1).
② i = 0, ..., n-2 인 i에 대해 kᵢ < kᵢ₊₁ 을 만족한다 (키는 오름차순).
③ i = 0, ..., n-1 인 i에 대해 Pᵢ가 가리키는 서브트리의 모든 키 값은 kᵢ의 키값보다 작다.
④ Pₙ이 가리키는 서브트리의 모든 키값은 kₙ₋₁의 키값보다 크다.
⑤ i = 0, ..., n 인 i에 대해 Pᵢ가 가리키는 서브트리는 m원 탐색 트리이다. (재귀적 정의)

**3원 탐색 트리 예시**: 노드가 `P₀ k₀ P₁ k₁ P₂`의 형태(키 2개, 포인터 3개)를 가지며, 50, 80을 담은 루트 아래로 20·40, 70, 82·91 등이 이어지는 예시 트리가 제시되었다(그림 참고). 단말 노드는 키 값만 표기하고, 자식이 없는 포인터는 그리지 않는다.

**m원 탐색 트리 노드의 C 언어 구조체 예시**
```c
struct Mnode {
    int n;
    struct rectype {
        struct Mnode *ptr;
        int key;
        struct rectype *addr;
    } keyptrs[n-1];
    struct Mnode *keyptrn;
};

typedef struct BSTnode {
    struct BSTnode* left;
    char key;
    char content[10];
    struct BSTnode* right;
} BSTnode;
```

**m원 탐색 트리의 탐색(검색) 알고리즘 — Search 함수**
```c
struct Mnode *nodeptr;
struct rectype *recptr;
struct rectype *Search(int skey, struct Mnode *r) {
    int i;
    extern struct Mnode node;
    if (r == NULL)
        return(NULL);
    else {
        i = 0;
        while(i < r->n && skey > r->keyptrs[i].key)
            i++;
        if (i < r->n && skey == r->keyptrs[i].key)
            return(r->keyptrs[i].addr);
        else if (i < r->n)
            return(Search(skey, r->keyptrs[i].ptr));
        else
            return(Search(skey, r->keyptrn));
    }
}
```
- 동작 순서: ① 루트가 NULL이면 탐색 실패. ② 노드 안의 키들을 왼쪽에서 오른쪽으로 비교해 skey보다 작은 동안 i를 증가시킨다. ③ 키를 찾으면 그 주소 반환. ④ 못 찾았고 i가 노드 안 범위면 그 위치의 포인터(Pᵢ)를 따라 재귀 탐색. ⑤ i가 범위를 벗어나면 마지막 포인터(Pₙ, 즉 keyptrn)를 따라 재귀 탐색.
- m원 탐색 트리의 탐색 연산: 일반적으로 노드의 가지(서브트리) 개수가 많을수록, 트리의 깊이가 얕아지므로 최대 탐색 길이는 짧아진다 (더 빨리 찾을 수 있음).
- 예시: 같은 데이터(1~9)를 4개 노드로 구성한 트리(루트가 자식 4개)는 2개 노드로 구성한 트리(이진 트리)보다 최대 탐색 경로 길이가 짧다. 키가 255개인 경우 4원 트리로 구성하면 최대 경로 길이가 4가 된다.

### 2. B 트리 (B-tree)

**비유**: m원 탐색 트리는 "가지를 여러 개 뻗어도 된다"는 규칙만 있을 뿐, 어느 가지는 길고 어느 가지는 짧아도 상관없다. 마치 나뭇가지를 아무렇게나 자라게 둔 나무 같다. B 트리는 이 나무를 "모든 가지 끝(잎)이 땅에서 같은 높이에 있도록" 정원사가 다듬어 놓은 나무다. 그래서 어디를 찾아가도 걸리는 시간이 비슷하다.

- m원 탐색 트리는 서브트리의 균형에 대해서는 특별히 제한하지 않음.
- 각 노드가 자식을 많이 갖게 하여 트리의 높이를 줄이고, 전체적으로 균형을 유지한다면 탐색 성능을 더욱 향상할 수 있음.
- m원 탐색 트리를 개선한 B 트리는 인덱스 구조를 구현하는 데 가장 일반적으로 사용함.
- 차수 m인 B 트리의 탐색 경로 길이는 같은 개수의 키를 가지는 이상적인 m원 탐색 트리보다 길 수 있지만, 이상적인 m원 탐색 트리의 유지 비용에 비해 키 값을 삽입/삭제할 때 B 트리를 유지하는 것이 더 효율적임(쉬움).

**B 트리의 조건 (차수 m)**
① 루트와 잎 노드를 제외한 트리의 각 노드는 최소 ⌈m/2⌉개의 서브트리를 갖는다.
② 트리의 루트는 최소한 2개의 서브트리를 갖는다.
③ 트리의 모든 잎 노드는 같은 레벨에 있다.

- `⌈ ⌉` : 가우스 함수(올림 함수). 소수점을 포함한 수를 그것보다 1 큰 정수로 바꿈. 예) ⌈3/2⌉ = ⌈1.5⌉ = 2.
- 차수 3인 B 트리 예시(63을 루트로, 13·43 / 86·90 등으로 이어지는 트리)가 제시됨: 각 노드는 최소 ⌈3/2⌉=2개의 서브트리를 가진다.

**B 트리에 키를 삽입하는 알고리즘**
① 삽입할 위치를 찾기 위해 노드의 키 값을 왼쪽에서 오른쪽으로 탐색한다. (B 트리에서 모든 노드는 잎 노드에서 삽입이 시작됨)
② 노드에 빈자리가 있으면 삽입 후 종료한다.
③ 노드가 꽉 찼으면 노드를 2개로 분리하고 키와 포인터를 새 노드에 반씩 할당한다.
  - ③-1 잎 노드 키값과 삽입 노드 키값 중에서 중간값을 선택한다.
  - ③-2 선택된 중간값보다 작은 키값은 왼쪽 노드에, 큰 것은 오른쪽 노드에 넣는다.
  - ③-3 중간값을 가지는 노드의 키값과 포인터를 부모 노드에 삽입한다. 만일 부모 노드가 루트 노드면 두 노드를 가리키도록(자식 노드가 되도록) 수정한다.

**삽입 예시 (차수 3인 B 트리에 21, 41, 54, 52, 51 차례로 삽입)**
- **21, 41 삽입**: 각각 20과 42 노드에 빈 자리가 있으므로 그냥 끼워 넣는다 → `20|21`, `41|42`.
- **54 삽입(노드 분리)**: `60` 노드에 54를 넣으려 하는데 자리가 없다. 기존 값 50, 53, 54, 60, 61, 62 중 중간값인 54를 기준으로, 작은 값(50, 53)은 왼쪽 노드, 큰 값(61, 62)은 오른쪽 노드로 나누고, 54는 부모 노드(13, 43 노드)로 올라가 `53 | 60`이 된다.
- **52 삽입**: 50 노드에 자리가 있으므로 `50 | 52`로 그냥 끼워 넣는다.
- **51 삽입(부모 노드까지 연쇄 분리)**: 50, 51, 52가 들어갈 노드에 자리가 없어, 중간값 51을 부모로 올리며 분리(`50` / `52`). 그런데 부모 노드(53, 60)도 꽉 차 있어 다시 분리가 필요 → 51, 53, 60 중 중간값 53이 그 위 부모(13, 43)로 올라가며, 43 노드도 꽉 차 있어 13, 43, 53 중 중간값 43이 루트(63)로 올라가 루트가 `43 | 63`이 된다. 이처럼 분리가 **부모 노드까지 연쇄적으로 전파**될 수 있다.
- 10개의 키(21, 41, 54, 52, 51 포함)를 모두 삽입한 후의 최종 B 트리 모습이 슬라이드에 제시됨.

**B 트리에서 키를 삭제하는 알고리즘**
- **잎 노드에서 삭제하는 경우**
  ① 노드에서 키 값을 삭제한다.
  ② 필요하면 재배열한다.
  - 예시: 62 삭제(그냥 지움, `61|62`→`61`), 0 삭제(`0|10`→`10`).
- **내부 노드에서 삭제하는 경우**: 내부 노드의 키 값은 하위 노드에 대한 기준값(중간값)이기 때문에 삭제 시 대체할 수 있는 적절한 값을 찾아야 한다. 보통 왼쪽 서브트리의 가장 큰 키 값 또는 오른쪽 서브트리의 가장 작은 키 값으로 대체할 수 있다. 이들은 모두 잎 노드에 위치한다.
  ① 새로운 기준값(삭제된 자리에 올 키 값)을 선택하여 해당(잎) 노드에서 삭제하고, 그 값을 현재 키 값을 삭제한 자리로 옮긴다. 즉 대체한 것이다.
  ② 기준값으로 대체하기 위해 키를 삭제한 잎 노드가 정해진 개수의 키 값을 갖지 않으면 트리를 재배열한다.
  - 예시: 40 삭제 → 왼쪽 서브트리 최댓값인 41을 가져와 40 자리를 대체(41이 부모 위치로, 남은 자식은 `32` / `42`).
- **재배열(rebalancing)**: 키 값이 부족한 노드가 생겼을 때 다음 순서로 처리한다.
  ① 오른쪽 형제가 존재하고 키가 정해진 개수보다 많다면 **왼쪽으로 회전**한다. (①-1 부모 노드의 기준(키)값을 개수가 부족한 노드의 끝으로 이동 즉, 기준값을 한 단계 아래로 내려 개수를 채움 / ①-2 부모 노드의 기준값을 오른쪽 형제의 첫 번째 키로 수정해 균형을 맞춤)
  ② 왼쪽 형제가 존재하고 키가 정해진 개수보다 많다면 **오른쪽으로 회전**한다. (②-1, ②-2는 ①과 방향만 반대로 대칭)
  ③ 좌우 형제가 모두 최소 개수의 키만 가지고 있다면 **좌우 형제를 합친다(결합)**.
    - ③-1 부모 노드의 기준(키)값을 왼쪽 노드의 마지막에 복사한다.
    - ③-2 오른쪽 노드의 모든 키 값을 왼쪽 노드로 옮긴다 (왼쪽 노드가 최대 개수의 키를 갖게 됨).
    - ③-3 키를 갖지 않는 오른쪽 노드는 삭제한다.
    - ③-4 부모 노드가 루트이면서 키를 더 이상 갖지 않으면 합쳐진 노드가 새로운 루트가 된다. 그렇지 않고 부모 노드의 키 개수가 정해진 개수보다 작으면 부모 노드를 재배열한다 (재귀적으로 위로 전파될 수 있음).
  - 예시: 11 삭제 → `11|12`에서 11을 지우면 `12`만 남아 최소 개수 미달 → 왼쪽 형제(10)와 부모 키(13)를 합쳐 `10|12`로 결합하고 부모 노드에서는 13이 사라져 `31`만 남음.

### 3. B\* 트리와 B+ 트리

**B\* 트리의 정의**
- 노드의 약 2/3 이상이 채워지는 B 트리(일반 B 트리는 최소 절반(⌈m/2⌉)만 채우면 되지만, B\*는 더 꽉 채움).
- 노드가 꽉 차면 바로 분리하지 않고, 키와 포인터를 **재배치하여 다른 형제 노드로 옮김** → B 트리와 동일한 수의 노드를 갖는다면 높이가 더 낮고, 삽입/삭제 시 발생하는 노드 분리를 줄이려고 고안됨.
- 차수가 m인 B\* 트리의 조건:
  ① 공집합이거나 높이가 1 이상인 m원 탐색 트리이다.
  ② 루트 노드는 2개 이상 2⌊(2m-2)/3⌋+1개 이하의 자식 노드를 갖는다.
  ③ 내부 노드는 최소한 ⌈(2m-1)/3⌉개의 자식 노드를 갖는다.
  ④ 모든 잎 노드는 동일한 레벨에 놓인다.
  ⑤ 포인터가 k개인 (잎 노드가 아닌) 노드는 k-1개의 키를 갖는다 (루트 노드 포함).

**B\* 트리의 노드 삽입 예시**
- **4 삽입 (ⅰ): 형제 노드로 키 값을 이동** — 형제 노드에 공간 여유가 있을 경우, 노드를 분리하지 않고 형제 노드로 키를 밀어 넣는다. 예: 부모 키가 6일 때 왼쪽 자식(1,2,3,5)에 4를 넣으려 하면 자리가 없으므로, 오른쪽 형제(7,8)에 여유가 있어 부모 키를 4로 바꾸고 기존 6은 오른쪽 형제로 밀어 넣어 왼쪽은 `1,2,3`, 오른쪽은 `5,6,7,8`이 된다.
- **4 삽입 (ⅱ): 두 개의 노드를 세 개로 분리** — 형제 노드에도 공간 여유가 없을 경우에는 부모 노드의 공간까지 이용해서 기존 두 개 노드를 세 개의 노드로 재구성한다. 예: `1,2,3,5`와 `7,8,9,10` 두 노드에 4를 넣을 자리가 없고 부모(6)도 꽉 차 있어, 전체를 재배치해 부모가 `3 | 7`이 되고 자식이 `1,2` / `4,5,6` / `8,9,10`의 세 노드로 나뉜다.

**B+ 트리의 정의**
- 탐색 트리로 구성하면 매우 빠르게 탐색할 수 있지만, 전체 데이터를 차례로(순차) 처리하기는 불편함. (매번 왼쪽인지 오른쪽인지 비교하며 다음 노드를 찾아가야 하기 때문)
- B+ 트리는 **인덱스된 순차 파일**을 구성하는 데 사용됨.
- B 트리와 같이 각 노드의 키가 적어도 1/2이 채워져야 하는 점은 같음.
- **잎 노드를 순차적으로 연결하는 포인터 집합**이 있다는 점에서 B 트리와 다름. 잎 노드의 마지막 포인터가 다음 키 값을 갖는 노드를 가리킴.
- 순차 처리를 할 때는 이 포인터를 이용해서 (키 값을 비교하지 않고) 차례로 다음 데이터에 접근해서 처리한다.
- 모든 키 값이 잎 노드에 있고, 그 키 값에 대응하는 실제 데이터(파일 내용)에 대한 주소를 잎 노드만이 가지고 있음.
- 직접 탐색은 반드시 잎 노드에 도달해야 종료됨.

**B+ 트리의 노드 삽입**
- 잎 노드가 2개의 노드로 분리될 때는 키 값 순서에 따라 배치하고, 중간 키 값은 부모 노드에 올려놓는다.
- 새 노드는 순서에 맞게 잎 노드에 삽입함.

**B+ 트리의 노드 삭제**
- 키 값을 잎 노드에서 삭제할 때, 트리의 내부 노드에서도 삭제할 필요는 없는데, 그 키 값이 직접 탐색을 위해 쓰이기 때문임 (내부 노드의 값은 "이정표" 역할만 하고, 실제 데이터 주소는 잎에만 있으므로).

**B+ 트리의 특징**
- 모든 키값이 앞(잎)에 있고, 그 키값에 대응하는 실제 데이터에 대한 주소를 잎 노드만이 가지고 있음.
- 탐색은 잎 노드에 도달해야 종료됨.
- 같은 노드의 B 트리보다 레벨이 작아서 같은 차수의 B 트리와 탐색 성능이 거의 같음.

### 트리 가계도 정리 (관계)

```
BS 트리 ----------→ m원 탐색 트리 ──→ B 트리 ──→ B+ 트리
(2원 탐색 트리)                              └──→ B* 트리
```

## 기억해야 할 키워드

- **m원 탐색 트리(m-way search tree)**: 노드가 m개 이하의 가지(자식)를 가질 수 있는 탐색 트리. 이진 탐색 트리의 확장.
- **n ≤ m-1**: m원 탐색 트리 노드 안의 키 개수(n)는 항상 m-1 이하여야 한다는 조건.
- **B 트리**: 루트·잎 제외 모든 노드가 최소 ⌈m/2⌉개의 서브트리를 갖고, 모든 잎이 같은 레벨에 있는 균형 잡힌 m원 탐색 트리. 인덱스 구조 구현에 가장 일반적으로 사용.
- **가우스 함수 ⌈ ⌉**: 소수점이 있는 수를 그보다 1 큰 정수로 바꾸는 올림 함수. 예) ⌈3/2⌉ = 2.
- **노드 분리(split)**: B 트리에서 노드가 꽉 찬 상태로 삽입이 일어나면, 중간값을 기준으로 노드를 둘로 나누고 중간값을 부모로 올리는 과정.
- **재배열(rebalancing)**: B 트리 삭제 후 키 개수가 부족한 노드를 형제 노드와 회전하거나 결합해 균형을 맞추는 과정.
- **회전(rotation)**: 형제 노드가 여유 키를 가지고 있을 때, 부모의 기준값을 내리고 형제의 키를 부모로 올려 개수를 맞추는 재배열 방법.
- **결합(merge)**: 좌우 형제가 모두 최소 개수의 키만 가질 때, 부모의 기준값과 함께 두 노드를 하나로 합치는 재배열 방법.
- **B\* 트리**: 노드의 약 2/3 이상이 채워지는 B 트리. 노드가 꽉 차도 바로 분리하지 않고 형제 노드로 키를 재배치해 분리 횟수를 줄임.
- **B+ 트리**: 모든 실제 데이터 주소를 잎 노드에만 두고, 잎 노드들을 포인터로 순차 연결한 트리. 인덱스된 순차 파일 구성에 사용. 직접 탐색과 순차 처리를 모두 지원.
- **인덱스된 순차 파일**: 데이터를 순서대로 접근(순차 처리)할 수도 있고, 특정 값을 바로 찾아갈(직접 탐색) 수도 있는 파일 구조. B+ 트리로 구현.
- **내부 노드에서의 삭제**: 삭제할 키가 내부 노드에 있으면, 왼쪽 서브트리의 최댓값 또는 오른쪽 서브트리의 최솟값(둘 다 잎 노드에 위치)으로 대체한 뒤 그 잎 노드에서 실제로 삭제.
