# 06강 — 연결 리스트의 응용

## 핵심 요약

- 단순(단일) 연결 리스트는 "다음 노드"만 가리키기 때문에, 어떤 노드의 **앞(선행) 노드**를 찾으려면 매번 머리(head)부터 다시 검색해야 하는 문제가 있다.
- 이 문제를 해결하는 두 가지 변형이 있다: **원형 연결 리스트**와 **이중 연결 리스트**.
- **원형 연결 리스트**: 마지막 노드의 링크가 `NULL`이 아니라 다시 **첫 번째 노드(head)를 가리키도록** 만들어, 리스트가 둥글게 연결된 구조. 링크는 한 개뿐이다.
- **이중 연결 리스트**: 노드마다 링크를 **두 개(Llink, Rlink)** 두어서, 선행 노드와 후행 노드 양쪽에 바로 접근할 수 있는 구조. 머리 노드도 `Lhead`, `Fhead` 두 개의 포인터를 가진다.
- 원형 리스트는 **순환 작업(라운드 로빈 스케줄링, 반복 재생 등)**에 유리하지만, 끝을 알리는 `NULL`이 없어서 종료 조건을 직접 정해줘야 하며 무한 루프 위험이 있다.
- 이중 연결 리스트는 **양방향 이동과 빠른 삭제**가 가능해 되돌리기(undo), 덱(deque), LRU 캐시 같은 곳에 적합하지만, 노드마다 포인터가 하나 더 필요해 메모리를 더 쓰고 구현이 더 복잡하다.
- 노드를 삽입/삭제할 때는 항상 "새 노드(또는 삭제할 노드) 주변의 링크들을 순서대로 다시 연결"하는 절차를 그림(주소값)으로 따라가며 이해하는 것이 핵심이다.

## 상세 내용

### 1. 단순 연결 리스트의 문제점

**비유**: 단순 연결 리스트는 기차 칸들이 **한 방향 고리**로만 연결된 것과 같다. 앞 칸에서 뒤 칸으로는 쉽게 넘어갈 수 있지만, 뒤 칸에 서서 "내 앞 칸이 뭐였지?"를 알고 싶으면 다시 맨 앞(기관차, head)까지 걸어가서 하나씩 세어봐야 한다.

**정확한 정의**: 단순 연결 리스트는 링크(link) 필드가 하나뿐이고, 각 노드의 링크는 **후행(다음) 노드만** 가리키는 구조이다. 따라서 특정 노드의 후행 노드는 쉽게 찾을 수 있지만, **특정 노드의 선행 노드에 접근하려면 head부터 재검색**해야 하는 문제가 있다. 이를 해결하기 위해 자료구조 자체를 바꾸는 방법(이중 연결 리스트)이 제안되었다.

```
H → [head] → [data:100|link] → [data:200|link] → [data:300|link:NULL]
```

### 2. 이중 연결 리스트 (개념 소개, 자세한 내용은 3절)

슬라이드에서는 먼저 "하나의 포인터가 더 필요함"을 보여주며 이중 연결 리스트 구조를 미리 보여준다. 각 노드는 `Llink`(왼쪽/선행), `data`, `Rlink`(오른쪽/후행) 세 부분으로 구성된다.

```
typedef struct {
    Llink   // 선행 노드를 가리키는 링크
    data    100
    Rlink   // 후행 노드를 가리키는 링크
}
```

**핵심 포인트**: 특정 노드에서 선행 노드와 후행 노드 모두에 "간단한 프로그램 코드"로 직접 접근할 수 있다는 점이 단순 연결 리스트와의 가장 큰 차이다.

### 3. 원형 연결 리스트

**비유**: 단순 연결 리스트의 마지막 칸은 항상 "다음 칸 없음(NULL)"이라는 표지판을 달고 있다. 그런데 이 표지판은 사실 아무 일도 하지 않고 그냥 버려지는 자리다. 원형 연결 리스트는 이 마지막 칸의 표지판 대신 **맨 앞 칸을 가리키는 화살표**를 달아서, 기차를 둥근 놀이기구처럼 계속 빙글빙글 돌 수 있게 만든 것이다.

**정확한 정의**: 연결 리스트의 마지막 노드 링크 필드는 원래 항상 `NULL` 값이다(마지막 노드 뒤에는 아무 노드도 없기 때문). 이 "노는" 링크 필드를 활용하면서 프로그램 성능에 도움이 되도록, 마지막 노드의 링크가 **첫 번째 노드(head)를 다시 가리키게** 만든 것이 원형 연결 리스트이다.

```
H → head(5000) → [data:100|link] → [data:200|link] → [data:300|link] ┐
      ↑___________________________________________________________|
```

**실무 예시(교재 외 내용)**: CPU 스케줄링의 **준비 큐(Ready Queue)**처럼, 작업(A, B, C, A …)들을 순서대로 처리하다가 끝나면 다시 큐의 맨 앞으로 돌아가 반복 처리하는 **라운드 로빈 스케줄링**에 원형 구조가 잘 어울린다.

#### 3-1. 원형 연결 리스트의 정의 및 생성 (코드)

```c
typedef struct ListNode {        // 원형 연결 리스트의 노드 구조 정의
    int data;
    struct ListNode* link;
} listNode;

typedef struct {                 // 원형 연결 리스트의 헤드 노드 구조 정의
    listNode* head;
} linkedList_h;

linkedList_h* createLinkedList_h(void) {   // 헤드 노드 생성
    linkedList_h* H;
    H = (linkedList_h*)malloc(sizeof(linkedList_h));
    H → head = NULL;
    return H;
}
```

#### 3-2. 원형 연결 리스트의 첫 번째 노드 삽입

리스트가 **비어 있을 때(H→head == NULL)**는, 새 노드(NewNode)를 만들어 그 자신이 자기 자신을 가리키게 한다(1개짜리 원이 되는 셈).

```c
void addFirstNode(linkedList_h* H, int x) {
    listNode* tempNode;
    listNode* NewNode;
    NewNode = (listNode*)malloc(sizeof(listNode));
    NewNode → data = x;
    NewNode → link = NULL;

    if (H → head == NULL) {           // 현재 원형 연결 리스트가 공백인 경우
        H → head = NewNode;
        NewNode → link = NewNode;     // 자기 자신을 가리킴
        return;
    }
    else {                             // 현재 원형 연결 리스트가 공백이 아닌 경우
        tempNode = H → head;
        while (tempNode → link != H → head)
            tempNode = tempNode → link;   // 마지막 노드를 찾음(head를 다시 가리키는 노드)
        NewNode → link = tempNode → link; // NewNode가 head를 가리키게
        tempNode → link = NewNode;        // 마지막 노드가 NewNode를 가리키게
        H → head = NewNode;               // head가 NewNode(새 첫 노드)를 가리키게
    }
}
```

**동작 순서 요약(공백이 아닌 경우, 맨 앞에 삽입)**:
1. `tempNode`를 head부터 출발시켜, 링크가 다시 head로 돌아오는 **마지막 노드**를 찾는다.
2. `NewNode → link = tempNode → link` : 새 노드가 기존 첫 노드(=head)를 가리키게 한다.
3. `tempNode → link = NewNode` : 마지막 노드가 새 노드를 가리키게 해서 원을 다시 닫는다.
4. `H → head = NewNode` : head가 새 노드를 가리키도록 바꾼다.

#### 3-3. 원형 연결 리스트의 중간 노드 삽입

이미 삽입할 위치의 **앞 노드(prevNode)**를 알고 있을 때는 훨씬 간단하다.

```c
void addMiddleNode(linkedList_h* H, listNode* prevNode, int itdata) {
    listNode* NewNode;
    NewNode = (listNode*)malloc(sizeof(listNode));
    NewNode → data = itdata;
    NewNode → link = NULL;

    NewNode → link = prevNode → link;  // 새 노드가 prevNode의 다음 노드를 가리키게
    prevNode → link = NewNode;          // prevNode가 새 노드를 가리키게
    return;
}
```

#### 3-4. 원형 연결 리스트의 노드 탐색과 삭제

먼저 지우려는 값을 가진 노드를 찾고(탐색), 찾으면 삭제 함수를 호출한다.

```c
void finddelCircularNode(linkedList_h* H, int itdata) {
    listNode* tempNode;
    listNode* prevNode;
    prevNode = H;
    if (H → head == NULL) {               // 공백인 경우
        printf("Circular Linked List is EMPTY");
        return;
    }
    else {
        tempNode = H → head;               // 첫 번째 노드부터 검색하기 위함
        do {
            if (tempNode → data == itdata) {       // 찾는 노드값 검색
                return deleteCircularNode(H, prevNode);
            }                                        // 찾았다면 삭제 함수 호출하며 검색 함수는 끝
            else {
                prevNode = tempNode;
                tempNode = tempNode → link;
            }
        } while (tempNode != H → head);
        // 마지막 노드까지 검색했는데 없는 경우라면,
        printf("Search Fail");    // 검색 실패 메시지 출력
        return;
    }
}
```

실제 삭제는 아래 함수가 담당한다. (prevNode는 삭제할 노드의 바로 앞 노드)

```c
void deleteCircularNode(linkedList_h* H, listNode* prevNode) {
    listNode* lastNode;
    listNode* delNode;
    lastNode = H → head;
    while (lastNode → link != H → head) lastNode = lastNode → link;  // 마지막 노드 찾기

    delNode = prevNode → link;             // 지울 노드
    prevNode → link = delNode → link;      // 앞 노드가 지울 노드를 건너뛰고 연결

    if (delNode == H → head) {             // 지울 노드가 첫 번째 노드였다면
        H → head = delNode → link;         // head를 다음 노드로 옮기고
        lastNode → link = H → head;        // 마지막 노드가 새 head를 가리키게
    }
    free(delNode);
}
```

**예외 상황(교재 외 내용)**: 지울 노드가 **리스트에 남은 유일한 노드**라면, `H == prevNode`가 되는 특수한 경우이며 이때는 `H → head = NULL`로 리스트를 완전히 비운다.

#### 3-5. 원형 연결 리스트의 장단점 (교재 외 내용)

| 구분 | 내용 |
|---|---|
| 장점 | 순환 처리(라운드 로빈, 반복 재생)에 적합 |
| 장점 | 끝/처음을 따로 처리할 필요가 줄어듦 (NULL 대신 다시 처음으로) |
| 장점 | 어떤 노드에서 시작해도 전체 순회 가능 (head가 꼭 "첫 위치"일 필요 없음) |
| 단점 | 종료 조건 실수 시 무한 루프 위험 (NULL이 없으므로 "head로 돌아오면 종료" 같은 기준 필요) |
| 단점 | 구현이 단일 연결 리스트보다 까다로움 (빈 리스트/노드 1개일 때 특히) |
| 단점 | 탐색은 여전히 O(n) — 원형이라고 검색이 빨라지지는 않음 |
| 단점 | 디버깅이 불편할 수 있음 (잘못 연결되면 계속 순환하며 원인 찾기 어려움) |

### 4. 이중 연결 리스트

**비유**: 기차의 각 칸이 앞 칸과 뒤 칸으로 가는 문을 **양쪽에 모두** 가지고 있는 것과 같다. 어느 칸에 서 있어도 앞으로도, 뒤로도 바로 이동할 수 있다.

**정확한 정의**: 이중 연결 리스트는 노드마다 **선행 노드를 가리키는 링크(Llink)**와 **후행 노드를 가리키는 링크(Rlink)**를 모두 가지는 구조이다. 덕분에 특정 노드에서 선행 노드와 후행 노드 모두에 간단한 코드로 직접 접근할 수 있다. 양쪽으로 순회해야 하므로 머리(head) 노드도 두 개의 링크, 즉 `Lhead`(왼쪽 끝을 가리킴)와 `Fhead`(First head, 첫 노드를 가리킴)를 가진다.

```c
typedef struct ListNode {        // 이중 연결 리스트의 노드 구조 정의
    struct ListNode* Llink;
    int data;
    struct ListNode* Rlink;
} listNode;

typedef struct {                 // 이중 연결 리스트의 헤드 노드 구조 정의
    listNode* Lhead;
    listNode* Fhead;
} linkedList_h;
```

**초기화**:
```c
linkedList_h* createLinkedList_h(void) {
    linkedList_h* H;
    H = (linkedList_h*)malloc(sizeof(linkedList_h));
    H → Lhead = NULL;
    H → Fhead = NULL;
    return H;
}
```

(참고로 슬라이드에는 "원형 이중 연결 리스트(완결)" 그림도 등장하는데, 이는 이중 연결 리스트에 원형 구조까지 합쳐서 `Lhead`가 리스트 전체를 양방향 원으로 닫아주는 모습을 보여준다.)

#### 4-1. 이중 연결 리스트의 노드 삽입

예: 데이터 값 100, 300인 노드 사이에 데이터 값 200인 새 노드를 삽입하는 경우.

```c
void addDNode(linkedList_h* H, listNode* prevNode, int x) {
    listNode* NewNode;
    NewNode = (listNode*)malloc(sizeof(listNode));
    NewNode → Llink = NULL;
    NewNode → data = x;
    NewNode → Rlink = NULL;

    NewNode → Rlink = prevNode → Rlink;        // ① 새 노드가 "뒤 노드"를 가리키게
    prevNode → Rlink = NewNode;                 // ② prevNode가 새 노드를 가리키게
    NewNode → Llink = prevNode;                 // ③ 새 노드가 "앞 노드(prevNode)"를 가리키게
    NewNode → Rlink → Llink = NewNode;          // ④ 새 노드 뒤에 있던 노드가 다시 새 노드를 가리키게
}
```

**그림으로 보는 4단계 순서**(중요! 순서를 바꾸면 링크를 잃어버린다):
1. `NewNode → Rlink = prevNode → Rlink` : 새 노드의 오른쪽 링크를 먼저 "원래 뒤 노드"로 설정 (이 순서를 지켜야 뒤 노드 주소를 잃지 않음)
2. `prevNode → Rlink = NewNode` : 앞 노드가 새 노드를 가리키도록 변경
3. `NewNode → Llink = prevNode` : 새 노드의 왼쪽 링크가 앞 노드를 가리키도록 설정
4. `NewNode → Rlink → Llink = NewNode` : (새 노드의 오른쪽에 있는) 뒤 노드의 왼쪽 링크가 새 노드를 가리키도록 수정 — 이렇게 해야 뒤 노드에서도 새 노드로 되돌아올 수 있다.

#### 4-2. 이중 연결 리스트의 노드 삭제

예: 데이터 값 300인 노드(delNode)를 삭제하는 경우.

```c
void deleteDNode(linkedList_h* H, listNode* delNode) {
    delNode → Llink → Rlink = delNode → Rlink;   // ① 앞 노드가 "delNode의 뒤 노드"를 바로 가리키게
    delNode → Rlink → Llink = delNode → Llink;   // ② 뒤 노드가 "delNode의 앞 노드"를 바로 가리키게
    free(delNode);                                 // ③ delNode 메모리 해제
}
```

삭제할 노드의 앞/뒤 링크 2개만 서로 다시 이어주면 되므로, 단일/원형 연결 리스트처럼 head부터 재검색할 필요가 없다는 것이 핵심 장점이다.

#### 4-3. 이중 연결 리스트의 장단점 (교재 외 내용)

| 구분 | 내용 |
|---|---|
| 장점 | 양방향 순회 가능 — undo, 이전/다음 탐색에 유리 |
| 장점 | 삭제 노드의 주소를 알고 있으면 보통 O(1)로 삭제 가능 |
| 장점 | 중간 삽입/삭제가 효율적 (해당 위치 포인터만 있으면 O(1)) |
| 장점 | Deque(양끝 큐), LRU 캐시 등에 적합 |
| 단점 | 노드마다 Llink가 추가되어 메모리 사용량 증가 |
| 단점 | 구현/유지보수가 더 복잡 (Llink, Rlink 둘 다 올바르게 갱신해야 함) |
| 단점 | 연산당 갱신할 포인터가 많아 상수 시간 오버헤드가 커질 수 있음 |

### 5. 정리 비교 (자료의 추상화 측면 / 자료구조 측면)

- **단순 연결 리스트**: 링크가 하나뿐이고, 각 노드는 후행 노드만 가리킴.
- **이중 연결 리스트**: 노드에서 선행 노드와 후행 노드 모두에 간단한 코드로 접근 가능.
- **원형 연결 리스트**: 원래 `NULL`이던 마지막 노드의 링크를 활용해 다시 첫 노드를 가리키게 함으로써, 한 방향으로 모든 노드가 원형으로 연결되어 **어느 한 노드에서 출발해도 다른 모든 노드에 접근 가능**한 구조.

## 기억해야 할 키워드

- **단순(단일) 연결 리스트**: 링크 필드가 하나뿐이고 후행 노드만 가리키는 기본 연결 리스트 구조
- **원형 연결 리스트(Circular Linked List)**: 마지막 노드의 링크가 NULL 대신 다시 첫 노드(head)를 가리키는 구조
- **이중 연결 리스트(Doubly Linked List)**: 노드마다 Llink(선행)·Rlink(후행) 두 개의 링크를 갖는 구조
- **head / Lhead / Fhead**: 리스트의 시작을 가리키는 포인터(헤드 노드). 이중 연결 리스트는 Lhead, Fhead 두 개를 가짐
- **prevNode**: 삽입/삭제 시 기준이 되는 "바로 앞" 노드를 가리키는 포인터 변수
- **tempNode**: 리스트를 순회하며 위치를 옮겨가는 임시 포인터 변수
- **delNode / lastNode**: 각각 삭제할 노드, 리스트의 마지막 노드를 가리키는 포인터 변수
- **malloc / free**: 동적 메모리 할당(새 노드 생성) / 메모리 해제(노드 삭제) 함수
- **라운드 로빈 스케줄링(Round Robin)**: CPU가 준비 큐의 작업을 순서대로 돌아가며 처리하는 방식 — 원형 연결 리스트가 적합한 실무 예
- **희소행렬(Sparse Matrix)**: 0이 아닌 값만 저장해 공간을 절약하는 2차원 배열 표현 방식 (연결 리스트 변형의 활용 예로 언급)
- **O(1) / O(n)**: 각각 "입력 크기와 상관없이 일정한 시간", "입력 크기에 비례하는 시간"이 걸리는 연산을 나타내는 표기법
