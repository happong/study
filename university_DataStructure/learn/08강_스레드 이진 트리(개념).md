# 08강 — 스레드 이진 트리

(컴퓨터과학과 정광식 교수 / 한국방송통신대학교)

## 핵심 요약

- 일반 이진 트리를 순회(전위·중위·후위)하려면, 아직 방문하지 않고 "지나쳐 온" 조상 노드들을 **스택에 저장**해 두어야 하는 번거로움이 있다.
- **스레드(thread)**: 정해진 순회 방법에 따른 "방문 순서"를 미리 기억해 두는 포인터. 스레드를 추가한 이진 트리를 **스레드 이진 트리(Threaded Binary Tree)** 라고 한다.
- 스레드 이진 트리에서는 **오른쪽 스레드가 그 노드의 후속(다음에 방문할) 노드**를, **왼쪽 스레드가 그 노드의 선행(바로 전에 방문한) 노드**를 가리킨다.
- 스레드를 구현하는 방법은 두 가지다. (1) 노드에 `*left`/`*right`(진짜 자식 포인터)와 별도로 `*lthread`/`*rthread`(스레드 전용 포인터) 필드를 **추가**하는 방법, (2) 이진 트리는 노드 개수를 n개라 하면 항상 **n+1개의 빈(NULL) 포인터**가 생기므로, 이 **빈 포인터 칸을 재활용**해서 스레드로 쓰는 방법.
- 빈 포인터를 재활용하는 경우, 그 포인터가 "진짜 자식"을 가리키는지 "스레드"를 가리키는지 구분할 **태그 필드(`int threadFlag`)** 가 반드시 필요하다 (특히 삽입/삭제 시).
- 스레드 이진 트리는 전위/중위/후위 순회 모두 만들 수 있지만, **중위 순회 스레드 이진 트리**가 가장 많이 쓰인다. 스택이나 재귀 없이, 포인터만 따라가면서 순회할 수 있기 때문이다.
- 중위 순회 스레드 이진 트리에서 순회를 시작하려면 먼저 **가장 왼쪽 노드**(`left`가 NULL일 때까지 왼쪽으로 계속 내려간 노드)를 찾아야 한다. 이 노드가 중위 순회의 첫 번째 노드이기 때문이다.
- 스레드 이진 트리는 노드를 삽입·삭제할 때 주변 스레드를 다시 연결해줘야 해서 구현이 까다롭지만, 추가 메모리를 거의 안 쓰면서도 스택 없이 순회할 수 있어 **메모리가 극도로 제한된 임베디드 시스템, 실시간 시스템, DB/파일시스템 인덱싱의 기초** 등에 쓰인다.

## 상세 내용

### 1. 스레드 이진 트리란 무엇인가

**쉬운 비유**: 책을 읽다가 다음 페이지로 넘어갈 때마다 "지금까지 읽은 페이지 번호"를 손가락으로 하나하나 짚어가며 기억해야 한다면 너무 번거롭다. 그런데 누군가 책의 여백에 미리 "다음엔 여기로 가세요"라는 화살표를 그려 놓았다면, 그 화살표만 따라가면 되므로 손가락으로 짚을 필요가 없다. 스레드는 바로 이 "다음엔 여기로 가세요" 화살표다.

- 이진 트리의 노드 순회 방법에는 **전위 순회, 중위 순회, 후위 순회**가 있다.
- 이진 트리를 순회할 때는, 아직 방문하지 않았지만 이미 지나쳐 온 노드(나중에 되돌아와야 하는 조상 노드)들을 **스택에 저장하여 관리**해야 하는 번거로움이 생긴다.
- **스레드 이진 트리**: '스레드'라는 포인터를 추가하여 트리 순회를 편리하게 만든 것.
- **스레드(thread)**: 정해진 순회 방법에 따른 방문 순서를 유지하는 포인터.

슬라이드의 예시 수식 트리: `(2*3)+4` 에 대응하는 이진 트리

```
        +
       / \
      *   4
     / \
    2   3
```

(참고: 이 트리는 교재 외 추가 설명을 위한 예시 그림이며, 원형 연결 리스트의 링크 구조를 복습한 뒤 이진 트리로 확장해서 보여준 것이다.)

### 2. (참고) 원형 연결 리스트 복습

슬라이드에서는 스레드 개념을 설명하기 전에, 이미 배운 **원형 연결 리스트(Circular Linked List)** 구조를 복습 그림으로 다시 보여준다. head가 첫 노드를 가리키고, 마지막 노드의 link가 다시 head(또는 첫 노드)를 가리켜서 "원"을 이루는 구조다. 스레드도 이와 비슷하게, 원래라면 비어 있을 포인터 자리를 "어딘가를 가리키는 화살표"로 채운다는 점에서 발상이 닮아 있다.

### 3. 스택을 이용한 순회 vs 스레드를 이용한 순회

슬라이드에서는 같은 트리(`(2*3)+4`)에 대해 "스택을 이용한 전위 순회"와 "스택을 이용한 중위 순회" 그림(빈 스택 칸이 그려져 있음)을 먼저 보여주며, **스택이 있어야만 순회가 가능한 기존 방식**의 번거로움을 강조한다. 이어서 "스레드 이진 트리"는 **포인터만 따라가면 스택 없이도 순회**할 수 있음을 대비해서 설명한다.

### 4. 세 가지 순회에 대한 스레드 이진 트리

같은 트리 `(2*3)+4` 에 대해, 순회 방식(전위/중위/후위)마다 스레드가 가리키는 방향이 다르다. 점선 화살표가 "스레드"이고, 실선은 원래 트리의 자식 연결이다.

**전위 순회 스레드 이진 트리**

```
전위 순회 결과: + * 2 3 4
```

- `+` → `*` → `2` → `3` → `4` 순서로 방문하도록 점선 스레드가 연결되어 있음.

**중위 순회 스레드 이진 트리**

```
중위 순회 결과: 2 * 3 + 4
```

- `2` → `*` → `3` → `+` → `4` 순서로 방문하도록 점선 스레드가 연결되어 있음.

**후위 순회 스레드 이진 트리**

```
후위 순회 결과: 2 3 * 4 +
```

- `2` → `3` → `*` → `4` → `+` 순서로 방문하도록 점선 스레드가 연결되어 있음.

→ 즉 스레드는 "어떤 순회 방법을 쓸 것인가"에 따라 미리 정해 두는 것이며, 한 트리에 대해 전위용/중위용/후위용 스레드를 각각 따로 만들 수 있다.

### 5. 스레드 이진 트리 구현 방법 (1) — 포인터 필드 추가

**쉬운 비유**: 책가방에 원래 있던 칸(진짜 교과서 칸)은 그대로 두고, 가방 옆에 작은 주머니(스레드 전용 칸)를 하나 더 달아서 "다음 수업 교실 위치 메모"를 넣어두는 것과 비슷하다. 기존 칸을 건드리지 않으니 안전하지만, 가방(노드)이 더 커진다(메모리를 더 쓴다).

- **포인터 필드의 추가**: 스레드를 저장하는 포인터를 노드 구조에 추가로 만드는 것.
- 노드 구조: **왼쪽 스레드 포인터, 왼쪽 자식 포인터, 데이터, 오른쪽 자식 포인터, 오른쪽 스레드 포인터** 로 구성.
- **오른쪽 스레드**: 정해진 순회 순서에 따른 그 노드의 **후속 노드**를 가리킴.
- **왼쪽 스레드**: 그 노드의 **선행 노드**를 가리킴.

| left_thread | *left | data | *right | right_thread |
|---|---|---|---|---|

```c
typedef struct tfNode {
    struct tfnode *left ;
    struct tfnode *lthread ;
    char data ;
    struct tfnode *right ;
    struct tfnode *rthread ;
} tfnode ;
```

**추가된 포인터 필드를 이용한 중위 순회 연산 (단순화 버전)**

슬라이드는 먼저, 트리의 맨 왼쪽부터 오른쪽 스레드(`rthread`)만 쭉 따라가며 출력하는 간단한 버전을 보여준다.

```c
void inorder(tfNode *startNode) {
    tfNode *ptr ;
    ptr = startNode;
    while(ptr != NULL) {
        printf("%c", ptr->data) ;
        ptr = ptr->rthread ;
    }
}
```

- ① 순회할 트리의 **맨 왼쪽(시작) 노드**를 가리키는 포인터 `startNode`를 매개변수로 받는 함수 이름을 `inorder()`로 한다.
- ② 노드를 가리킬 수 있는 (tfNode) 타입의 포인터 `ptr`을 생성하고, 시작 노드를 가리키도록 한다.
- ③ `ptr`이 NULL이 아닌 동안, 현재 노드의 데이터를 출력하고, `rthread`를 따라 다음 노드로 이동하는 것을 반복한다.

→ 트리 그림에서 `2 → * → 3 → + → 4` 순서로 점선(스레드)을 따라가며 중위 순회 결과(`2*3+4`)가 출력되는 과정을 화살표로 보여준다.

### 6. 과연 왼쪽 스레드가 꼭 필요한가?

- 슬라이드는 "왼쪽 스레드(`lthread`)가 정말 필요한가?"라는 질문을 던진다.
- 앞의 원형 연결 리스트 그림(`Llink` / `data` / `Rlink` 구조, `H → head → 100 → 200 → 300 → NULL`, 마지막 노드의 Rlink가 다시 head 등으로 순환)과 비교하며, 왼쪽 방향 정보 없이 오른쪽 스레드만으로도 순회(한 방향 진행)는 가능하다는 점을 시사한다. 다만 **선행 노드를 알아야 하는 연산(예: 역방향 순회, 삭제 시 부모 찾기)**에는 왼쪽 스레드가 필요하다.

### 7. 스레드 이진 트리 구현 방법 (2) — 빈 포인터 필드 재활용

**쉬운 비유**: 책가방에 새 주머니를 추가로 달지 않고(방법 1처럼 공간을 늘리지 않고), 원래 있던 칸 중에서 **비어서 안 쓰고 있는 칸**에 메모를 끼워 넣는 것과 같다. 가방 크기는 그대로인데, 원래 "없음"을 표시하던 빈 칸을 "다음 교실 위치"로 재활용하는 것이다.

- **노드의 빈 포인터 필드를 활용**: 기존 이진 트리의 노드 구조를 그대로 사용하면서, 노드에 있는 사용하지 않는 포인터(빈 포인터, NULL)를 활용하는 방법.
- 장점: **추가 기억장소를 사용하지 않아도 됨**.
- 규칙: 어떤 노드 X에 대해 **오른쪽 포인터가 NULL이면** 이 포인터를 노드 X의 **후행 노드**를 가리키도록 하고, **왼쪽 포인터가 NULL이면** 노드 X의 **선행 노드**를 가리키도록 한다.

**빈 포인터(NULL)가 몇 개나 생길까? — 수학적으로 확인하기**

- 이진 트리의 포인터 개수 (노드의 개수를 n개라 가정함): 왼쪽 서브트리를 가리키는 포인터 n개 + 오른쪽 서브트리를 가리키는 포인터 n개 = **2n개의 포인터**
- 루트 노드를 제외한 각 노드는 모두 "누군가로부터 가리켜지는" 진입 차수가 1이 되므로, 루트 노드를 제외한 전체 노드 수, 즉 **NULL이 아닌 포인터 개수 = n-1개**
- 따라서 **2n - (n-1) = n+1개의 NULL 포인터**가 노드에 존재함 → 이 n+1개의 빈 칸을 스레드로 재활용할 수 있다는 뜻.

**잎 노드의 빈 포인터 필드 활용 예시**

`((A+B)*(C/D))` 구조의 트리로 J, A, Sh(Show), M, P, Sc(Score), E 같은 노드들을 예시로 들어, 잎 노드(자식이 없는 노드)들의 빈 포인터가 빨간 동그라미 화살표(스레드)로 채워지는 모습을 보여준다. 노드 구조는 다음과 같이 **원래 이진 트리와 똑같은 3칸**만 사용한다.

| *left | data | *right |
|---|---|---|

### 8. 스레드 사용 여부를 표시하는 태그 필드가 필요한 이유

- 각 노드에 대해 포인터가 **스레드로 사용 중인지**, 아니면 **서브트리에 대한 (진짜 자식) 포인터인지**를 구분해야 한다.
- 왜냐하면 포인터 값만 봐서는 "자식을 가리키는 것"인지 "스레드(선행/후행 노드)를 가리키는 것"인지 구분할 수 없기 때문이다. 특히 **삽입/삭제 연산에서 반드시 필요**하다.
- 이를 위해 **스레드 사용여부 태그 필드(`int threadFlag`)** 를 노드에 추가한다.

```c
typedef struct thNode {
    struct tfNode *left ;
    chat data ;          // 슬라이드 원문 그대로(오타로 보이는 char의 표기): 실제로는 char data
    struct tfNode *right ;
    int threadFlag ;
} tfNode ;
```

- 전위 순회를 예로, 각 노드의 **왼쪽 포인터 필드를 스레드로 사용하는 제한**을 가정한 그림을 보여준다.
  - **실선**: 어떤 노드의 왼쪽 포인터가 실제 왼쪽 자식을 가리키는 경우.
  - **점선**: 어떤 노드의 왼쪽 포인터가 NULL이면, 전위 순회로 순회할 때 다음으로 방문하는 노드(후행 노드)를 가리키는 경우.

**`((A+B)*(C/D)+E%F)/G`의 이진 트리 표현** (슬라이드 원문 수식)

```
        /
       / \
      +   G
     / \
    *   %
   / \  / \
  +  /  E  F
 /\ /\
A B C D
```

- 이 트리의 **전위 순회 스레드 이진 트리**: `(a) / + * + A B / C D % E F G`
- **중위 순회 스레드 이진 트리**: `(b) A + B * C / D + E % F / G`
- **후위 순회 스레드 이진 트리**: `(c) A B + C D / * E F % + G /`

(세 그림 모두 같은 트리에 대해, 순회 방식에 따라 점선 스레드의 방향만 달라지는 것을 보여준다. 전위/중위/후위 각각의 시작 노드(`startNode`)도 함께 표시되어 있다.)

### 9. 중위 순회 스레드 이진 트리의 실제 연산 (가장 많이 쓰이는 형태)

**① 시작 노드(가장 왼쪽 노드) 찾기**

중위 순회는 항상 "가장 왼쪽 노드"부터 시작해야 하므로, 순회 전에 먼저 이 노드를 찾는 함수가 필요하다.

```c
tfNode* inorderStart(tfNode* ptr) {
    if(ptr == NULL)
        return NULL ;
    while(ptr->left != NULL)
        ptr = ptr->left ;
    return ptr ;
}
```

- `ptr`이 NULL이면 NULL을 반환(빈 트리)한다.
- `ptr->left`가 NULL이 아닌 동안(=진짜 왼쪽 자식이 있는 동안) 계속 왼쪽으로 내려간다.
- 더 이상 왼쪽 자식이 없으면, 그 노드가 바로 중위 순회의 첫 번째(가장 왼쪽) 노드다.

**② 실제 순회(전체 트리를 끝까지 출력)**

```c
void inorder(tfNode* root) {
    tfNode* ptr = inorderStart(root) ;
    while(ptr != NULL) {
        printf("%c", ptr->data) ;
        if(ptr->threadFlag)
            ptr = ptr->right ;
        else
            ptr = inorderStart(ptr->right) ;
    }
}
```

- 먼저 `inorderStart(root)`로 맨 왼쪽(첫) 노드를 찾는다.
- 현재 노드의 데이터를 출력한 뒤,
  - `threadFlag`가 참(스레드로 쓰이는 중)이면, 오른쪽 포인터가 바로 "후속 노드"이므로 그대로 `ptr = ptr->right`로 이동.
  - `threadFlag`가 거짓(진짜 오른쪽 자식이 있음)이면, 오른쪽 서브트리의 **가장 왼쪽 노드**를 다시 찾아야 하므로 `inorderStart(ptr->right)`를 호출.
- 이 과정을 `ptr`이 NULL이 될 때까지 반복한다.

→ 스택이나 재귀 없이, **포인터만 따라가며 트리의 모든 노드를 순서대로 순회**할 수 있다는 것이 스레드 이진 트리의 핵심 장점이다.

### 10. 스레드 이진 트리의 삽입 연산

**노드 Y가 잎 노드인 경우** (새로 삽입되는 Y가 자식이 없는 경우)

- 기존 노드 X의 오른쪽에 새 노드 Y를 끼워 넣을 때, X의 원래 오른쪽 스레드를 Y가 이어받고, X는 Y를 가리키게 바뀐다.

```c
void insert(tfNode *x, tfNode *ttree) {
    ttree->left = NULL ;
    ttree->right = x->right ;
    ttree->lthread = x ;
    ttree->rthread = x->rthread ;
    x->right = ttree ;
    x->rthread = ttree ;
}
```

- (그림 예시) `+` 노드의 오른쪽 자식 칸에 새 노드 `A`를 삽입하는 과정을 빨간 점선 화살표로 보여준다. 삽입 후 `A`의 왼쪽 스레드는 원래 `+` 노드를 가리키고, `A`의 오른쪽 스레드는 `+` 노드가 원래 가졌던 오른쪽 스레드를 그대로 물려받는다.

**노드 Y가 내부 노드인 경우** (Y가 자신의 자식(서브트리)을 가진 채로 삽입되는 경우)

삽입 절차는 다음 6단계로 이뤄진다.

① 삽입되는 노드 Y의 왼쪽 포인터를 NULL로 설정
② 삽입되는 노드 Y의 오른쪽 포인터는 노드 X의 오른쪽 포인터 값으로 설정
③ 삽입되는 노드 Y의 왼쪽 스레드 포인터가 X를 가리키도록 설정
④ 삽입되는 노드 Y의 오른쪽 스레드가 노드 X의 오른쪽 스레드와 같게 설정
⑤ 노드 X의 오른쪽 포인터가 노드 Y를 가리키도록 설정
⑥ 노드 X의 오른쪽 스레드가 노드 Y를 가리키도록 설정

(코드는 잎 노드 삽입과 동일한 `insert(x, ttree)` 함수를 그대로 사용하며, 그림에서는 X의 원래 오른쪽 서브트리 전체가 Y의 오른쪽 자식 자리로 통째로 옮겨 붙는 모습을 보여준다.)

### 11. 스레드 이진 트리의 삭제 연산

- **내부 노드(자식이 있는 노드)를 삭제**할 때는, 삭제된 노드의 자식 노드를 어떻게 처리할지에 대한 방법이 필요하다. 슬라이드는 세 가지 방법을 제시한다.
  ① 노드의 자식 노드를 **모두 삭제**하는 방법 (서브트리 전체를 날림)
  ② 삭제하려는 노드 X의 왼쪽 서브트리나 오른쪽 서브트리의 **루트를 X가 있던 위치로 옮기는** 방법
  ③ **잎 노드가 아닌 노드는 삭제하지 못하게** 제한하는 방법 (가장 단순하고 안전한 방법)

### 12. 스레드 이진 트리의 현실적 적용과 한계

**적용 사례**

- 메모리가 극도로 제한된 **임베디드 시스템(Embedded Systems)**
- **실시간 시스템(Real-time Systems)** (스택/재귀 없이 빠르고 예측 가능한 순회가 필요한 경우)
- **데이터베이스 및 파일 시스템의 인덱싱 기초** (슬라이드에 B-트리 형태와 비슷한 인덱스 구조 그림이 함께 제시됨)

**이진 트리 vs 스레드 이진 트리 비교표**

| 특징 | 이진 트리 | 스레드 이진 트리 |
|---|---|---|
| 순회 방식 | 재귀 또는 스택 필수 | 스택/재귀 없이 순회 가능 |
| 메모리 효율 | 스택 메모리 추가 소모 | 추가 메모리 소모 거의 없음 |
| 구현 난이도 | 쉬움 | 어려움 (삽입/삭제 시 링크 관리) |
| 주 사용처 | 일반적인 데이터 구조 및 응용 | 임베디드, OS 커널, 컴파일러 심볼 테이블 |

**스레드 이진 트리의 한계**

- 구현 및 유지보수의 **복잡도**가 높음 (삽입/삭제마다 스레드를 다시 연결해줘야 함)
- **하드웨어 성능의 발전**으로, 스택/재귀 사용에 따른 메모리·속도 부담이 예전만큼 치명적이지 않게 됨
- 요즘은 더 **좋은 대안과 라이브러리**가 많이 존재함

### 정리하기 (강의 마지막 요약 슬라이드)

- **스레드(thread)**: 정해진 순회 방법에 따른 방문 순서를 유지하는 포인터
- **스레드 이진 트리**: 스레드라는 포인터를 갖는 이진 트리
- **오른쪽 스레드**: 정해진 순회 순서에 따른 그 노드의 후속 노드를 가리킴
- **왼쪽 스레드**: 그 노드의 선행 노드를 가리킴
- **이진 트리의 NULL 포인터 개수**: `2N - (N-1) = N + 1`개

## 기억해야 할 키워드

- **스레드(Thread)**: 정해진 순회 방법(전위/중위/후위)에 따른 "다음에 방문할 노드"나 "직전에 방문한 노드"를 미리 가리켜 두는 포인터.
- **스레드 이진 트리(Threaded Binary Tree)**: 스레드 포인터를 가진 이진 트리. 스택/재귀 없이 포인터만 따라가며 순회할 수 있다.
- **오른쪽 스레드(right thread)**: 그 노드의 후속(다음 방문) 노드를 가리키는 포인터.
- **왼쪽 스레드(left thread)**: 그 노드의 선행(이전 방문) 노드를 가리키는 포인터.
- **스레드 구현 방법 (1) 포인터 필드 추가**: `*left, *lthread, data, *right, *rthread` 처럼 자식 포인터와 스레드 포인터를 별도로 둠. 안전하지만 메모리를 더 쓴다.
- **스레드 구현 방법 (2) 빈 포인터 재활용**: 이진 트리에 원래 존재하는 `n+1`개의 NULL 포인터 칸을 스레드로 재활용. 추가 메모리가 거의 필요 없지만 구현이 더 복잡하다.
- **threadFlag (스레드 사용여부 태그)**: 한 포인터 필드가 "진짜 자식 포인터"인지 "스레드"인지 구분하기 위한 표시 필드. 삽입/삭제 시 반드시 필요.
- **NULL 포인터 개수 공식**: 노드 수 n개인 이진 트리는 `2n - (n-1) = n+1`개의 NULL 포인터를 가진다 (전체 포인터 2n개 중, 루트를 제외한 n-1개 노드만 "가리켜지므로").
- **inorderStart()**: 중위 순회 스레드 이진 트리에서, 왼쪽 자식을 계속 따라 내려가 "가장 왼쪽 노드"(순회 시작 노드)를 찾는 함수.
- **inorder() (스레드 버전)**: `threadFlag`를 확인해서, 스레드면 바로 이동하고 아니면 `inorderStart()`로 다음 서브트리의 시작 노드를 다시 찾아가며 순회하는 함수.
- **잎 노드(Leaf Node)**: 자식이 없는 노드. 스레드 이진 트리에서 삽입/삭제 규칙이 내부 노드보다 단순하다.
