# 03강 — 스택

## 핵심 요약

- 스택(Stack)은 "객체와 그 객체가 저장되는 순서를 기억하는" 자료구조이며, 먼저 들어간 것이 가장 나중에 나오는 **LIFO(Last In First Out)** 구조이다.
- 삽입은 `push(=add)`, 삭제는 `pop(=delete)` 연산이며, 두 연산 모두 스택의 맨 위(`top`) 한 곳에서만 일어난다.
- 스택의 추상자료형(ADT)은 `CreateStack`, `Push`, `Pop`, 그리고 상태 확인용 `StackIsFull`, `StackIsEmpty` 연산으로 정의된다.
- 스택은 변수의 메모리 할당(시스템 스택), 함수(서브루틴) 호출 관리, 인터럽트 복귀 지점 저장, 컴파일러의 순환 호출 관리, 그래프의 깊이 우선 탐색(DFS) 등 실무 곳곳에서 쓰인다.
- 수식은 중위(infix) `A+B`, 전위(prefix) `+AB`, 후위(postfix) `AB+`의 세 가지 방식으로 표기할 수 있으며, 컴퓨터는 괄호와 우선순위를 따질 필요가 없는 **후위 표기법**을 계산에 즐겨 쓴다.
- 중위 표기식은 "우선순위대로 괄호 묶기 → 연산자를 묶음의 맨 오른쪽으로 이동 → 괄호 제거"의 절차로 후위 표기식으로 바꿀 수 있다.
- 후위 표기식은 스택 하나만으로 계산할 수 있다: 숫자는 push, 연산자를 만나면 두 번 pop해서 계산한 뒤 결과를 다시 push한다.
- 배열로 스택을 구현할 때 `top`이라는 정수 변수 하나로 "지금 맨 위 자리가 몇 번 칸인지"를 기억한다 (`top == -1`이면 빈 스택).

## 상세 내용

### 1. 스택의 개념

**쉬운 비유** — 책을 바닥에 쌓아 올린다고 생각해 보자. 책을 올릴 때도 맨 위에 올리고, 뺄 때도 맨 위 책부터 뺀다. 맨 아래에 깔린 책을 바로 빼낼 수는 없다. 슬라이드에서는 실제로 쌓여 있는 책 더미 사진과, "컴퓨터과학 개론 → 자료구조 → DB → XML" 순서로 책을 쌓은 예시 그림이 나온다. 가장 먼저 쌓은 "컴퓨터과학 개론"이 맨 아래에 있고, 가장 나중에 올린 "XML"이 맨 위에 있다.

**정확한 정의**
- 스택(stack): 객체와 그 객체가 저장되는 **순서**를 기억하는 방법에 관한 자료구조
  - 가정: 먼저 입력된 자료가 가장 나중에 출력되는 관계를 표현함 (LIFO, Last-In-First-Out)
  - 객체에 대한 정의와 그 객체들 간의 관계(순서)를 표현하는 연산이 모여서 "순서가 기억되는 스택의 추상 자료형"이 완성됨
  - 자료구조란, 자료들 간의 관계를 추상자료형에서 정의된 연산을 통해 입력/출력을 제어하는 방법 중 하나임 (스택, 큐가 그 예)
- 스택의 정의(좀 더 구체적으로)
  - 0개 이상의 원소를 갖는 **유한 순서 리스트**
  - `push(add)`와 `pop(delete)` 연산이 **한 곳(top)**에서만 발생하는 자료구조
- 스택의 추상 자료형에 필요한 기본 연산
  - `Stack CreateStack(maxStackSize)` — 스택을 만든다
  - `Stack Push(stack, item)` — 원소를 넣는다
  - `Element Pop(stack)` — 원소를 뺀다

### 2. 스택의 추상 자료형(ADT)

**쉬운 비유** — ADT(추상자료형)는 "자판기 사용설명서" 같은 것이다. 안에서 어떻게 동전이 쌓이고 움직이는지는 몰라도, "버튼을 누르면 음료가 나온다"는 사용 규칙만 정확히 정해두면 누구나 똑같이 사용할 수 있다. 스택도 내부 구현(배열이든 다른 방식이든)과 상관없이, Push/Pop이 어떻게 동작해야 하는지 규칙을 먼저 정해둔다.

**정확한 정의 (연산 명세)**

```
연산: stack ∈ Stack, item ∈ element, maxStackSize ∈ positive integer인
모든 stack, item, maxStackSize에 대하여 다음과 같은 연산이 정의된다
(stack은 0개 이상의 원소를 갖는 스택, item은 스택에 삽입되는 원소,
 maxStackSize는 스택의 최대 크기를 정의하는 정수).
```

- **생성 연산**
  ```
  Stack CreateStack(maxStackSize) ::=
      스택의 크기가 maxStackSize인 빈 스택을 생성하고 반환한다;
  ```
- **삽입(Push) 연산**
  ```
  Stack Push(stack, item) ::=
      if (StackIsFull(stack))
          then { 'stackFull'을 출력한다; }
          else { 스택의 가장 위에 item을 삽입하고, 스택을 반환한다; }
  ```
- **삭제(Pop) 연산**
  ```
  Element Pop(stack) ::=
      if (StackIsEmpty(stack))
          then { 'stackEmpty'을 출력한다; }
          else { 스택의 가장 위에 있는 원소(element)를 삭제하고 반환한다; }
  ```
- **가득 찼는지 확인**
  ```
  Boolean StackIsFull(stack, maxStackSize) ::=
      if((stack의 elements의 개수) == maxStackSize)
          then { 'TRUE' 값을 반환한다; }
          else { 'FALSE' 값을 반환한다; }
  ```
- **비었는지 확인**
  ```
  Boolean StackIsEmpty(stack) ::=
      if(stack == CreateStack(maxStackSize))
          then { 'TRUE' 값을 반환한다; }
          else { 'FALSE' 값을 반환한다; }
  ```

**Pop/Push 연산 실행 예시** (슬라이드의 순서 그대로)

```
① CreateStack(3);
② Push(stack, 'S');
③ Push(stack, 'T');
④ Pop(stack);
⑤ Push(stack, 'R');
⑥ Push(stack, 'P');
⑦ Push(stack, 'Q');
⑧ Pop(stack);
```

단계별 스택 모양 (맨 아래가 바닥, `top →`이 가리키는 칸이 맨 위):

| 단계 | 동작 | 스택 내용 (아래→위) | top이 가리키는 원소 |
|---|---|---|---|
| ① | 초기 상태 | (비어 있음) | 없음 |
| ② | push(S) | S | S |
| ③ | push(T) | S, T | T |
| ④ | pop() → T 삭제 | S | S |
| ⑤ | push(R) | S, R | R |
| ⑥ | push(P) | S, R, P | P |
| ⑦ | push(Q) | S, R, P, Q | Q |
| ⑧ | pop() → Q 삭제 | S, R, P | P |

### 3. 스택의 응용

**쉬운 비유** — 서랍이 아니라 "접시 쌓기"로 생각해보면, 스택은 우리 생활과 컴퓨터 내부 곳곳에 숨어 있다.

- **변수를 위한 메모리 할당/수집: 시스템 스택(system stack)**
  - 운영체제가 프로그램이 실행되는 동안 변수를 저장하고 정리하기 위해 관리하는 스택
- **서브루틴(함수) 호출 관리를 위한 스택**
  - 비유: 내가 책을 읽다가 중간에 전화를 받으러 가면, "몇 쪽 읽던 중이었는지" 책갈피를 꽂아두고 간다. 전화를 끊고 오면 책갈피 위치부터 다시 읽는다.
  - 코드 예시 (교재 외 내용으로 소개됨):
    ```
    main A() {
        .
        .
        call func B();
        .
        .
    }
    func B() {
        .
        .
        call func C();
        .
        .
    }
    func C() {
        .
        .
    }
    ```
  - `main`이 `B`를 호출하면 "`main`으로 돌아올 자리"가 스택에 쌓이고, `B`가 `C`를 호출하면 "`B`로 돌아올 자리"가 또 쌓인다. `C`가 끝나면 스택 맨 위(가장 최근에 쌓인 자리)부터 꺼내 돌아간다 — 이것이 바로 함수 호출이 스택 구조로 관리되는 이유다.
- **연산자들 간의 우선순위에 의해 계산 순서가 결정되는 수식 계산**
- **인터럽트 처리와, 이후 리턴할 명령 수행 지점을 저장하기 위한 스택**
- **컴파일러, 순환(재귀) 호출 관리**
- **깊이 우선 탐색(DFS) 알고리즘** (교재 외 내용)
  - 정의: 최근 방문한 정점의 인접한 정점들 중에서 아직 방문하지 않은 하나의 정점을 우선적으로 방문하는 방법
  - 슬라이드의 그래프 예시: 정점 1이 2, 3과 연결되고, 2는 4, 5와, 3은 5, 6과, 5와 6은 다시 7과 연결된 트리 모양 그래프로 DFS 탐색 대상을 보여줌

### 4. 스택의 연산 (C 언어 구현)

**쉬운 비유** — 스택을 실제 프로그램으로 만들 때는 "줄지어 놓인 서랍(배열)"과 "지금 몇 번째 서랍까지 채워져 있는지 적어두는 메모지(top 변수)"만 있으면 된다.

**주의할 점: `top--`과 `--top`의 차이**

연산자(`--`)가 변수의 앞에 있는지 뒤에 있는지에 따라 계산 순서가 달라진다.

```
int a, b;              int a, b;
a = 5;                  a = 5;
b = a--;                b = --a;

a = 4                   a = 4
b = 5                   b = 4
```

→ `b = a--;`는 "먼저 b에 a의 현재 값을 대입한 다음 a를 1 감소"시키고, `b = --a;`는 "먼저 a를 1 감소시킨 다음 그 값을 b에 대입"한다. 스택의 `top--`(후위) vs `--top`(전위) 표기도 이와 같은 원리이므로, Pop/Push 코드에서 `stack[top--]`과 `stack[++top]`을 쓸 때 순서를 혼동하면 안 된다.

**스택의 생성**

```c
// Stack CreateStack
#define STACK_SIZE 10
typedef int element;
element stack[STACK_SIZE];
int top = -1;
```

- `top = -1`은 "아직 아무것도 쌓이지 않은 빈 스택"을 의미한다.

**스택의 삭제(Pop) 연산**

```c
// Element Pop
int pop() {
    if (top == -1) {
        return StackIsEmpty();
    }
    else return stack[top--];
}
```

**스택의 삽입(Push) 연산**

```c
// Stack Push
void push(int item) {
    if (top >= STACK_SIZE - 1)
        return StackIsFull();
    else stack[++top] = item;
}
```

### 5. 사칙연산의 전위·후위·중위 표현

**쉬운 비유** — 우리가 평소에 쓰는 식 `A + B`는 연산자(+)가 두 수 "사이"에 있다. 그런데 컴퓨터 입장에서는 연산자가 숫자들 "뒤"에 와주는 게 계산하기 더 편하다. 마치 "짐을 다 내려놓은 다음에 합치세요"라고 지시하는 것과 같다.

**수식의 세 가지 표기 방법**

| 표기법 | 영어 | 규칙 | 예시 |
|---|---|---|---|
| 중위 표기법 | infix notation | 연산자를 피연산자 **사이**에 표기 | `A + B` |
| 전위 표기법 | prefix notation | 연산자를 피연산자 **앞**에 표기 | `+ A B` |
| 후위 표기법 | postfix notation | 연산자를 피연산자 **뒤**에 표기 | `A B +` |

**중위 표기식을 후위 표기식으로 바꾸는 방법**

1. 먼저 중위 표기식을 연산자의 우선순위를 고려하여 `(피연산자, 연산자, 피연산자)` 형태로 괄호로 묶어준다.
2. 각 계산 뭉치를 묶고 있는 괄호 안에서, 연산자를 그 계산 뭉치의 **가장 오른쪽**으로 이동시킨다.
3. 각 계산 뭉치를 하나의 피연산자로 생각하여 1~2를 반복한다.
4. 괄호를 모두 제거한다.

**예시 1**

```
(A - ((B + K) / D))
→ (A - ((B K+) / D))
→ (A - ((B K+) D /))
→ A ((B K+) D /) -
```
즉, `A - ((B + K) / D)` 는 후위로 `A B K + D / -` 가 된다.

**예시 2 (비교용)**

```
A - B + K / D
→ (풀이 과정은 슬라이드에서 비어 있으나, 왼쪽 예시와 같은 절차로 진행)
```

**예시 3**

```
((A - (B / C)) - (D * E))
→ ((A (B C /) -) (D E *) -)
```

즉, `A + B → AB +` 처럼, 식 전체가 최종적으로 `((A(BC/)-)(DE*)-)`의 형태(괄호 제거 전)로 바뀐다.

**후위 표기식의 계산 알고리즘 (스택 이용)**

예시 수식: `3 6 9 * +` (배열에 문자열로 저장되며 끝에는 널 문자 `\0`가 있음)

```c
// 후위 표기식(369*+)을 계산하는 연산
element evalPostfix(char *exp) {
    int oper1, oper2, value, i = 0;
    int length = strlen(exp);
    char symbol;
    top = -1;

    for (i = 0; i < length; i++) {
        symbol = exp[i];
        if (symbol != '+' && symbol != '-'
            && symbol != '*' && symbol != '/') {
            value = symbol - '0';
            push(value);
        }
        else {
            oper2 = pop();
            oper1 = pop();
            switch (symbol) {
                case '+': push(oper1 + oper2); break;
                case '-': push(oper1 - oper2); break;
                case '*': push(oper1 * oper2); break;
                case '/': push(oper1 / oper2); break;
            }
        }
    }
    return pop();
}
```

**계산 과정을 손으로 따라가 보기 (`3 6 9 * +`)**

| 읽은 문자 | 동작 | 스택 내용 (아래→위) |
|---|---|---|
| `3` | 숫자 → push(3) | 3 |
| `6` | 숫자 → push(6) | 3, 6 |
| `9` | 숫자 → push(9) | 3, 6, 9 |
| `*` | 연산자 → pop(9)=oper2, pop(6)=oper1, push(6*9=54) | 3, 54 |
| `+` | 연산자 → pop(54)=oper2, pop(3)=oper1, push(3+54=57) | 57 |
| (끝) | pop() → 57 반환 | (비어 있음) |

슬라이드에 나온 보충 예시 `3 - 6` → 후위 표기로는 `3 6 -` 이며, 스택에 `3`, `6`을 순서대로 push한 뒤 `-` 연산자를 만나 `oper2=6`, `oper1=3`을 pop해서 `3-6`을 계산(결과는 슬라이드에 명시되어 있지 않음, 식 구조만 제시됨)한다.

**참고 (교재 외 내용): NUL 문자와 NULL 포인터는 다르다**

| 구분 | NUL 문자 (`'\0'`) | NULL (널 포인터) |
|---|---|---|
| 의미 | 문자열의 끝(Null Terminator)을 나타내는 특수한 문자 | 아무것도 가리키지 않는 포인터 / '메모리 주소 0'을 가리키는 포인터 |
| 값 | ASCII 코드값 0 (10진수), 비트 패턴 `0000 0000` | 보통 정수 0 또는 `(void*)0`으로 정의됨 (시스템마다 다를 수 있음) |
| 용도 | C 언어 문자열의 길이를 파악하는 기준이 됨. 예: `"hello"`는 `'h'`, `'e'`, `'l'`, `'l'`, `'o'`, `'\0'`으로 문자열에 저장됨 | 동적 할당 실패 시 반환 값, 또는 유효하지 않은 메모리 주소를 나타낼 때 사용 (널 포인터 역참조는 에러) |

## 기억해야 할 키워드

- **스택(Stack)**: 객체와 그 객체가 저장되는 순서를 기억하는 방법에 관한 추상 자료형. 먼저 들어간 것이 가장 나중에 나오는(LIFO) 구조.
- **top**: 스택에서 push/pop이 일어나는, 가장 위에 있는 자리(위치)를 가리키는 값.
- **push**: 스택의 맨 위에 새 원소를 추가하는 삽입 연산.
- **pop**: 스택의 맨 위 원소를 꺼내서 삭제하는 연산.
- **StackIsFull / StackIsEmpty**: 스택이 꽉 찼는지/비었는지를 TRUE·FALSE로 알려주는 연산.
- **시스템 스택(system stack)**: 변수에 대한 메모리의 할당과 수집을 위해 운영체제가 관리하는 스택.
- **서브루틴(함수) 호출 관리**: 함수를 호출할 때 돌아올 위치를 스택에 쌓아두고, 함수가 끝나면 맨 위부터 꺼내 복귀하는 방식.
- **깊이 우선 탐색(DFS)**: 최근 방문한 정점의 인접 정점 중 방문하지 않은 하나를 우선 방문하는 그래프 탐색 방법.
- **중위 표기법(infix notation)**: 연산자를 피연산자 사이에 쓰는 방법. 예) `A + B`
- **전위 표기법(prefix notation)**: 연산자를 피연산자 앞에 쓰는 방법. 예) `+ A B`
- **후위 표기법(postfix notation)**: 연산자를 피연산자 뒤에 쓰는 방법. 예) `A B +`
- **후위 표기식 계산 알고리즘**: 숫자는 push, 연산자를 만나면 두 번 pop하여 계산한 뒤 결과를 다시 push하는 스택 기반 계산 방법.
- **NUL 문자(`'\0'`)**: 문자열의 끝을 나타내는 특수 문자(ASCII 값 0).
- **NULL(널 포인터)**: 아무것도 가리키지 않는 포인터.
