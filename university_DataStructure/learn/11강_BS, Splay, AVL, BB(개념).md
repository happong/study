# 11강 — BS, Splay, AVL, BB

(컴퓨터과학과 정광식 교수 / 한국방송통신대학교)

## 핵심 요약

- **이진 탐색 트리(BS 트리, Binary Search Tree)**: 모든 노드에 대해 "왼쪽 서브트리의 키 값은 모두 더 작고, 오른쪽 서브트리의 키 값은 모두 더 크다"는 규칙을 만족하도록 만든 이진 트리. 탐색·삽입·삭제에 최적화되어 있다.
- BS 트리에서 **중위 순회(inorder)**를 하면 키 값이 정렬된 순서로 그대로 출력된다.
- BS 트리의 **삭제**는 지워지는 노드의 자식 수에 따라 세 가지 경우(자식 0개/1개/2개)로 나뉘며, 특히 **자식이 2개인 노드**를 지울 때는 "선행자(predecessor)" 또는 "후속자(successor)"를 찾아 그 값으로 대신 채운 뒤, 그 선행자/후속자 노드를 지우는 방식으로 처리한다.
- BS 트리는 삽입·삭제가 반복되면 구조가 한쪽으로 치우쳐(편향) 성능이 나빠질 수 있다. 이를 보완한 트리가 **Splay 트리, AVL 트리, BB 트리**다.
- **Splay 트리**: 방금 접근(탐색/삽입)한 노드 x를 **회전을 반복해서 트리의 루트까지 끌어올리는** 트리. 자주 쓰는 데이터일수록 다음에 더 빨리 찾을 수 있다는 아이디어이며, 회전 방법에 따라 **Zig / Zig-Zig / Zig-Zag** 세 가지 연산이 있다.
- **AVL 트리**: "완전한 균형"이라는 조건을 살짝 완화해서, 모든 노드에 대해 **왼쪽 서브트리 높이와 오른쪽 서브트리 높이의 차이가 최대 1**까지만 나도록 허용한 트리(높이 균형 트리, height balanced tree).
- **BB 트리(bound-balanced tree)**: 높이 대신 **무게(잎 노드의 개수)** 기준으로 균형을 유지하는 트리. 균형 인수 β(0 < β ≤ 1/2)를 이용해 왼쪽/오른쪽 서브트리의 무게 비율을 일정 범위 안으로 제한한다.
- AVL·BB 트리처럼 "느슨한 균형 조건"을 쓰면, 완전 균형을 억지로 유지하는 것보다 삽입/삭제 후 재조정 비용이 훨씬 적다. 완전 균형을 유지하려면 최악의 경우 **O(n)개**의 노드를 옮겨야 하지만, AVL·BB 트리는 **O(log₂n)개**의 노드만 옮기면 된다.

## 상세 내용

### 1. 이진 탐색 트리(BS 트리)의 정의

**쉬운 비유**: 전화번호부를 생각해 보자. 이름이 "가나다순"으로 정리되어 있으면, 찾고 싶은 이름이 앞쪽에 있는지 뒤쪽에 있는지 한 번에 가늠하고 그쪽만 뒤지면 된다. 이진 탐색 트리는 바로 이 "가나다순 정리"를 트리 모양으로 구현한 것이다. 왼쪽에는 항상 더 작은 값, 오른쪽에는 항상 더 큰 값이 있으니, 찾는 값보다 크면 왼쪽으로, 작으면 오른쪽으로만 따라가면 된다.

- **이진 탐색 트리(BS 트리: binary search tree)**
  - 특정 데이터의 효과적인 검색을 위해 자료구조의 제한점을 갖는 이진 트리
  - 특정 데이터의 검색과 노드의 삽입/삭제 처리에 효과적인 이진 트리
  - 트리를 구성할 때, 데이터의 탐색을 고려하여 구성하므로 탐색에 최적화된 이진 트리
  - **키(key)**: 탐색·삽입·삭제 연산에서 비교의 대상이 되는 값. 이진 트리 노드의 데이터를 대표하는 값, 혹은 노드를 특정할 수 있는 값.

- **정의**: 노드 $V_i$의 키를 $k_i$라 할 때, 각 노드 $V_i$가 다음을 만족하는 이진 트리
  1. $V_i$의 왼쪽 서브트리에 있는 모든 노드의 키 값은 $V_i$의 키 값보다 **작다**.
  2. $V_i$의 오른쪽 서브트리에 있는 모든 노드의 키 값은 $V_i$의 키 값보다 **크다**.

  ⇒ (슬라이드에 나온 생각할 거리) 두 개의 키 값이 같은 경우에는 어떻게 처리해야 할 것인가?

**BS 트리 예시** (같은 데이터 {1~9}를 담은 서로 다른 두 가지 BS 트리 모양)

```
        6                     7
       / \                   / \
      4   8                 6   9
     / \ / \               / \   \
    2  5 7  9             3  5   8
   / \                   / \
  1   3                 1   4
```

같은 데이터라도 삽입 순서에 따라 트리 모양은 달라질 수 있다. (슬라이드에는 루트가 6인 트리와 루트가 7인 트리, 또 루트가 6/8인 변형 트리까지 여러 모양 예시가 등장한다.)

### 2. BS 트리의 노드 정의와 중위 순회

**노드 정의** (C 언어 구조체)

```c
typedef struct BSTnode {
    struct BSTnode* left ;     // 왼쪽 자식을 위한 포인터
    char key;                  // 키값을 위한 문자 배열
    char content[10];          // 데이터 필드
    struct BSTnode* right ;    // 오른쪽 자식을 위한 포인터
} BSTnode;
```

**중위 순회**: BS 트리의 중위 순회는 **정렬된 순서로 데이터를 출력**할 수 있음 — 이것이 BS 트리의 핵심 성질이다.

```c
void inorderBST(BSTnode* root) {
    if(root ! = NULL) {
        inorderBST(root → left) ;
        printf("%c", root → key) ;
        inorderBST(root → right) ;
    }
}
```

### 3. BS 트리의 노드 탐색

**키값이 k인 노드 탐색 과정**

1. 트리가 비어 있다면 탐색 실패, 아니면 k와 현재 루트 노드의 키값 $k_i$를 비교한다.
2. $k = k_i$ 이면 탐색 성공, 이때 찾은 노드는 $v_i$다.
3. $k < k_i$ 이면 $v_i$의 왼쪽 서브트리를 탐색한다. 즉, $v_i = v_{i,left}$로 바꾸고 ①로 간다.
4. $k > k_i$ 이면 $v_i$의 오른쪽 서브트리를 탐색한다. 즉, $v_i = v_{i,right}$로 바꾸고 ①로 간다.

**탐색 연산 코드**

```c
BSTnode* searchBST(BSTnode* root, char key) {
    if (root == NULL) {
        printf("Error : 값을 찾을 수 없습니다\n");
        return root;  }
    if (key == root → key) {
        return root;
    } else if (key < root → key)  {
        searchBST(root → left, key);
    } else if (key > root → key)  {
        searchBST(root → right, key); }
}
```

### 4. BS 트리의 노드 삽입

**키값이 k인 노드 삽입 연산 (절차)**

1. $k = k_i$ 이면 멈춘다. (중복 키는 허용하지 않음)
2. $k < k_i$ 이면 $v_i$의 왼쪽 서브트리에 삽입해야 하므로, $v_i = v_i → left$로 하고 ④로 간다.
3. $k > k_i$ 이면 $v_i$의 오른쪽 서브트리에 삽입해야 하므로, $v_i = v_i → right$로 바꾸고 ④로 간다.
4. $v_i$의 서브트리가 비어 있으면 키 k를 가지는 노드를 삽입한다. 그렇지 않으면 다시 k와 $v_i$의 서브트리의 루트 노드의 키 $k_i$를 비교하여 탐색을 반복한다.

**삽입 연산 예제**: 트리 `C(B,E(D))` 에 키가 A인 노드와 F인 노드를 각각 삽입

```
      C                      C
     / \                    / \
    B   E       →          B   E
       /                  /   / \
      D                  A   D   F   (※ A, F 삽입은 각각 별개의 예시)
```

- A 삽입: C→B(왼쪽, 더 작음)→B의 왼쪽이 비어있으므로 A를 B의 왼쪽 자식으로 삽입.
- F 삽입: C→E(오른쪽, 더 큼)→E의 오른쪽이 비어있으므로 F를 E의 오른쪽 자식으로 삽입.

**삽입 연산 코드**

```c
BSTnode* insertBST(BSTnode* root, char key) {
    BSTnode* ptr;
    BSTnode* newNode = (BSTnode*)malloc(sizeof(BSTnode));
    newNode → key = key;
    newNode → left = newNode → right = NULL;

    if(root == NULL) {
        root = newNode;
        return root;         }

    ptr = root;
    while(ptr) {
        if(key == ptr → key) {
            printf("Error : 중복값은 허용되지 않습니다!\n");
            return root;
        } else if(key < ptr → key) {
            if(ptr → left == NULL) {
                ptr → left = newNode;
                return root;
            } else { ptr = ptr → left; }
        } else {
            if(ptr → right == NULL) {
                ptr → right = newNode;
                return root;
            } else { ptr = ptr → right; } }  }
}
```

- 새 노드를 만든 뒤, 트리가 비어 있으면 그 노드를 루트로 삼는다.
- 비어 있지 않으면 `ptr`을 루트부터 시작해 키 값을 비교하며 내려가다가, 들어갈 자리(비어 있는 자식 칸)를 찾으면 그 자리에 새 노드를 연결한다.
- 같은 키가 이미 있으면 오류 메시지를 내고 삽입하지 않는다 (중복 키 비허용).

### 5. BS 트리의 노드 삭제 — 자식 0개 / 1개 / 2개로 나눠서 처리

삭제할 노드(`del`)가 가진 자식의 개수에 따라 처리 방법이 달라진다. 아래는 슬라이드의 예시 트리(F를 루트로, D-J, B-E-I-L, A-C-H-K-M, G 순)를 이용한 설명이다.

**① 자식이 하나만 있는 노드의 삭제**: [삭제한 노드를 가리키던 포인터]가 [그 노드의 null이 아닌 서브트리의 루트]를 가리키게 할당한다.

- 예) 노드 I(자식이 H 하나뿐)를 삭제 → I의 부모였던 J가 이제 H를 직접 가리키도록 연결을 바꾼다.
- 예) 노드 K(자식이 L 하나뿐 — 정확히는 L이 K의 자식)를 삭제하는 경우도 같은 방식으로, K의 부모가 L을 바로 가리키도록 바꾼다.

**② 자식을 두 개 갖는 노드의 삭제**: 항상 특정 방향의 자식 노드를 올리는 방법으로 구현 (즉, 항상 오른쪽(혹은 왼쪽) 자식 노드를 삭제 위치로 이동)

- 예) 노드 F(자식 D, J 둘 다 있음)를 삭제할 때, "선행자/후속자"를 찾아 그 값으로 치환한다.
  - 방법(1): F의 왼쪽 서브트리에서 가장 큰 값(= 선행자, 가장 오른쪽으로 내려간 노드) G를 찾아 F 자리에 올린다 → 결과: 루트가 G로 바뀜.
  - 방법(2): F의 오른쪽 서브트리에서 가장 작은 값(= 후속자, 가장 왼쪽으로 내려간 노드) E를 찾아 F 자리에 올린다 → 결과: 루트가 E로 바뀜.
  - 두 방법 모두 "값만 옮기고, 옮겨진 원래 노드(G 또는 E)는 다시 삭제 대상이 되는" 재귀적인 과정이다.

**삭제 연산 코드 (자식 0개 / 2개 / 1개 순서로 처리)**

```c
if(del → left == NULL && del → right == NULL) { // 자식 노드 0개
    if(parent != NULL) {
        if(parent → left == del) {
            parent → left = NULL;
        } else { parent → right = NULL;  }
    } else { root = NULL; }

} else if(del → left != NULL && del → right != NULL) { // 자식 노드 2개
    predecessor = del;
    successor = del → left;

    while(successor → right != NULL) {
        predecessor = successor;
        successor = successor → right;
    }
    if(predecessor → left == successor) {
        predecessor → left = successor → left;
    } else { predecessor → right = successor → left; }

    del →key = successor → key;
    del = successor;

} else { // 자식 노드 1개
    if(del → left != NULL) {
        child = del → left;
    } else { child = del → right; }

    if(parent != NULL) {
        if(parent → left == del) {
            parent → left = child;
        } else { parent → right = child; }
    } else {
        root = child;
    }
}
```

- **자식 0개**: 부모가 자신을 가리키던 포인터(left 또는 right)를 NULL로 바꾸기만 하면 된다. 부모가 없으면(루트이면) 트리 전체가 비게 된다.
- **자식 2개**: 왼쪽 서브트리에서 가장 오른쪽으로 내려간 노드(선행자, `successor`라는 변수명이지만 실제로는 왼쪽 서브트리의 최댓값)를 찾아 그 키 값을 `del`의 자리로 복사(`del→key = successor→key`)하고, 실제 삭제 대상은 그 선행자 노드(`del = successor`)로 바뀐다 → 결국 자식 0개 또는 1개인 경우로 재귀적으로 넘어가서 처리된다.
- **자식 1개**: 있는 자식(`child`)을 부모가 직접 가리키도록 연결을 바꾼다.

### 6. 이진 탐색 트리의 구조와 성능 문제

- 트리의 구조와 특정 노드에 접근할 확률은 BS 트리의 성능에 영향을 줌 → 트리의 성능이 구조의 영향을 받음.
- 트리가 사용되는 시점에서 삽입/삭제 연산으로 인해 구조가 동적으로 변함
  ⇒ 어떤 노드의 탐색/삽입/삭제를 위한 접근정보를 예측할 수 없음
  ⇒ 따라서, 최적의 BS 트리 구조를 결정하기 어려움

- **경험적으로 좋은 성능의 BS 트리를 구축하는 방법 (휴리스틱 알고리즘)**
  - 자주 탐색하는 키를 가진 노드를 트리의 루트에 가깝게 놓는다. → **Splay 트리**의 아이디어
  - 트리가 균형(balance)이 되도록 유지한다. 즉, 각 노드에 대해 왼쪽과 오른쪽 서브트리가 가능한 한 같은 수의 노드를 갖게 한다. → **AVL 트리 / BB 트리**의 아이디어

이 두 아이디어를 바탕으로, BS 트리는 **Splay 트리**, 그리고 **AVL 트리 / BB 트리** 계열로 발전한다.

```
BS 트리 ─ SPLAY 트리
        └ BB 트리
        └ AVL 트리
```

### 7. Splay 트리

**쉬운 비유**: 자주 꺼내 보는 책을 책장 맨 앞칸(손이 가장 잘 닿는 곳)으로 계속 옮겨 놓는 것과 비슷하다. 방금 찾은 책을 맨 앞으로 옮겨두면, 다음에 또 찾을 때 더 빨리 찾을 수 있을 거라는 기대에서다.

- **Splay 트리**: 자주 탐색하는 키를 가진 노드를 루트에 가깝게 위치하도록 구성한 BS 트리.
- **Splay 연산**: 최근에 접근한 노드 x를 (곧 사용할 것으로 예상하여) 루트에 위치시켜 트리를 재구성하는 연산.
- **Splay 트리**: 가장 최근에 사용한 노드 x가 트리의 루트에 올 때까지 Splay 연산을 반복하여 적용하여 생성된 이진 트리.

**용어**: 노드 x(최근에 접근한 노드), 노드 p(x의 부모 노드), 노드 g(x의 조부모(부모의 부모) 노드)

**(1) Zig 회전 (단일 회전)**: p가 트리의 루트 노드이면 p와 x의 간선 연결(edge joining)을 회전시킨다.

```
    p                x
   / \              / \
  x   c    →       a   p
 / \                  / \
a   b                b   c
```

- x가 p의 자리로 올라가고, p는 x의 오른쪽 자식이 되며, x가 원래 갖고 있던 오른쪽 서브트리(b)는 p의 왼쪽 서브트리로 옮겨 붙는다.

**(2) Zig-Zig 회전 (같은 방향으로 두 번 — 두 개의 단일 회전)**: p가 루트가 아니고 x와 p가 동일하게 왼쪽 자식들 또는 오른쪽 자식들이면, **p와 조부모 g와의 간선 연결을 먼저 회전**시키고, 그 다음에 **x와 p의 간선 연결을 회전**시킨다.

```
      g                p                 x
     / \              / \               / \
    p   ④     →      x   g      →      ①   p
   / \                  / \                / \
  x   ③                ③   ④              ②   g
 / \                                           / \
①   ②                                         ③   ④
```

**(3) Zig-Zag 회전 (지그재그 방향 — 이중 회전)**: p가 루트가 아니고 x가 p의 왼쪽 자식, p가 g의 오른쪽 자식(또는 그 반대)이면, **먼저 x와 p의 간선 연결을 회전**시키고, 그 다음에 **x와 x의 새로운 부모 g와의 간선 연결을 회전**시킨다.

```
      g               g                x
     / \             / \              / \
    p   ④    →      x   ④    →      p    g
   / \                 / \          / \  / \
  ③   x               p   ②        ③  ①  ②  ④
     / \             / \
    ①   ②            ③   ①
```

- Zig-Zig과 Zig-Zag의 차이: Zig-Zig은 "같은 쪽으로 꺾인" 모양(부모·자식이 둘 다 왼쪽 자식이거나 둘 다 오른쪽 자식)일 때 쓰고, Zig-Zag은 "서로 다른 쪽으로 꺾인" 모양일 때 쓴다.

**Splay 연산 적용 예제**: 아래 트리에서 7이 루트가 되도록 Splay 연산을 적용

```
          5                                    7
        /   \                                /   \
       3     6                              5     8
      / \     \            (최종 결과)      / \   / \
     1   4     8                          3   6 6'  9
        /     / \                        / \
       2     7   9                      1   4
                                            /
                                           2
```

(슬라이드에서는 7을 루트로 올리기까지, Zig-Zig/Zig-Zag 회전을 여러 단계로 반복해서 적용하는 중간 과정의 트리 모양들을 순서대로 보여준다. 최종적으로 7이 루트가 되고, 5와 8이 각각 왼쪽/오른쪽 자식이 되며, 나머지 노드들이 그 아래로 재배치된다.)

### 8. AVL 트리

**쉬운 비유**: 저울의 양쪽 접시에 추를 올릴 때, 완벽하게 똑같이 맞추기는 어렵지만 "한쪽으로 너무 기울지만 않으면" 쓸 만하다고 봐주는 것과 비슷하다. AVL 트리는 "완벽한 균형"까지는 아니어도 "왼쪽과 오른쪽의 높이 차이가 1 이하"이기만 하면 괜찮다고 봐준다.

- 노드의 삽입과 삭제가 일어날 때, 노드의 키값과 서브트리 키값 사이의 관계를 유지하면서 균형을 유지시키는 것이 쉽지 않음 → 이 때문에 "완전한 균형" 대신 "약간의 불균형은 허용"하는 변형 BS 트리가 필요해짐.

- 예) 노드 8을 삽입해도 균형이 유지되는 경우, 반대로 노드 1을 삽입하면 균형이 깨지는 경우가 생길 수 있음. 균형을 다시 맞추려면 많은 노드가 이동되어야 할 수도 있다.

**AVL 트리의 개념**
- 제한 조건을 완화하여 트리가 (완전한) 균형이 아닌 것을 허용함.
- 무너진 균형의 정도는 작아야 하고, 평균 탐색 길이도 완전 균형 트리의 탐색 길이와 크게 차이가 나지 않아야 함.
- 거의 완전한 균형 트리의 한 형태로 **높이가 균형 잡힌 높이 균형 트리(height balanced tree)**.
- 직접 탐색 성능이 매우 좋음.

**AVL 트리의 조건**: 노드 $v_i$의 **왼쪽 서브트리 높이**와 $v_i$의 **오른쪽 서브트리 높이**가 **최대 1만큼만** 차이가 남.

- 예) 노드 1이 삽입되어 균형이 깨진 것처럼 보이는 트리도, 각 노드의 좌우 서브트리 높이 차가 1 이하이기만 하면 **AVL 트리 조건상 허용**된다.

**AVL 트리(높이 균형 트리) 판정 예시**: 높이가 "대략" 균형 잡힌 트리들

```
  2        2          3               3
 / \      / \        / \             / \
1   3    1   3       1   5           1   5
          \           \             /   / \
           4           2           2   4   6
                                            \
                                             7
```

(왼쪽 두 트리는 완전/거의 완전 균형. 오른쪽 두 트리(점선 박스로 표시된 부분)는 AVL 조건을 만족하는 "허용 가능한" 형태의 예시다.)

**높이가 불균형인 트리의 예**: 노드 8이 들어가면서 어떤 노드의 좌우 서브트리 높이 차이가 2 이상이 되어 **AVL 조건에 위배**되는 경우 (슬라이드의 점선 박스로 표시된 부분이 "높이 차 ≥ 2"가 되어 버린 서브트리).

### 9. BB 트리 (bound-balanced tree)

- **BB(bound-balanced) 트리**: 거의 완전히(대략) 균형 잡힌 트리의 다른 종류로 **무게가 균형 잡힌 트리**.
- 각 노드의 양쪽 서브트리 **무게**(= 잎 노드의 개수)가 균형을 유지하는 트리.
- 임의의 노드 x에 대한 아래 식을 만족하는 트리:

$$\sqrt{2} - 1 < \frac{\text{왼쪽 서브트리의 무게}}{\text{오른쪽 서브트리의 무게}} < \sqrt{2} + 1$$

- **β(베타)**는 균형을 제어하기 위한 인수.
- 균형 β (0 < β ≤ 1/2)라는 것은, 임의의 노드 x에 대해 x의 한 쪽(보통 왼쪽) 서브트리에 x의 자식 노드 수의 비율이 β와 1-β 사이에 있도록 제한하는 경우.
- 만일 β = 1/2이면, 왼쪽 서브트리와 오른쪽 서브트리는 **같은 수의 노드**를 가져야 함 → 극단적으로 무게가 완전히 균형 잡힌 상태.
- β = 1/4이면, 한쪽 서브트리는 다른쪽 서브트리에 비해 **3배 정도** 노드를 많이 갖는 것이 허용되는 조건.
- **β가 1/2에 가까울수록 균형을 엄격하게 유지하게 됨.**

### 10. 균형 트리(AVL / BB)의 효율성

- AVL 또는 BB 트리에 대하여, 각각 무게 또는 크기(높이) 제한 조건을 만족시키는데 드는 비용은 트리를 완전히 균형 잡히게 유지하는 비용이나 노력보다 훨씬 작음.
- 삽입이나 삭제 후에 트리를 **완전히** 균형 잡히게 유지하기 위해서는 $O(n)$개의 노드를 옮겨야 하는 반면에, **AVL 또는 BB 트리는 $O(\log_2 n)$개의 노드를 옮기면 되는 것**으로 알려져 있음.

### 11. 네 가지 트리의 관계 정리

```
BS 트리 ─ SPLAY 트리
        └ BB 트리
        └ AVL 트리
```

- 모두 **BS 트리**(이진 탐색 트리)에서 출발한 변형이다.
- **Splay 트리**는 "자주 쓰는 노드를 루트로" 끌어올려 평균 탐색 속도를 개선하는 방향.
- **BB 트리 / AVL 트리**는 "좌우가 너무 기울지 않도록" 균형(무게 또는 높이)을 유지하는 방향.

## 기억해야 할 키워드

- **이진 탐색 트리(BS 트리, binary search tree)**: 빠르게 탐색할 수 있도록 구성한 이진 트리. 모든 노드에서 왼쪽 서브트리 < 자신 < 오른쪽 서브트리 규칙을 만족한다.
- **키(key)**: 각 노드를 식별하기 위해 별도의 간단한 이름을 붙인 것. 탐색·삽입·삭제에서 비교의 대상이 되는 값.
- **중위 순회(inorder)**: BS 트리를 중위 순회하면 정렬된 순서로 데이터가 출력된다.
- **삭제 연산의 3가지 경우**: 자식 0개(바로 제거), 자식 1개(자식이 부모에게 직접 연결됨), 자식 2개(선행자/후속자 값으로 치환 후 그 노드를 재귀적으로 삭제).
- **선행자(predecessor)/후속자(successor)**: 자식이 2개인 노드를 삭제할 때, 왼쪽 서브트리의 최댓값(선행자) 또는 오른쪽 서브트리의 최솟값(후속자)을 가져와 대신 채우는 노드.
- **Splay 트리**: 자주 탐색하는 키를 가진 노드를 루트에 가깝게 위치하도록 구성한 이진 탐색 트리.
- **Splay 연산**: 최근에 접근한 노드 x를 회전시켜 루트로 끌어올리는 연산.
- **Zig**: p가 루트일 때, p와 x의 간선을 한 번 회전시키는 단일 회전.
- **Zig-Zig**: x와 p가 같은 방향(둘 다 왼쪽 또는 둘 다 오른쪽) 자식일 때, p-g 회전 후 x-p 회전을 하는 두 번의 단일 회전.
- **Zig-Zag**: x와 p가 서로 다른 방향 자식일 때, x-p 회전 후 x-g 회전을 하는 이중 회전.
- **AVL 트리(높이 균형 트리)**: 노드 $v_i$의 왼쪽 서브트리 높이와 오른쪽 서브트리 높이가 최대 1만큼 차이가 나는 것을 허용하는 트리.
- **BB 트리(bound-balanced tree, 무게 균형 트리)**: 각 노드의 좌우 서브트리 무게(잎 노드 개수) 비율이 β와 1-β 사이에 있도록 제한하는 트리.
- **균형 인수 β**: 0 < β ≤ 1/2. β=1/2이면 좌우 무게가 완전히 같아야 하고, β가 1/2에 가까울수록 균형이 엄격해진다.
- **균형 트리의 효율성**: 완전 균형 유지에는 최악 $O(n)$개 노드 이동이 필요하지만, AVL·BB 트리는 $O(\log_2 n)$개 노드 이동으로 충분하다.
