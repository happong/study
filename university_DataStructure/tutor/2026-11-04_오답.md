## 문제별 상세

### 1. [초급·객관식] ADT의 정의
- 문제: ADT(추상 자료형)의 정의로 가장 적절한 것은?
- 제출 답: ② 자료값의 집합 + 연산의 집합으로 자료의 논리적 성격을 정의한 형식
- 정답: ②
- 결과: ✅ 정답

### 2. [초급·단답] ADT 영문 풀네임
- 문제: ADT의 영어 풀네임(원어)을 쓰시오.
- 제출 답: "a-, date" (의미 불명확, 오답)
- 정답: Abstract Data Type
- 오답 원인: 영문 풀네임을 정확히 암기하지 못함
- 관련 개념: 01강 — 추상 자료형(ADT)

### 3. [중급·단답] 배열 ADT의 세 가지 기본 연산
- 문제: 배열 ADT의 세 가지 기본 연산의 이름과 역할을 각각 한 줄로 쓰시오.
- 제출 답: "create : 배열의 크기를 정한다." (retrieve, store 누락)
- 정답:
  - create(n): 크기 n인 빈 배열을 생성한다
  - retrieve(a, i): a배열의 i번째 원소값을 반환(조회)한다
  - store(a, i, e): a배열의 i번째 위치에 원소값 e를 저장한다
- 오답 원인: 3개 연산 중 1개만 작성, create 설명도 "생성"이 아닌 "크기를 정한다"로 다소 부정확
- 관련 개념: 01강/02강 — 배열의 추상 자료형(ADT)

### 4. [중급·계산] 희소행렬 효율적 배열표현의 표 크기
- 문제: 10행 12열 행렬에 0이 아닌 원소가 18개 있을 때, 효율적 배열표현으로 저장하면 몇 행 몇 열의 표가 되는가?
- 제출 답: 3행 11열
- 정답: 19행 3열 (= 0이 아닌 원소 개수 18 + 헤더 1줄, 열은 (행,열,값) 3칸 고정)
- 오답 원인: "원래 행렬의 행/열 크기"와 "효율적 배열표현 표의 행/열 개수"를 혼동함. 공식(개수+1행, 3열 고정)을 적용하지 못함
- 관련 개념: 02강 — 희소행렬의 효율적 배열표현

### 5. [고급·서술형] 일반적 배열표현 vs 효율적 배열표현 비교
- 문제: 희소행렬의 일반적 배열표현과 효율적 배열표현을 비교하고, 각각 어떤 상황에 유리한지 설명하시오.
- 제출 답: "잘 모르겠어요" (미작성)
- 모범 답안 요지:
  - 일반적 배열표현: 0 포함 모든 원소 저장 → 인덱스로 즉시 접근(O(1)) 가능하지만 메모리 낭비 심함
  - 효율적 배열표현: 0이 아닌 값만 (행,열,값)으로 저장 → 메모리 절약되지만 특정 위치 검색 시 순차 탐색(O(n)) 필요
  - 희소행렬(0이 아주 많음)일 때는 효율적 배열표현이 유리, 밀집 행렬이고 빠른 조회가 중요할 때는 일반적 배열표현이 유리
- 오답 원인: 개념은 앞서 학습했으나 스스로 요약/서술하는 데 어려움을 느낌 (이해 vs 표현의 간극)
- 관련 개념: 02강 — 희소행렬

### 6. [고급·객관식] ADT에 대한 틀린 설명 고르기
- 문제: ADT에 대한 설명 중 틀린 것은?
- 제출 답: ②
- 정답: ③ "ADT는 반드시 특정 프로그래밍 언어로만 정의될 수 있다" (이것이 틀린 설명 — ADT는 언어 독립적으로 정의됨)
- 오답 원인: "틀린 것 고르기" 유형에서 맞는 설명(②)을 답으로 선택함. 문제 유형(틀린 것 찾기) 자체를 헷갈렸을 가능성
- 관련 개념: 01강 — 추상 자료형(ADT)의 특징

## 반복 오답 패턴 (다음 세션에서 우선 재학습)

- **희소행렬 계산/서술 전부 오답** — "0이 아닌 원소 개수 + 1행, 3열 고정" 공식과, 원래 행렬 크기 vs 표 크기를 구분하는 연습이 더 필요함. → **같은 세션 내 재학습 후 재시도로 해결됨 (아래 참고)**
- **ADT 영문 명칭 등 암기형 단답**에서 약함 — 핵심 용어 암기 확인 문제를 다음 세션에서도 계속 섞어서 낼 것.

## 재학습 결과 (같은 날 바로 재시도)

문제 5(서술형)와 문제 4(계산)를 각각 다시 설명한 뒤 재시도함.

- **5번 서술형 재시도**: "일반적 배열표현은 모든 값을 나열하여 메모리를 차지하지만 인덱스로 빠르게 접근 가능 / 효율적 배열표현은 0이 아닌 값만 나열해 메모리를 절약하지만 순차 탐색이 필요하다"는 내용을 본인 말로 정확히 작성함. (단, "어떤 상황에 유리한지" 결론 문장은 힌트 제공 후에야 보완 — 스스로는 장단점까지만 작성)
  → **재시도 결과: 정답(핵심 내용 정확)**
- **4번 유형 계산 재시도** (숫자를 바꾼 새 문제: 6행7열, 0아닌 원소 9개): "9+1=10행, (행,열,값) 3열 고정 → 10행 3열"로 정확히 계산 과정과 답 모두 작성함.
  → **재시도 결과: 정답**

**결론**: 희소행렬 관련 약점은 이번 세션 내 재학습으로 해소됨. 다음 세션에서는 이 개념을 이전 학습 범위(01~02강)에 섞어서 한 번 더 가볍게 확인하고, 새로운 약점(ADT 암기형 단답 등) 위주로 복습 문제를 구성할 것.

## 출석수업과제 문제1~3 단계별 풀이 세션 (같은 날 이어서 진행)

방송통신대 자료구조 출석수업과제(경기지역대학 ZOOM4, 강의: 은인기) 문제 1~3번을, 단답형 질문으로 잘게 쪼개서 사용자가 직접 단계별로 작성하도록 안내함. 문제4(스택 변환·계산)는 시간 부족으로 다음 세션으로 이월.

### 진행 중 나온 오답/혼동 포인트

- **자료(Data) 정의**: 처음에 "정리되지 않은 데이터의 모음"이라고 답함 → "정리 여부"는 정의의 핵심이 아니며, 정확한 정의는 "현실에서 관찰·측정으로 수집된 값/사실"임을 재설명 후 정정함 (재시도 정답)
- **추상화(Abstraction) 정의**: "정보들을 종합하여 공통된 특징을 뽑은 것"이라고 답해 **정보 단계와 추상화 단계를 혼동**함 → 추상화는 "정보"가 아니라 "객체(대상)"에서 공통점을 뽑는 것이라고 재설명 후 정정함 (재시도 정답). 이 혼동은 처음 틀렸을 때와 같은 유형(자료→정보→추상화 흐름의 순서/대상 혼동)이므로 다음 복습에서 한 번 더 확인 필요
- **ADT 표기 오류**: 영문 스펠링 "abstruct"(오타, 정답은 Abstract) + "자료 구조형"이라는 틀린 용어 사용(정답은 "추상 자료형") → 정정함
- **희소행렬 정의 1차 시도**: "데이터 값을 행과 열로 나열한 것"이라고 답함 → 이는 "희소행렬"이 아니라 그냥 "행렬" 자체의 정의임. "0이 아닌 값보다 0이 훨씬 많다"는 희소행렬만의 핵심 특징이 빠짐 → 재설명 후 정정함
- **반올림 개념 오류**: `2÷3=0.6666...`을 반올림하는 문제에서 "0.66"이라고 답함(이는 버림/절삭이지 반올림이 아님) → 셋째 자리(6)가 5 이상이면 올림한다는 반올림 원리를 재설명 후 "0.67"로 정정함
- **이항연산자 개념 혼동**: evalPostfix 트레이스 중 "연산자 심볼이 하나인데 왜 피연산자를 2개 꺼내는지" 질문함 → 모든 사칙연산자(+,-,*,/)는 피연산자 2개가 있어야 계산되는 이항연산자이며, 코드도 연산자 종류와 무관하게 항상 pop 2번임을 재설명함

### 완성된 정리본 (본인 답변 기반으로 구성, 과제 제출 시 본인 말로 다듬어 사용할 것)

**문제1 (자료구조와 ADT)**: 자료→정보→추상화→자료구조→ADT 흐름을 전부 본인 정의로 정리. 과일(사과/딸기/바나나/키위) 비유로 추상화~ADT까지 본인이 직접 확장해 이해함. 배열 ADT 예시(자료값의 집합 `<인덱스,원소값>` + create/retrieve/store 세 연산)까지 포함해 완성.

**문제2 (희소행렬)**: 정의, 일반적 배열표현의 단점, 효율적 배열표현과 (행,열,값) 형식이 필요한 이유, 본인이 직접 만든 5×5 예시 행렬(0이 아닌 값 5개)의 변환 표, 두 방식의 장단점 비교까지 전부 완성.

**문제3 (exp="423/*" 계산)**: 아스키코드를 이용한 `value = symbol - '0'` 설명, push/pop 트레이스 전 과정(i=0~4), 나눗셈 반올림(0.67) 처리, 최종 결과 `2.68`까지 전부 완성.
