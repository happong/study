## 개념 질문 — 상한·하한 / 최댓값·최솟값 (2강, 중간과제 대비)

과제 1번의 풀이 순서를 묻는 질문 중에 개념 오해가 확인됨 (과제 답 자체는 다루지 않음)

| 사용자 이해 | 바른 개념 | 태그 |
|---|---|---|
| 상한 = 작은 쪽(극한값 쪽), 하한 = 큰 쪽 | **상한 = 위쪽(큰 쪽) 경계, 하한 = 아래쪽(작은 쪽) 경계** | `#정의혼동` |
| 상계가 무한히 많으니 "가장 작은 상계"는 알 수 없다 | 상계는 무한히 많아도 그중 가장 작은 것(상한)은 하나로 정해짐 (예: {1,3,5} 의 상계는 5 이상의 모든 수, 상한은 5) | `#정의혼동` |
| 4단계(후보값이 집합 안에 있는지)를 이해 못 함 | 최댓값/최솟값 = 집합 **안에 실제로 있는** 상한/하한 | `#정의혼동` |
| 예제 C={1−1/n} 에 0 이 왜 있는지 (n=0 을 넣은 줄 앎) | n=1 을 넣으면 1−1/1 = 0 | `#계산실수` |

→ 조치: 비유(천장·키)와 수직선 그림으로 재설명, 세트 2의 2·3번으로 다시 확인 예정

### 추가 질문 (같은 날)
| 사용자 이해 | 바른 개념 | 태그 |
|---|---|---|
| 상한 = 가장 높은 **원소** | 상한 = 상계 중 가장 작은 **수**. 원소가 아닐 수도 있음 (원소일 때만 최댓값과 같음) | `#정의혼동` |
| 원소가 한없이 작아지며 어떤 수에 다가가면 하한은 "무한" | 하한은 항상 **하나의 수**. 원소들이 한없이 다가가는 그 수가 아래쪽 경계 후보 (무한은 수가 아님) | `#정의혼동` |
| 상계의 뜻을 모름 | 상계 = 모든 원소보다 크거나 같은 수 (여러 개) | `#정의혼동` |
| 구간 기호 `[1, 3)` 를 모름 | `[` `]` = 끝점 포함, `(` `)` = 끝점 미포함 (2강 내용, 아직 미수강) | `#선수지식` |

→ 상한·하한 개념 혼동 같은 날 2회 → **재학습 대상**으로 지정

### 재학습 진행 (같은 날)
- 후보 수를 하나씩 "시험"하는 방법으로 설명한 뒤, 사용자가 스스로 "하계 = ○ 이하의 수, 하한 = 그중 가장 큰 수" 흐름을 찾아냄 → 추론 방향 ✅
- 남은 보완점: 하계 정의를 "가장 근접하는 수"로 표현함 → 정확한 정의는 "**모든 원소보다 작거나 같은 수**" (근접 여부와 무관). "근접"은 하한을 찾을 때 쓰는 생각
- 다음 확인: 최솟값 존재 여부(4단계), 그 수보다 조금 큰 수가 하계가 아닌 이유를 답안에 쓰는 법

### 재학습 결과 (같은 날)
- 사용자가 스스로 "최댓값/최솟값 = 상한/하한이 집합의 원소인지로 결정" 을 적용함 → 개념 흐름 ✅
- 보완점: 답안에 원소 여부의 **근거**(어떤 n 에서 나오는지 / 방정식의 자연수 해가 없는 이유)를 함께 쓰기
- 남은 확인: 확인 질문 3개(`{2,4,6}`, `[1,3)`, `E={n/(n+1)}`) 미제출 → 제출 시 개념 "통과" 판정
- B = A ∪ {0} 에도 4단계를 스스로 적용함 → 개념 흐름 ✅
- 보완점: ① 원소 나열에서 0 을 수열의 "마지막 항"처럼 쓰지 않기 (집합은 순서 무관, 1강) ② 차이 설명은 "무엇이 다른가"에서 끝내지 말고 "그래서 어떤 결과(상한·하한·최댓값·최솟값)가 달라지고, 어떤 것은 그대로인가"까지 쓰기

### 과제 1번 초안 셀프 점검 (과제 답안 내용은 저장하지 않음)
과제 규정상 값의 정오는 확인하지 않고, 형식·표기·근거 누락만 짚음. 학습 포인트:
- `#기호오류` "n = 1 = 1/1 = 1" 처럼 서로 다른 것을 등호로 이어 씀 → "n = 1 일 때 1/n = 1" 로 쓰기
- `#기호오류` "n = 1/100" (n 자리에 원소 값을 씀) → "n = 100 일 때 1/n = 1/100"
- `#조건누락` 상한·하한·최댓값·최솟값의 **근거**(왜 그 값인지 / 원소인지) 생략
- `#조건누락` 소문항 번호 어긋남 (내용과 번호 대응 확인 습관)
- 불필요한 소수 변환·근삿값(0.333) → 분수로 유지

### 과제 1번 서술 보완 점검 (답안 내용은 저장하지 않음)
- `#정의혼동` (재발 2회째) 하계를 "가장 근접한 0 이하의 수"로 정의 → "모든 원소보다 작거나 같은 수". 근접은 하한을 고를 때의 생각
- `#조건누락` 상한·하한의 (나) 근거(그보다 조금 큰/작은 수는 하계/상계가 아님) 여전히 없음
- `#조건누락` 원소 여부의 근거(n = 1 / 1/n > 0) 생략
- 용어: 최댓값·최솟값은 "계산할 수 없다"가 아니라 "**존재하지 않는다**", 상계·하계는 "계산"이 아니라 "정해진다/존재한다"

### 세트 3 - 3번 시도 1 (n = 1, 2, 3 직접 대입)
- n = 3 에서 `1 + 5` 로 계산 → 2번째 항 3 을 빠뜨림 (정답: 1 + 3 + 5 = 9 = 3²) `#조건누락` — "n 번째 항까지 **모든** 항을 더한다"를 놓침
- `1 + (2*2 − 1 = 3) = 2*2 = 4` 처럼 식 안에 등호를 넣어 이어 씀 `#기호오류` (재발 2회째)
- 개념: 몇 개의 n 을 대입해 확인하는 것은 귀납법이 아님 → k 에서 k+1 로 넘어가는 단계 필요

### 귀납 단계(k) 시도 — 과제 2번 공부 중 (답안 내용은 저장하지 않음)
- `#조건누락` (재발 3회째) n = k 일 때 식을 1 + xᵏ 로 써서 중간 항 x, x², … 를 빠뜨림 → "처음부터 마지막 항까지 모두" 패턴 반복 오답
- `#계산실수` 지수법칙: x · xᵏ 을 x²ᵏ 로 계산 → 곱하면 지수는 **더한다**: x¹ · xᵏ = xᵏ⁺¹
- `#증명논리` 귀납 가정(n = k)을 전개해서 검증하려 함 → 가정은 "성립한다고 두는 것", 계산은 n = k+1 에서 함
- `#기호오류` x^k+1 처럼 지수 범위 불명확 → x^(k+1) 로 괄호
